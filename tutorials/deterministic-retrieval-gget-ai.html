Deterministic Retrieval with gget

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

← Previous tutorialAll tutorialsNext tutorial →

Use gget to query Ensembl-linked metadata and sequence records, then preserve the raw response and enough provenance to interpret it later. Database retrieval is reproducible only when you record the software, query, source state, and response; an LLM can still misread supplied evidence.

Format: Hands-on lab. This guided exercise is for learners comfortable with a Unix-like shell; you will install pinned gget, retrieve metadata and a protein FASTA for the supplied ACE2 Ensembl ID, and inspect saved outputs. No input files are supplied or needed; an internet connection and package-install permission are required.

Learning objectives and prerequisites

By the end of this lesson you will be able to:

  • Install gget in an isolated Python environment and record the installed version.
  • Retrieve gene metadata and a translated sequence using the documented gget CLI and Python API.
  • Save raw responses and query provenance so a human or LLM can inspect the supplied evidence.
  • Interpret common outputs (IDs, coordinates, sequences) and understand what they do and do not prove.

Prerequisites: basic command-line familiarity (bash or similar), a Python environment supported by your chosen gget release, and permission to install Python packages. No prior knowledge of gget or the Ensembl/UniProt APIs is required.

Why deterministic retrieval matters in bioinformatics

Large Language Models (LLMs) are powerful at synthesizing text and generating code, but they are not authoritative sources of changing biological facts such as current Ensembl gene IDs, transcript coordinates, or canonical UniProt accessions. These facts change over time: annotations are updated, assemblies are remapped, and IDs may be deprecated. Supplying an LLM with a saved database response gives it evidence to inspect, but does not prevent hallucinations or guarantee correct interpretation. Record the query, retrieval time, software version, and relevant database release so another person can assess the result.

gget provides separate command-line and Python modules for querying bioinformatics resources. Here, we use its Ensembl-linked info and seq modules. The query is explicit, but the remote annotation can change between releases; saving the response preserves what you received, not the database service itself.

Reproducible, sequential workflow

The example uses the human ACE2 Ensembl gene ID documented in the gget quick start. Commands assume a Unix-like shell and an internet connection. Gene symbols can be ambiguous; resolve a symbol to the intended Ensembl ID before using this pattern. Responses from external services may change over time.

1) Create an isolated environment and install gget

Run these commands from a new working directory. Create the results directory before redirecting help output:

# Create and activate a Python virtual environment
mkdir -p retrieval-results
python3 -m venv .venv
source .venv/bin/activate

# Upgrade pip and install a pinned gget version for reproducibility
python -m pip install --upgrade pip
python -m pip install "gget==0.28.6"

# Verify installation and save the help output
gget --help > retrieval-results/gget-help.txt 2>&1
python -m pip show gget > retrieval-results/gget-package.txt

What these commands produce:

  • .venv/ — isolated Python environment (do not delete if you want reproducibility).
  • retrieval-results/gget-help.txt — records the CLI help output.
  • retrieval-results/gget-package.txt — records installed gget package metadata, including its version.

The example pins gget 0.28.6. Check that release is compatible with your Python version and platform; do not silently substitute a newer release if reproducing an older analysis.

2) Prepare a retrieval-results directory and record metadata

# Make a directory to hold raw retrievals and logs
mkdir -p retrieval-results
# Record the environment and Python package list for provenance
python -m pip freeze > retrieval-results/requirements.txt
python --version > retrieval-results/python-version.txt
date --iso-8601=seconds > retrieval-results/retrieval_timestamp.txt

Files created:

  • retrieval-results/requirements.txt — installed Python distributions, not a complete lockfile of platform dependencies.
  • retrieval-results/retrieval_timestamp.txt — time the environment metadata was captured; it is not a query start or completion time.

3) Deterministic retrieval: get Ensembl gene metadata using gget info

Use an Ensembl gene identifier, not a gene symbol: gget info accepts Ensembl IDs and writes JSON to standard output by default. The official quick start uses ENSG00000130234 for ACE2.

# Log start/end, exact command label, and exit status around each CLI query
log_run() {
  label=$1; shift
  started=$(date --iso-8601=seconds)
  "$@"
  status=$?
  finished=$(date --iso-8601=seconds)
  printf 'start=%s | command=%s | exit=%s | end=%s\n' "$started" "$label" "$status" "$finished" >> retrieval-results/commands.log
  return "$status"
}
# Save the raw command-line JSON; inspect stderr and do not interpret output if it fails
log_run 'gget info ENSG00000130234' gget info ENSG00000130234 > retrieval-results/ACE2_info.json || echo "gget info failed; inspect stderr and output file."

# Python API: info returns a pandas DataFrame; export its returned columns
python - <<'PY'
import gget
records = gget.info(["ENSG00000130234"])
records.to_csv("retrieval-results/ACE2_info_python.csv", index=False)
print("Rows:", len(records), "Columns:", list(records.columns))
PY

The Python call is a separate live query and is not wrapped by the shell logger above. Compare its saved rows with the CLI response, rather than assuming the output fields or source annotations are identical. Keep the raw JSON: a summary table can omit fields needed later.

4) Deterministic retrieval: download a protein sequence with gget seq

Fetch translated sequence output for the same gene. The gget manual states that --translate returns amino-acid sequences fetched from UniProt, while nucleotide sequences are fetched from Ensembl; --isoforms requests sequences for all known transcripts for a gene ID. The manual does not establish a canonical-selection rule for this default query, so identify any accession/isoform from the returned FASTA header and source record rather than assuming which product was selected.

log_run 'gget seq --translate ENSG00000130234' gget seq --translate ENSG00000130234 > retrieval-results/ACE2_protein.fasta || echo "gget seq failed; inspect stderr and output file."

# Structural check: require a FASTA header and at least one sequence character
python - <<'PY'
from pathlib import Path
p = Path("retrieval-results/ACE2_protein.fasta")
lines = p.read_text().splitlines()
if not lines or not lines[0].startswith(">") or not any(line.strip() for line in lines[1:]):
    raise SystemExit("FAIL: expected a FASTA header followed by a non-empty sequence; inspect the file and gget error before retrying")
print("Header:", lines[0])
print("Sequence characters:", sum(len(line.strip()) for line in lines[1:]))
PY

Illustrative shape only (not a promised ACE2 accession or sequence): >source_record_id description or isoform details followed by one or more lines of amino-acid letters. A header-and-sequence check catches empty files and many error-page responses, but it does not prove the record matches the requested gene. If the check fails, inspect the file beginning and command error, verify network/service availability, and rerun only after resolving the cause. If it passes, compare the header identifier with the relevant UniProt record; report unresolved mapping or isoform identity as unknown.

Files produced:

  • retrieval-results/ACE2_protein.fasta — FASTA output from gget. For translated output, gget uses UniProt; it is not a sequence fetched from Ensembl.

5) Save exact commands, inputs, and timestamps for provenance

The two CLI retrievals above append start and completion timestamps, the exact command labels, and exit statuses to retrieval-results/commands.log. The separate Python API query is not wrapped by this logger. Times are local to the shell and bracket execution; they do not freeze upstream database state.

Files produced:

  • retrieval-results/commands.log — start/end timestamps, exact command labels, and exit status for CLI retrievals. Times are local to the shell and bracket execution; they do not freeze upstream database state.

Output inspection and interpretation

After you save retrieval outputs, inspect them systematically. For each saved file ask:

  • Does the response include the queried Ensembl ID and any linked transcript/protein identifiers?
  • If coordinates are present, can you identify the assembly and annotation release from the returned metadata or source? If not, do not assign an assembly by assumption.
  • Is there a retrieval timestamp and the gget version recorded?

Example: what to look for in ACE2_info_python.csv

  • Requested ID and linked IDs: distinguish the gene ID from transcript and protein IDs. A successful query for one identifier does not establish that every linked record is current or relevant to your analysis.
  • Coordinates: confirm coordinate convention, assembly, and annotation release using returned metadata or the source database. If any are absent, report them as unknown rather than assuming GRCh38.
  • uniprot_id: link to UniProt canonical accessions, if present. Absence does not mean the protein is uncharacterized; it may reflect lacking cross-reference in that release.
  • description: human-readable gene description. Do not treat this as a definitive function annotation; it's a short text string from the database.

What a plausible result means and does not prove:

  • A returned identifier shows that the service supplied a mapping for the query at that time. It does not validate downstream analyses, nor does an ID alone resolve ambiguity in a symbol-based query.
  • Presence of a UniProt accession means UniProt and Ensembl are cross-referenced in that release; absence could be due to timing or curation differences, not necessarily absence of an actual protein product.
  • For gget seq --translate, the gget manual identifies UniProt as the amino-acid sequence source. Do not label a record canonical unless the returned record establishes which sequence was selected. Sequence retrieval is not experimental validation, and alternative isoforms may exist.

Troubleshooting: symptoms, likely causes, and fixes

Below are common issues when working with gget and how to proceed.

Symptom: gget command not found

  • Likely cause: gget is not installed in the active Python environment or the virtualenv is not activated.
  • Fixes:
    1. Activate the virtual environment: source .venv/bin/activate.
    2. Reinstall: python -m pip install gget==0.28.6 and check python -m pip freeze | grep gget.
    3. Check that the active environment contains gget with python -m pip show gget; the CLI is invoked as gget info ENSG00000130234.

Symptom: empty JSON or no matching record for a gene symbol

  • Likely causes:
    • Ambiguous or species-ambiguous gene symbol (e.g., many species use the same symbol).
    • Symbol is deprecated or not present in the selected species.
  • Fixes:
    1. Resolve the symbol with gget search -s homo_sapiens FOXP3; confirm the intended match before querying its Ensembl ID.
    2. Try a stable identifier (Ensembl ENSG...) if available.
    3. Use gget search -s homo_sapiens FOXP3 to see candidate matches and their species context.

Symptom: FASTA file is truncated or contains HTML/redirect text

  • Likely causes: network interruption, API rate limiting, or gget following an HTTP redirect to a page.
  • Fixes:
    1. Check network connectivity and retry.
    2. Inspect the file start with head -n5 to see if it contains an error HTML page; if so, retry later or check the gget error and upstream service status before retrying. Do not switch endpoints unless gget documentation identifies a supported option.
    3. Use the Python API and check for exceptions rather than piping CLI output, so you get proper error messages.

Symptom: different results on repeat retrievals

  • Likely causes:
    • Database updates between retrievals (annotation changes, new releases).
    • Different default assembly or species settings in different runs.
  • Fixes:
    1. Record the gget version and query time. Identify the Ensembl release or assembly from returned metadata or source records; do not infer missing values.
    2. If reproducibility is critical, capture and archive the raw JSON output and the complete environment (requirements.txt, Python version).

Limitations, reference-data caveats, and responsible use

Limitations and caveats to keep in mind:

  • Database currency: gget queries external services. Responses reflect service state at retrieval time and can change with database releases or service changes. The saved response preserves the received result, not a snapshot of the database.
  • Identifier granularity: Ensembl has separate namespaces for genes (ENSG), transcripts (ENST) and proteins (ENSP). Ensure you request the correct namespace for your task.
  • Assembly version: Genomic coordinates are meaningful only when paired with an assembly (e.g., GRCh37/hg19 vs GRCh38/hg38). If the response omits the assembly, do not assume one; consult the source record or omit assembly-specific interpretation.
  • LLM interpretation: supplying retrieved records may ground an LLM response, but does not guarantee that the model will use them correctly. Validate critical facts against the saved record and upstream source.
  • Data licensing and usage: check the upstream database terms and licenses for the data and use case. Do not assume one licensing rule applies across these services.

Responsible-use notes:

  • When sharing retrieval outputs in publications or reports, include the exact commands, the gget and dependency versions, retrieval timestamps, and the source (Ensembl/UniProt release).
  • Do not assume that a retrieved gene description equals experimentally validated function. Use appropriate experimental evidence when making biological claims.
  • For human genomic data with privacy concerns, ensure that any identifiers or sequences do not inadvertently reveal participant-level data or violate consent agreements.

Next-step checklist

  1. Confirm gget installation and record retrieval-results/gget-help.txt and retrieval-results/requirements.txt.
  2. Run a deterministic retrieval for at least one gene and save both raw JSON and a CSV summary in retrieval-results/.
  3. Record the exact commands and timestamps to retrieval-results/commands.log.
  4. If you provide the saved response to an LLM, ask it to cite the file and quote the relevant field. Verify its interpretation yourself against the source record.
  5. If you will share results externally, include the gget version, retrieval timestamp, and database release numbers in your methods section.
