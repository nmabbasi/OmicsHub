Data Visualization Fundamentals

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

By the end of this lesson you will be able to:

  • Choose appropriate visualizations for common bioinformatics questions (QC, sample structure, differential signals).
  • Generate reproducible plots for distributions, PCA (principal component analysis), UMAP (Uniform Manifold Approximation and Projection), heatmaps, and volcano plots, with explicit preprocessing reported.
  • Read and interpret these plots conservatively: distinguish visual patterns from statistical or biological claims and list the assumptions behind each plot.
  • Produce a publication-ready exploratory figure with labeled axes (including units), a documented color choice, an interpretation note, and the code used to create it.

Prerequisites:

  • Basic familiarity with R (ggplot2) or Python (matplotlib/seaborn/pandas). Example code is provided for both languages.
  • Completion of a basic quality-control tutorial for the assay you are using (e.g., RNA-seq QC, single-cell QC).
  • Access to a UNIX-like shell to run commands and save outputs to files.

Why careful visualization matters (biological and computational context)

Plots are arguments: they communicate evidence, assumptions, and uncertainty. In omics and bioinformatics, visuals are used at multiple stages — quality control (QC), exploratory data analysis (EDA), dimensionality reduction, and hypothesis testing. Each plot type encodes both data and processing choices (filtering, normalization, scaling, color mapping). If these choices are not reported, readers may over-interpret visual patterns as biological mechanisms when they could be batch effects, normalization artifacts, or downstream processing differences.

This lesson emphasizes responsible plotting: always show units and sample sizes, state preprocessing, avoid misleading scales or truncated axes, and treat plots as descriptive evidence that motivates further statistical testing, not proof of mechanism.

Reproducible, sequential workflow

The workflow below assumes you start with tabular expression or QC metrics. Example paths and outputs are explicit. Adjust file names to your environment. The commands are intended to be run locally; they do not modify your raw data files.

Files you should have

  • data/qc_metrics.tsv — tab-separated QC metrics with columns: sample, batch, condition, total_reads, pct_mt, mapping_rate (example header below).
  • data/counts.tsv — raw or preprocessed count matrix (genes x samples) for PCA/heatmaps/volcano; tab-separated with gene IDs in the first column and sample IDs matching qc_metrics.tsv header.

Example header for qc_metrics.tsv (first line):

sample\tbatch\tcondition\ttotal_reads\tpct_mt\tmapping_rate
S01\tB1\tcontrol\t25000000\t5.2\t0.95
...

Step A — Basic QC plots (distribution, per-sample metrics)

Goal: identify outliers, batch patterns, or samples that fail pre-defined thresholds.

# Python 3.11 example (save to scripts/qc_plots.py)
# Input: data/qc_metrics.tsv
# Output: results/qc_boxplot.png, results/qc_histograms.png
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt
sns.set(style="whitegrid", context="talk")

qc = pd.read_csv("data/qc_metrics.tsv", sep="\t")

# Boxplot by batch with jittered points colored by condition
plt.figure(figsize=(8,5))
ax = sns.boxplot(data=qc, x="batch", y="pct_mt", showfliers=False)
sns.stripplot(data=qc, x="batch", y="pct_mt", hue="condition", dodge=True,
              jitter=0.2, palette="colorblind", alpha=0.6)
ax.set_xlabel("Batch")
ax.set_ylabel("Mitochondrial reads (%)")
ax.set_title("QC: mitochondrial fraction by batch")
plt.legend(title="Condition", bbox_to_anchor=(1.05, 1), loc="upper left")
plt.tight_layout()
plt.savefig("results/qc_boxplot.png", dpi=300)
plt.close()

# Histogram and KDE of total reads
plt.figure(figsize=(6,4))
sns.histplot(qc["total_reads"]/1e6, kde=True, color="#4C72B0", bins=20)
plt.xlabel("Total reads (millions)")
plt.title("Distribution of sequencing depth")
plt.tight_layout()
plt.savefig("results/qc_histograms.png", dpi=300)

# R 4.3.2 equivalent (save to scripts/qc_plots.R)
# Input: data/qc_metrics.tsv
# Output: results/qc_boxplot_R.png
library(ggplot2)
qc <- read.delim("data/qc_metrics.tsv", stringsAsFactors = FALSE)

p <- ggplot(qc, aes(x = batch, y = pct_mt, color = condition)) +
  geom_boxplot(outlier.shape = NA, alpha = 0.6) +
  geom_jitter(width = 0.2, size = 1.5, alpha = 0.7) +
  labs(x = "Batch", y = "Mitochondrial reads (%)", title = "QC: mitochondrial fraction by batch") +
  theme_minimal()
ggsave("results/qc_boxplot_R.png", p, width = 8, height = 5, dpi = 300)

What these commands produce:

  • results/qc_boxplot.png (or qc_boxplot_R.png) — a boxplot of pct_mt per batch with individual points colored by condition.
  • results/qc_histograms.png — global distribution of sequencing depth (total reads) in millions.

Step B — PCA for global structure

Goal: identify axes of major variation and check for cohort, batch, or outlier structure. Always document preprocessing (log-transform, scaling) and random seed.

# Python example using scikit-learn (save to scripts/pca_analysis.py)
# Input: data/counts.tsv
# Output: results/pca_coords.tsv, results/pca_plot.png
import numpy as np
import pandas as pd
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler
import matplotlib.pyplot as plt
import seaborn as sns

np.random.seed(7)
counts = pd.read_csv("data/counts.tsv", sep="\t", index_col=0)  # genes x samples
# Basic preprocessing: filter low-count genes, log2 CPM (counts per million)
libsize = counts.sum(axis=0)
cpm = counts.divide(libsize, axis=1) * 1e6
logcpm = np.log2(cpm + 1)

# Keep genes with variance above a small threshold to reduce noise
var_genes = logcpm.var(axis=1)
keep = var_genes > 0.5
mat = logcpm.loc[keep].T  # samples x genes

# Scale features (zero mean, unit variance)
mat_scaled = StandardScaler().fit_transform(mat)

pca = PCA(n_components=10, random_state=7)
pcs = pca.fit_transform(mat_scaled)

pcs_df = pd.DataFrame(pcs[:, :2], columns=["PC1", "PC2"], index=mat.index)
pcs_df.to_csv("results/pca_coords.tsv", sep="\t")

meta = pd.read_csv("data/qc_metrics.tsv", sep="\t", index_col=0)
plot_df = pcs_df.join(meta, how="left")

plt.figure(figsize=(6,5))
sns.scatterplot(data=plot_df, x="PC1", y="PC2", hue="condition", style="batch", palette="colorblind", s=60)
plt.xlabel(f"PC1 ({pca.explained_variance_ratio_[0]*100:.1f}%)")
plt.ylabel(f"PC2 ({pca.explained_variance_ratio_[1]*100:.1f}%)")
plt.title("PCA of log2-CPM (genes filtered, scaled)")
plt.tight_layout()
plt.savefig("results/pca_plot.png", dpi=300)

Notes:

  • Save PCA coordinates to results/pca_coords.tsv so downstream reproducibility is explicit.
  • Report preprocessing: gene filtering threshold, transformation (log2-CPM + 1), scaling method, and random_state.

Step C — UMAP for local neighborhoods (single-cell or high-dimensional)

# Python example using umap-learn (save to scripts/umap_analysis.py)
# Input: results/pca_coords.tsv or preprocessed matrix
# Output: results/umap_coords.tsv, results/umap_plot.png
import umap
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns

np.random.seed(7)
# Prefer running UMAP on PCA components or scaled features, not raw counts
pca_coords = pd.read_csv("results/pca_coords.tsv", sep="\t", index_col=0)
# If you have numeric PCA components, use them; here we'll simulate using first 10 PCs if available
# Assume pca_matrix is samples x n_components produced earlier; for this example, re-load mat_scaled if available
# For reproducibility, you should run UMAP with documented parameters:
reducer = umap.UMAP(n_neighbors=15, min_dist=0.1, n_components=2, metric="euclidean", random_state=7)
# If you have the original scaled matrix, pass that; here we use PCS (if saved as many dims)
# Example: pcs_full = pd.read_csv("results/pca_full.tsv", sep="\t", index_col=0)
# embedding = reducer.fit_transform(pcs_full)
# For demonstration, if only PC1/PC2 available, UMAP is less meaningful — prefer at least 10 PCs.
embedding = reducer.fit_transform(pca_coords.values)  # adjust according to your saved matrix
emb_df = pd.DataFrame(embedding, columns=["UMAP1", "UMAP2"], index=pca_coords.index)
emb_df.to_csv("results/umap_coords.tsv", sep="\t")

meta = pd.read_csv("data/qc_metrics.tsv", sep="\t", index_col=0)
plot_df = emb_df.join(meta, how="left")
plt.figure(figsize=(6,5))
sns.scatterplot(data=plot_df, x="UMAP1", y="UMAP2", hue="condition", palette="tab10", s=40)
plt.title("UMAP (n_neighbors=15, min_dist=0.1) — input: PCA components")
plt.tight_layout()
plt.savefig("results/umap_plot.png", dpi=300)

Important: record all UMAP parameters (n_neighbors, min_dist, metric, random_state) and the input matrix (which PCA components or scaled features you used). UMAP is sensitive to these choices, and different seeds or inputs can produce different-looking layouts.

Step D — Heatmap and clustering

# Python example using seaborn clustermap (save to scripts/heatmap.py)
# Input: data/counts.tsv, results/pca_coords.tsv
# Output: results/heatmap_topgenes.png
import pandas as pd
import numpy as np
import seaborn as sns
import matplotlib.pyplot as plt

counts = pd.read_csv("data/counts.tsv", sep="\t", index_col=0)
# Select top variable genes for the heatmap (e.g., top 50 by variance)
logcpm = np.log2((counts / counts.sum(axis=0)) * 1e6 + 1)
var = logcpm.var(axis=1)
top50 = logcpm.loc[var.sort_values(ascending=False).head(50).index]

# Z-score by gene (rows) to emphasize patterns across samples
from scipy.stats import zscore
z_top50 = top50.apply(zscore, axis=1)

cg = sns.clustermap(z_top50, method="average", metric="euclidean",
                    row_cluster=True, col_cluster=True, cmap="vlag",
                    col_colors=None, standard_scale=None, figsize=(10,10))
plt.savefig("results/heatmap_topgenes.png", dpi=300)

Document clustering choices: distance metric (euclidean, correlation), linkage method (average, ward), and whether rows/columns were scaled or standardized. Heatmaps emphasize patterns but can hide absolute expression units; always state the transformation used (e.g., row z-score).

Step E — Volcano plot for differential expression

# R example using DESeq2 result (save to scripts/volcano_plot.R)
# Input: results/deseq2_results.tsv (must contain log2FoldChange and padj columns)
# Output: results/volcano.png
library(ggplot2)
res <- read.delim("results/deseq2_results.tsv", stringsAsFactors = FALSE)
res$label <- ifelse(res$padj < 0.05 & abs(res$log2FoldChange) > 1, "significant", "not_significant")

ggplot(res, aes(x=log2FoldChange, y=-log10(padj))) +
  geom_point(aes(color=label), alpha=0.6, size=1.5) +
  scale_color_manual(values=c("not_significant"="#B0B0B0", "significant"="#D62728")) +
  labs(x="log2 fold change", y="-log10 adjusted p-value", title="Volcano plot") +
  geom_vline(xintercept=c(-1,1), linetype="dashed", color="black", alpha=0.5) +
  geom_hline(yintercept=-log10(0.05), linetype="dashed", color="black", alpha=0.5) +
  theme_minimal()
ggsave("results/volcano.png", width=6, height=5, dpi=300)

Note: the volcano plot visualizes effect size (log2 fold change) vs statistical significance (adjusted p-value). Do not equate statistical significance with biological importance; small effect sizes with tiny p-values may be statistically robust but biologically negligible. Report the test used (Wald test, LRT), multiple testing correction method (e.g., Benjamini–Hochberg), and the model formula (covariates included).

Output inspection and interpretation

For each plot type, here is what to look for and what a plausible observation might indicate — along with what it does NOT prove.

QC plots (boxplots, histograms)

  • Look for: clear outliers, multi-modal distributions, batch-specific shifts, or truncated axes.
  • Plausible meaning: a cluster of low total_reads could indicate failed libraries; batch shifts in pct_mt may suggest technical differences in sample handling.
  • What it does NOT prove: a high mitochondrial fraction does not, by itself, prove a sample is degraded or low-quality — check protocol-specific thresholds and other QC metrics (mapping_rate, gene detection).

PCA

  • Look for: separation by known covariates (condition, batch), tight clusters, or single-sample outliers. Check explained variance for PC1/PC2.
  • Plausible meaning: if PC1 separates samples by batch and explains a large fraction of variance, batch correction or modelling may be required before downstream analysis.
  • What it does NOT prove: PCA shows major axes of variation but does not identify which genes drive the separation without further loadings analysis; it does not establish causality.

UMAP

  • Look for: local clusters, gradients, or mixing of known labels. Compare multiple parameter settings (n_neighbors, min_dist) and seeds.
  • Plausible meaning: tight local clusters often reflect groups of similar samples/cells but can also arise from overclustering or insufficient preprocessing.
  • What it does NOT prove: UMAP geometry is non-linear and non-parametric; distances or angles are not directly interpretable as meaningful global metrics, and different runs/parameters can change the layout.

Heatmap

  • Look for: consistent block structures, sample clusters, and annotation concordance with metadata.
  • Plausible meaning: co-clustering of sets of genes and samples can indicate shared regulation or technical biases (e.g., library prep). Examine raw vs scaled views to understand absolute vs relative changes.
  • What it does NOT prove: heatmap clustering alone does not validate biological pathways or regulatory relationships — follow up with enrichment analysis and statistical tests.

Volcano plot

  • Look for: genes that are both large in effect and significant. Mark thresholds clearly (fold-change, adjusted p-value).
  • Plausible meaning: candidate genes for follow-up validation; however small fold-changes with tiny p-values may be sequencing-depth artifacts or batch-related.
  • What it does NOT prove: significance does not equal biological relevance; validate with independent experiments or orthogonal measurements.

Troubleshooting

Symptom: PCA separates samples by batch rather than the biological condition you expect.

  • Likely causes: unbalanced design, batch-specific library prep, or normalization that removed biological signal.
  • Fixes: re-check metadata, include batch as a covariate in downstream models, consider batch-correction methods (ComBat, limma removeBatchEffect) while preserving experimental contrasts. Always perform diagnostics post-correction to ensure biology is retained.

Symptom: UMAP shows many singleton clusters or excessive fragmentation.

  • Likely causes: insufficient feature selection (too many noisy features), inappropriate n_neighbors for dataset size, or very aggressive min_dist.
  • Fixes: reduce dimensionality first (PCA on top variable genes), increase n_neighbors, increase min_dist, or use larger perplexity analogue in t-SNE if appropriate. Rerun with documented seed and parameters.

Symptom: Heatmap shows no structure, everything looks uniform.

  • Likely causes: plotting raw counts without transformation, or inclusion of too many low-variance genes.
  • Fixes: log-transform or compute z-scores per gene, restrict to top variable genes, and choose color scales that show midrange contrasts (e.g., divergent palettes centered at zero after z-scoring).

Limitations, version and reference-data caveats, and responsible-use notes

  • Software versions matter. Reproducibility requires recording major package versions (e.g., Python 3.11, R 4.3.2, scikit-learn version, umap-learn version, seaborn/matplotlib or ggplot2). Save session info or a conda/environment YAML when possible.
  • Transformations affect interpretability: e.g., log-transformed data compresses large differences; z-scoring removes between-gene amplitude information. State transformations explicitly in captions and methods.
  • Color and accessibility: use colorblind-friendly palettes (e.g., ColorBrewer “Colorblind” or seaborn “colorblind” palette). Avoid red/green as the only contrast for critical categorizations.
  • Statistical caution: visualization is exploratory. Use appropriate statistical models for inference and correct for multiple testing. Provide effect-size thresholds in addition to p-values.
  • Reference data: when comparing to external references (e.g., cell atlases), ensure compatible preprocessing and batch-correction strategies are applied; mismatched normalization can produce misleading overlays.

Next-step checklist (concise)

  • Document preprocessing steps (filtering thresholds, normalization, scaling) in a README accompanying your figures.
  • Save intermediate outputs (pca_coords.tsv, umap_coords.tsv, heatmap matrices) to the results/ directory for reproducibility.
  • Annotate each figure with: dataset, n (samples), preprocessing summary, plotting parameters (e.g., UMAP params), software versions, interpretation sentence, and one limitation sentence.
  • When making biological claims, follow visualization with appropriate statistical tests and, where possible, independent validation.
