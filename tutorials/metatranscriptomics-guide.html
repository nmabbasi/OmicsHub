Metatranscriptomics Basics

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

By the end of this lesson you should be able to:

  • Explain the difference between metagenomic presence (DNA) and metatranscriptomic activity (RNA).
  • Describe a reproducible preprocessing and analysis workflow for short-read metatranscriptomic data, including rRNA and host removal, quality control (QC), taxonomic context, and functional profiling.
  • Run core commands (SortMeRNA, Bowtie2, Diamond, HUMAnN3 or SAMSA2) with explicit input and output paths and interpret the principal outputs.

Prerequisites:

  • Familiarity with RNA-seq concepts and basic Linux command line.
  • Completed an introductory metagenomics or taxonomic profiling tutorial and comfortable with FASTQ/FASTA files.
  • Installed tools or access to an environment with SortMeRNA, Bowtie2, Diamond, HUMAnN3 (and MetaPhlAn), or SAMSA2. Exact versions and reference databases will affect results — see limitations below.

Why metatranscriptomics matters (biological and computational context)

Metatranscriptomics measures the pool of RNA molecules (typically mRNA after rRNA depletion) present in a complex microbial community at the time of sampling. Unlike shotgun metagenomics, which reports on genetic potential (what genes are present), metatranscriptomics reports on gene expression (what genes are being actively transcribed). This distinction is critical for understanding microbial responses to environment, stress, treatment, or host interaction.

Computationally, metatranscriptomics is more demanding than metagenomics because most RNA mass in cells is ribosomal RNA (rRNA), and in host-associated samples a large fraction of reads may derive from the host. Therefore, accurate rRNA and host read removal, careful normalization, and awareness of reference database bias are essential.

Reproducible sequential workflow

The following workflow assumes paired-end Illumina reads. Adjust for single-end data by omitting the second file arguments. All paths are explicit; replace sample names and references with your actual files. Commands show common options but are not exhaustive — consult tool manuals for advanced parameters.

Files you should have before starting

  • Raw sequencing reads: sample_R1.fastq.gz and sample_R2.fastq.gz
  • Host reference genome (FASTA) or index for Bowtie2: e.g., human_GRCh38.fasta
  • rRNA reference database for SortMeRNA: e.g., smr_v4.3_default_db.fasta (or the bundled DBs)
  • HUMAnN3 and MetaPhlAn database files, or SAMSA2-compatible database (RefSeq/SEED) and Diamond database

Step 0 — Initial QC

# produce per-read QC reports (FastQC) and aggregate (MultiQC)
fastqc -o qc_reports/ sample_R1.fastq.gz sample_R2.fastq.gz
multiqc qc_reports/ -o qc_reports/

Outputs: QC HTML files in qc_reports/. Inspect per-base quality, adapter content, and overrepresented sequences.

Step 1 — Adapter trimming and quality filtering

# using fastp for adapter/adaptor trimming and read filtering
fastp -i sample_R1.fastq.gz -I sample_R2.fastq.gz \
      -o trimmed/sample_trim_R1.fastq.gz -O trimmed/sample_trim_R2.fastq.gz \
      -h trimmed/fastp_report.html -j trimmed/fastp_report.json --thread 8

Outputs: trimmed FASTQ files and HTML/JSON reports. Confirm adapter removal and per-base quality improvements.

Step 2 — Remove rRNA (SortMeRNA)

# SortMeRNA (example configuration)
# Requires index DB files; adjust --ref paths to your installed DBs.
sortmerna --ref /path/to/silva-bac-16s-id90.fasta,/path/to/silva-bac-16s-db \
          --ref /path/to/silva-euk-18s.fasta,/path/to/silva-euk-18s-db \
          --reads trimmed/sample_trim_R1.fastq.gz \
          --reads trimmed/sample_trim_R2.fastq.gz \
          --aligned rRNA/sample_rRNA \
          --other nonrRNA/sample_nonrRNA \
          --fastx --paired_in --threads 8

Outputs:

  • rRNA/sample_rRNA.*: reads classified as rRNA (likely many reads).
  • nonrRNA/sample_nonrRNA.*: reads remaining after rRNA removal (to use downstream as putative mRNA).

Note: SortMeRNA may produce paired and unpaired files; ensure pairing is kept for downstream tools that require paired reads.

Step 3 — Remove host-derived reads (Bowtie2)

# Build or use an existing Bowtie2 index for the host genome (one-time)
bowtie2-build human_GRCh38.fasta indices/GRCh38

# Map and keep only unmapped reads (i.e., non-host)
bowtie2 -x indices/GRCh38 \
        -1 nonrRNA/sample_nonrRNA_R1.fastq.gz -2 nonrRNA/sample_nonrRNA_R2.fastq.gz \
        --very-sensitive --threads 8 --un-conc-gz nonhost/sample_nonhost_unmapped.%_fastq.gz \
        -S host_mapped.sam 2> bowtie2_host.log

Outputs:

  • nonhost/sample_nonhost_unmapped.1_fastq.gz and .2_fastq.gz — paired reads not mapping to host; these are your host-depleted reads for annotation.
  • host_mapped.sam and bowtie2_host.log — mapping statistics; inspect for percent mapped as a QC metric.

Step 4a — Option A: Functional profiling with HUMAnN3

HUMAnN3 integrates MetaPhlAn for taxonomic profiling and a two-tier functional search (pangenome mapping then translated search). Input should be host- and rRNA-depleted reads. 

# run HUMAnN3 (reads can be single- or paired-end; here we provide paired ends)
humann --input nonhost/sample_nonhost_unmapped.1_fastq.gz,nonhost/sample_nonhost_unmapped.2_fastq.gz \
       --output humann_out/ --threads 16 --metaphlan-options "--input_type fastq"

Outputs (per sample):

  • humann_out/sample_genefamilies.tsv — gene-family abundances (often UniRef90 identifiers).
  • humann_out/sample_pathabundance.tsv — pathway abundance estimates.
  • vivified intermediate files and MetaPhlAn taxonomic profile.

Step 4b — Option B: Annotation with SAMSA2 / Diamond

SAMSA2 is a flexible framework often used to annotate reads directly with Diamond against RefSeq/SEED. Workflows and database setup vary; below is a minimal Diamond step for translated search.

# make Diamond DB (one-time)
diamond makedb --in refseq_proteins.fasta -d db/refseq_db

# translated search (blastx equivalent)
diamond blastx -d db/refseq_db \
               -q nonhost/sample_nonhost_unmapped.1_fastq.gz --query-gzip true \
               -q2 nonhost/sample_nonhost_unmapped.2_fastq.gz --threads 16 \
               -o diamond/sample_matches.m8 -f 6 qseqid sseqid pident length evalue bitscore stitle

Outputs:

  • diamond/sample_matches.m8 — tabular alignments; use SAMSA2 scripts or custom parsing to produce functions and taxon-level summaries.

Output inspection and interpretation

After running HUMAnN3 or SAMSA2, focus your inspection on three areas: mapping rates, gene/pathway abundance patterns, and taxonomic context.

  • Mapping rates — Check how many reads passed QC, how many were filtered as rRNA or host, and how many remained for annotation. Extremely low retained read counts (<1M reads for complex samples, depending on study goals) can limit interpretability.
  • Gene-family abundances — HUMAnN3 gene-family tables (UniRef IDs) indicate relative transcriptional activity. Look for consistent, biologically plausible signals (e.g., transcription of housekeeping genes across samples). A high relative abundance of a pathway suggests active transcription, not necessarily high protein production.
  • Pathway abundance — Pathway-level summaries aggregate gene families; increased pathway abundance can indicate coordinated expression, but interpretation requires normalization and consideration of contributing taxa.

What a plausible result means:

  • High expression of genes related to, for example, carbohydrate metabolism in gut samples suggests the microbiome is actively using those substrates under sampled conditions.
  • Concordance between taxonomic and functional signals (e.g., taxa known to encode a pathway also show corresponding transcript counts) strengthens biological plausibility.

What the results do NOT prove:

  • Transcript abundance does not equal protein abundance or enzymatic activity. Post-transcriptional regulation, mRNA stability, and translation efficiency can decouple RNA and protein levels.
  • Detection of transcripts from a taxon does not guarantee the organism is growing; it may be transiently active or stressed.

Troubleshooting (symptoms, likely causes, fixes)

  • Symptom: Very high proportion (>80%) of reads are retained as rRNA after laboratory depletion.
    Likely cause: Inefficient wet-lab depletion or poor match between depletion probes and sample rRNA sequences.
    Fix: Use a permissive computational rRNA filter (SortMeRNA with multiple rRNA DBs), consider experimental redesign with a different depletion kit, or increase sequencing depth.
  • Symptom: >50% reads map to host after host filtering.
    Likely cause: Sampling tissue with high host RNA content (blood, biopsy) or inefficient host removal.
    Fix: Improve sample preparation to reduce host RNA, add additional host references (mitochondrial/contaminant genomes), or use more sensitive mapping parameters. Document the fraction of host reads in your metadata.
  • Symptom: Few reads map to functional databases; diamond / HUMAnN translational search yields low sensitivity.
    Likely cause: Novel organisms absent from reference databases, too-short reads, or errors introduced by sequencing.
    Fix: Use translated searches with reduced stringency (longer e-value thresholds), assemble reads to transcripts (metatranscriptome assembly) and annotate contigs, or supplement with custom reference protein sets.
  • Symptom: One sample drives an apparent pathway-level difference but has low sequencing depth or high rRNA carryover.
    Likely cause: Technical artifact rather than biological effect.
    Fix: Re-evaluate normalization, remove low-depth or poor-quality samples from downstream comparative analyses, and repeat library prep/sequence if possible.

Limitations, version and reference-data caveats, and responsible use

Metatranscriptomic analyses are subject to several limitations that should be explicitly acknowledged in any report or publication:

  • Database bias: Functional assignments depend on the completeness and taxonomic breadth of protein databases (UniRef, RefSeq, SEED). Novel or uncultured taxa may be misannotated or unannotated.
  • Normalization choices: RNA-seq normalization methods (TPM, RPKM, CPM) impact comparisons across samples. HUMAnN3 provides options for gene-family normalization; document your choice and justify for the study design.
  • Temporal/Spatial snapshots: Metatranscriptomics captures a moment in time and may be sensitive to sampling handling, storage, and diurnal effects. Avoid overgeneralizing from single timepoints.
  • Tool and database versions: Results will change with software versions and database releases. Record exact tool versions and database names/versions as part of provenance and reproducibility.
  • Ethical/responsible use: For host-associated samples, remove host sequences prior to public deposition unless consent and controlled-access deposition are appropriate. Protect subject privacy and adhere to data sharing agreements.

Concise next-step checklist

  1. Record tool versions and database names used for SortMeRNA, Bowtie2, HUMAnN3, Diamond/SAMSA2.
  2. Run QC and trimming; confirm improvements in quality reports.
  3. Perform rRNA and host removal; document read counts at each stage.
  4. Choose HUMAnN3 for integrated taxonomic+functional profiling or SAMSA2/Diamond for custom annotation workflows; run with consistent parameters across samples.
  5. Inspect mapping rates, gene-family and pathway outputs; perform appropriate normalization before between-sample comparisons.
  6. Annotate your methods with exact commands, parameter settings, and database versions for reproducibility.
