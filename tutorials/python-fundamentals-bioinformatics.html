Python Fundamentals for Bioinformatics

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Learn core Python 3 constructs for bioinformatics step by step: string normalization and reverse complements, reusable functions with explicit ambiguous-base rules, k-mer dictionaries, constant-memory FASTA generators (yield), and validated CSV output. Readers following the R-first track can jump directly to R and Tidyverse Fundamentals or open the collapsible base-R comparison at the bottom of this page.

Format: Hands-on lab. Builds a complete Python 3 standard-library FASTA validator and summary CLI from individual language building blocks, with locally executed Python 3.12 outputs at every step and no external package requirement.

What you will build and prerequisites

You will progress from interactive Python expressions on a single DNA sequence to a modular command-line script (scripts/compute_fasta_stats.py) that streams multi-record FASTA files in constant memory and writes a checked CSV (id, length, gc_fraction, valid). All core steps require only Python 3.10+ and a POSIX terminal.

Step 1: Strings, slicing, and reverse complements

Raw sequence strings from text files or primers often arrive with leading/trailing whitespace, newline characters, mixed case, or ambiguous N bases. Python strings are immutable sequences supporting zero-based slicing (seq[start:stop]), reversal (seq[::-1]), and fast character translation tables via str.maketrans():

raw_seq = "  acgtacgtnnacgt \n"
seq = "".join(raw_seq.split()).upper()
complement_table = str.maketrans("ACGTN", "TGCAN")
rev_comp = seq.translate(complement_table)[::-1]

print(f"Normalized: {seq} (length = {len(seq)}, first_codon = {seq[:3]})")
print(f"Reverse complement: {rev_comp}")

Observed output (Python 3.12.3):

Normalized: ACGTACGTNNACGT (length = 14, first_codon = ACG)
Reverse complement: ACGTNNACGTACGT

Mini-exercise: Why use "".join(raw_seq.split()) instead of raw_seq.strip()? Because multi-line FASTA sequences or GenBank pastes can contain internal spaces or newlines; .split() removes all whitespace characters anywhere in the string, whereas .strip() trims only the ends.

Step 2: Functions, sets, and the GC denominator trap

Membership checks against a set (ch in VALID_BASES) run in O(1) average time. When writing a GC-content function, decide explicitly whether ambiguous N bases belong in the denominator: dividing G + C by full sequence length (6 / 14 = 0.42857) differs from Biopython's Bio.SeqUtils.gc_fraction(seq, ambiguous="remove") default, which drops N from the denominator (6 / 12 = 0.50000):

VALID_BASES = set("ACGTN")

def is_valid_dna(seq: str) -> bool:
    return bool(seq) and all(ch in VALID_BASES for ch in seq)

def gc_fraction(seq: str, include_n: bool = True) -> float:
    denom = len(seq) if include_n else sum(1 for ch in seq if ch in "ACGT")
    if denom == 0:
        return 0.0
    return sum(1 for ch in seq if ch in "GC") / denom

seq = "ACGTACGTNNACGT"
print(f"Valid: {is_valid_dna(seq)} | GC (with N): {gc_fraction(seq, True):.5f} | GC (A/C/G/T only): {gc_fraction(seq, False):.5f}")

Observed output:

Valid: True | GC (with N): 0.42857 | GC (A/C/G/T only): 0.50000

Step 3: Lists, loops, and dictionaries for k-mer counting

Dictionaries (dict) map unique keys (such as record IDs or short oligonucleotide k-mers) to values in constant average lookup time. Sliding a window of length k = 4 across seq while skipping windows containing N illustrates loops, conditionals, and dict.get(key, 0):

seq = "ACGTACGTNNACGT"
kmers: dict[str, int] = {}
for i in range(len(seq) - 4 + 1):
    kmer = seq[i : i + 4]
    if "N" not in kmer:
        kmers[kmer] = kmers.get(kmer, 0) + 1

print("Unambiguous 4-mers:", kmers)

Observed output:

Unambiguous 4-mers: {'ACGT': 3, 'CGTA': 1, 'GTAC': 1, 'TACG': 1}

Step 4: Why generators (yield) matter for genome-scale FASTA files

Reading an entire FASTA file into a list or dictionary works for three toy sequences, but human GRCh38 occupies ~3.1 GB uncompressed. A generator function using yield pauses after each complete record, holding only one sequence in RAM at a time while still allowing clean for header, seq in fasta_records(path): iteration.

Step 5: Complete FASTA-to-CSV command-line workflow

1. Set up the project and create the synthetic FASTA fixture

mkdir -p ~/projects/python-bioinfo/data/raw ~/projects/python-bioinfo/scripts ~/projects/python-bioinfo/outputs
cd ~/projects/python-bioinfo

cat > data/raw/example.fasta <<'EOF'
>seq1
ACGTACGTNNACGT
>seq2
acgtacgtacgtacgtacgt
>seq3
AGCTTAGC--NNNN
EOF

cat data/raw/example.fasta

seq3 intentionally contains alignment gap characters (--) so you can verify that invalid records are flagged (valid=no, blank gc_fraction) rather than silently stripped.

2. Optional virtual environment for third-party packages

python3 -m venv .venv
source .venv/bin/activate
# Optional only if you want Step 6's Biopython comparison:
# python -m pip install biopython && python -m pip freeze > envs-requirements.txt

3. Save scripts/compute_fasta_stats.py

#!/usr/bin/env python3
"""Read FASTA records, validate A/C/G/T/N after normalization, and write CSV."""
import csv
from pathlib import Path
import sys

VALID_BASES = set("ACGTN")

def normalize(seq: str) -> str:
    return "".join(seq.split()).upper()

def is_valid_dna(seq: str) -> bool:
    return bool(seq) and all(ch in VALID_BASES for ch in seq)

def gc_fraction(seq: str) -> float:
    if not seq:
        return 0.0
    return sum(1 for ch in seq if ch in ("G", "C")) / len(seq)

def fasta_records(path: Path):
    with open(path, "r", encoding="utf-8") as fh:
        name = None
        parts: list[str] = []
        for raw in fh:
            line = raw.strip()
            if not line:
                continue
            if line.startswith(">"):
                if name is not None:
                    yield name, "".join(parts)
                name = line[1:].strip()
                if not name:
                    raise ValueError("FASTA header is empty")
                parts = []
            elif name is None:
                raise ValueError("Sequence text found before the first FASTA header")
            else:
                parts.append(line)
        if name is not None:
            yield name, "".join(parts)

def main() -> None:
    if len(sys.argv) != 3:
        print("Usage: python3 scripts/compute_fasta_stats.py INPUT.fasta OUTPUT.csv", file=sys.stderr)
        sys.exit(2)
    in_path = Path(sys.argv[1])
    out_path = Path(sys.argv[2])
    if in_path.resolve() == out_path.resolve():
        print("Input and output paths must be different", file=sys.stderr)
        sys.exit(2)
    out_path.parent.mkdir(parents=True, exist_ok=True)
    with open(out_path, "w", newline="", encoding="utf-8") as out_fh:
        writer = csv.DictWriter(out_fh, fieldnames=["id", "length", "gc_fraction", "valid"])
        writer.writeheader()
        for header, seq in fasta_records(in_path):
            seq_norm = normalize(seq)
            valid = is_valid_dna(seq_norm)
            writer.writerow({
                "id": header,
                "length": len(seq_norm),
                "gc_fraction": f"{gc_fraction(seq_norm):.5f}" if valid else "",
                "valid": "yes" if valid else "no",
            })

if __name__ == "__main__":
    main()

4. Run the script and verify the CSV output

python3 scripts/compute_fasta_stats.py data/raw/example.fasta outputs/sequence_stats.csv

5. Optional Biopython comparison and base-R counterpart

When Biopython is installed, Bio.SeqIO.parse(path, "fasta") replaces custom header/line splitting while leaving alphabet and denominator choices to your analysis:

from Bio import SeqIO

valid_bases = set("ACGTN")
for rec in SeqIO.parse("data/raw/example.fasta", "fasta"):
    seq = "".join(str(rec.seq).split()).upper()
    valid = bool(seq) and all(base in valid_bases for base in seq)
    gc_text = f"{sum(1 for b in seq if b in 'GC') / len(seq):.5f}" if valid else ""
    print(rec.id, len(seq), gc_text, "yes" if valid else "no")

Output inspection and interpretation

When you open outputs/sequence_stats.csv, check the following:

  • All expected record IDs are present. Missing IDs may indicate a parsing error or that the input FASTA lines were malformed.
  • Length values reflect the number of characters after normalization (spaces and tabs removed). Very short sequences (length 0–3) should be inspected manually because they may be fragments, adapter sequences, or corrupted lines.
  • gc_fraction is the proportion of G or C bases (0.0–1.0). This script divides the count of G and C characters by the full normalized sequence length, including N in the denominator. Compare values only when the denominator rule and sequence scope match; GC content alone is not a quality verdict.
  • The valid column flags records where non-standard characters were found (for this lesson that means characters outside A,C,G,T,N). If valid is "no", the gc_fraction field is left blank and you should inspect the corresponding sequence in the FASTA file.

What a plausible result means and what it does NOT prove:

  • If a sequence has gc_fraction = 0.42, this simply means 42% of the characters in the provided string are G or C. It does not prove the sequence is error-free or biologically meaningful; contamination, assembly artifacts, or sequencing biases can change GC content.
  • Short sequences or sequences labeled invalid may be genuine biological data (e.g., primers with ambiguous bases) or may indicate file corruption. Manual inspection or comparison to original data sources is required.
  • Aggregate summaries (mean GC across records) are descriptive. They are not a substitute for statistical testing if you want to compare groups or draw biological conclusions.

Troubleshooting: symptoms, likely causes, and fixes

Symptom: The script crashes with UnicodeDecodeError when reading the FASTA.

  • Cause: The input file uses a non-UTF-8 encoding (e.g., Windows-1252) or contains binary content.
  • Fix: Convert the file to UTF-8 or open with the correct encoding. Example: iconv -f WINDOWS-1252 -t UTF-8 input.fasta -o output.fasta. Always inspect binary files (e.g., using file and head commands) before processing.

Symptom: Many sequences are flagged valid=no.

  • Cause: The input FASTA contains characters outside the accepted set (e.g., gap character '-', IUPAC codes like R/Y, or quality scores accidentally included).
  • Fix: Decide what extended characters you want to accept (IUPAC codes: R, Y, S, W, K, M, B, D, H, V) and extend VALID_BASES accordingly. Alternatively, pre-filter or clean sequences to remove gap characters if appropriate for your analysis.

Symptom: Output CSV is missing records or header only.

  • Cause: The file may be empty, contain no header beginning with >, or use malformed record structure. The parser now rejects sequence text before the first header, but an empty file still produces a header-only CSV.
  • Fix: Confirm the FASTA file contains at least one header line (beginning with '>') and sequence lines. Use wc -l and grep '^>' to count headers: grep -c '^>' data/raw/example.fasta.

Symptom: Incorrect GC values compared to external tools.

  • Cause: Differences in normalization: some tools ignore ambiguous bases or gaps when computing fractions, others count them in the denominator.
  • Fix: Make your normalization explicit. If you want GC fraction computed as GC / (A+C+G+T) excluding ambiguous bases, implement that rule rather than using the raw length.

Limitations, version and reference-data caveats, and responsible use

Limitations of this lesson and script:

  • The simple parser is educational and reads records incrementally, though it holds each record sequence in memory. It does not validate FASTA headers against a controlled schema (for example, embedded tabs or spaces), support FASTQ, or provide indexed access. For production work, use a maintained parser such as Biopython SeqIO and validate records against your workflow’s requirements.
  • Validation here is limited to a user-defined alphabet (A, C, G, T, N). Biological sequences sometimes include IUPAC ambiguity codes or gap characters (e.g., '-'). Decide which characters your pipeline should accept and document that choice.
  • Floating-point representation of GC fraction uses simple rounding for readability; for downstream statistical analysis you may want more precision or native numeric types (not formatted strings).

Version and reference-data caveats:

  • Different versions of Biopython, pandas, or Python may change behavior (for example, encoding defaults or CSV dialect handling). Record exact versions with pip freeze or conda list for reproducibility.
  • Reference genome sequences and annotations can change over time. If you are comparing GC content to published values, ensure you are using the same assembly and coordinate convention as the reference.

Responsible use notes:

  • Do not assume computed statistics imply biological meaning without appropriate controls and metadata assessment (sample origin, library preparation, sequencing platform).
  • Be cautious when sharing sequence-derived files that may include sensitive or personally identifying information. Follow institutional policies and data-use agreements.
  • Never run or paste unreviewed code into tools that will give it network access or elevate privileges. The examples here are safe for local file processing and avoid destructive commands (no rm, mv, or system calls that touch other directories).

Next-step checklist

  1. Run the script on your own FASTA files and confirm outputs/sequence_stats.csv contains expected rows and values.
  2. Decide how to treat ambiguous bases and update VALID_BASES and gc_fraction semantics accordingly.
  3. For large inputs, consider a streaming parser such as Biopython SeqIO; this script still holds each individual record sequence in memory.
  4. Write small unit tests for gc_fraction and is_valid_dna using the pytest framework to ensure behavior is stable as you refactor.
  5. Keep the requirements file with the project and document how to recreate the environment. A freeze records package versions, but does not by itself capture Python, operating-system, or system-library details.
