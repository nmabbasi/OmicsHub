Mastering Prompt Engineering for Seurat & Scanpy

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Cursor, Aider

Learning objectives and prerequisites

Learning objectives

  • Learn how to write intent-based prompts (sometimes called "vibe coding") that direct AI to produce reproducible Seurat (R) and Scanpy (Python) analysis scripts.
  • Be able to craft a prompt that contains dataset context, a biological goal, practical constraints, and concrete output checks so an assistant produces runnable code.
  • Understand how to validate and iterate on AI-generated code, inspect outputs, and interpret common results safely.

Prerequisites

  • Basic familiarity with single-cell RNA-seq (scRNA-seq) data concepts: cells, genes, counts, metadata, clustering, and differential expression.
  • Working AI coding environment (e.g., Cursor, Aider, or a code-completion assistant) and local ability to run R (>=4.0) or Python (>=3.8) with Seurat (>=4) or Scanpy (>=1.8) installed.
  • Command-line literacy for running scripts and saving outputs to explicit file paths.

Why intent-based prompting matters for Seurat & Scanpy workflows

AI-assisted coding is powerful, but models are better at producing useful scripts when you describe the biological objective rather than only specifying library functions. Intent-based prompting (a.k.a. "vibe coding") focuses the assistant on what you want to achieve — for example, "identify markers distinguishing cluster 2" — and leaves the assistant to choose reasonable API calls within explicit constraints you provide. This approach reduces brittle, API-specific prompts and helps generate scripts tailored to your dataset, visualization preferences, and reproducibility needs.

In single-cell analysis, small changes in preprocessing (filtering thresholds, normalization, variable-gene selection) materially affect downstream results. Therefore, prompt templates should require the assistant to state assumptions, include checks, and write files that let you re-run analyses deterministically.

Reproducible prompting loop

Before asking an assistant to write code, establish a reproducible loop:

  • Provide a concise dataset summary and file paths.
  • State the biological intent (what question you want answered).
  • Define constraints (statistical test, thresholds, plotting formats, language).
  • Require output files and programmatic checks (dimensions, column names, saved plots).
  • Run the script, inspect outputs, and iterate with small changes.

Example prompt template to give an assistant (replace bracketed tokens):

Goal: Identify marker genes for cluster 2 vs all in a PBMC dataset.
Input: RDS Seurat object at ./data/pbmc_seurat.rds; metadata column 'seurat_clusters' present; 5,000 cells expected.
Constraints: Use R and Seurat >=4; test = MAST; logfc.threshold = 0.25; return genes with p_val_adj < 0.05; save CSV and HTML report.
Output: ./results/cluster2_markers.csv, ./results/cluster2_markers.html, UMAP plot ./results/umap_cluster2.png
Checks: resulting CSV has columns gene, avg_log2FC, p_val_adj; at least 10 rows; UMAP PNG exists.
Ask: show all package imports and version prints; explain any assumptions and cite Seurat functions used.

Reproducible, sequential workflow examples

Below are two sequential workflows: one Scanpy (Python) QC → clustering → markers example, and one Seurat (R) marker extraction example. Each step lists required input files and what the command produces.

Scanpy workflow (Python)

Files you should have:

  • Input AnnData file: ./data/adata.h5ad (AnnData object with .X counts or normalized values, .obs metadata including 'n_genes', 'pct_counts_mt' if present)
  • Output directory: ./results/ (create if missing)
# Save this as ./scripts/scanpy_quick_workflow.py
import scanpy as sc
import matplotlib.pyplot as plt
import anndata
import os
import sys

# Input/outputs (change paths as needed)
adata_path = "./data/adata.h5ad"
outdir = "./results"
os.makedirs(outdir, exist_ok=True)

# Load and print basic info
adata = sc.read_h5ad(adata_path)
print("AnnData shape:", adata.shape)
print("obs columns:", list(adata.obs.columns)[:20])

# Calculate QC metrics (adds n_genes_by_counts, total_counts, pct_counts_mt if mt genes detected)
adata.var['mt'] = [name.upper().startswith('MT-') for name in adata.var_names]
sc.pp.calculate_qc_metrics(adata, qc_vars=['mt'], inplace=True)

# Plot QC violin (before filtering)
sc.pl.violin(adata, ['n_genes_by_counts', 'total_counts', 'pct_counts_mt'],
             jitter=0.4, multi_panel=True, show=False)
plt.savefig(os.path.join(outdir, "qc_violins_before.png"))
plt.clf()

# Filters: example thresholds (state these in your prompt)
min_genes = 200
max_genes = 8000
max_mt_pct = 5.0

sc.pp.filter_cells(adata, min_genes=min_genes)
sc.pp.filter_cells(adata, max_genes=max_genes)
adata = adata[adata.obs['pct_counts_mt'] < max_mt_pct, :]

sc.pp.filter_genes(adata, min_cells=3)

# Normalization, variable genes, PCA, neighbors, UMAP, clustering
sc.pp.normalize_total(adata, target_sum=1e4)
sc.pp.log1p(adata)
sc.pp.highly_variable_genes(adata, n_top_genes=2000, subset=True)
sc.pp.scale(adata, max_value=10)
sc.tl.pca(adata, svd_solver='arpack')
sc.pp.neighbors(adata, n_neighbors=10, n_pcs=40)
sc.tl.umap(adata)
sc.tl.leiden(adata, key_added='leiden_r10')

# Save UMAP plot with clusters
sc.pl.umap(adata, color='leiden_r10', save="_leiden_r10.png", show=False)  # saves to matplotlib default dir; we'll also save explicitly
plt.savefig(os.path.join(outdir, "umap_leiden_r10.png"))
plt.clf()

# Differential expression: rank genes for cluster '0' vs rest using t-test overestim_var
sc.tl.rank_genes_groups(adata, 'leiden_r10', method='t-test_overestim_var')
# Convert to a readable table and save
import pandas as pd
r = adata.uns['rank_genes_groups']
groups = r['names'].dtype.names
records = []
for group in groups:
    names = r['names'][group].tolist()
    pvals_adj = r['pvals_adj'][group].tolist()
    logfoldchanges = r.get('logfoldchanges', {}).get(group, [None]*len(names))
    for name, p, lf in zip(names, pvals_adj, logfoldchanges):
        records.append({'group': group, 'gene': name, 'p_val_adj': p, 'logfoldchange': lf})
df = pd.DataFrame.from_records(records)
df.to_csv(os.path.join(outdir, "scanpy_rank_genes.csv"), index=False)

# Save AnnData with processed fields
adata.write_h5ad(os.path.join(outdir, "adata_processed.h5ad"))
print("Wrote results to", outdir)

What each command produces:

  • ./results/qc_violins_before.png — violin plots of QC metrics before filtering.
  • Filtered in-memory AnnData (then saved): ./results/adata_processed.h5ad
  • UMAP images in ./results/umap_leiden_r10.png and in Scanpy's plotting default location.
  • Cluster ranking table: ./results/scanpy_rank_genes.csv

Seurat workflow (R)

Files you should have:

  • Input Seurat object: ./data/seurat_obj.rds (serialized Seurat object from saveRDS)
  • Output directory: ./results/
# Save this as ./scripts/seurat_marker_workflow.R
library(Seurat)
library(ggplot2)
library(MAST) # used for statistical test
library(dplyr)

# Paths
infile <- "./data/seurat_obj.rds"
outdir <- "./results"
dir.create(outdir, showWarnings = FALSE, recursive = TRUE)

# Load object and report
seurat_obj <- readRDS(infile)
cat("Seurat object dimensions (cells x genes):", dim(seurat_obj), "\n")
cat("Available metadata columns:", paste(colnames(seurat_obj@meta.data), collapse=", "), "\n")

# Run UMAP and clustering if not present (safe checks)
if (!"umap" %in% names(seurat_obj@reductions)) {
  seurat_obj <- NormalizeData(seurat_obj, verbose = FALSE)
  seurat_obj <- FindVariableFeatures(seurat_obj, selection.method = "vst", nfeatures = 2000, verbose = FALSE)
  seurat_obj <- ScaleData(seurat_obj, verbose = FALSE)
  seurat_obj <- RunPCA(seurat_obj, verbose = FALSE)
  seurat_obj <- FindNeighbors(seurat_obj, dims = 1:20, verbose = FALSE)
  seurat_obj <- FindClusters(seurat_obj, resolution = 0.5, verbose = FALSE)
  seurat_obj <- RunUMAP(seurat_obj, dims = 1:20, verbose = FALSE)
}

# Save UMAP plot (colored by clusters)
p <- DimPlot(seurat_obj, reduction = "umap", group.by = "seurat_clusters") + ggtitle("UMAP by seurat_clusters")
ggsave(filename = file.path(outdir, "umap_seurat_clusters.png"), plot = p, width = 6, height = 5)

# Differential expression: cluster 3 vs all using MAST
cluster_of_interest <- "3"
markers <- FindMarkers(seurat_obj,
                       ident.1 = cluster_of_interest,
                       test.use = "MAST",
                       logfc.threshold = 0.5,
                       min.pct = 0.1)

# Filter by adjusted p-value
significant_markers <- markers %>% rownames_to_column(var = "gene") %>% filter(p_val_adj < 0.05)
write.csv(significant_markers, file = file.path(outdir, paste0("cluster", cluster_of_interest, "_markers.csv")), row.names = FALSE)

# Save processed seurat object
saveRDS(seurat_obj, file = file.path(outdir, "seurat_obj_processed.rds"))
message("Wrote results to ", outdir)

What each command produces:

  • ./results/umap_seurat_clusters.png — UMAP colored by 'seurat_clusters'.
  • ./results/cluster3_markers.csv — differential expression results for cluster 3 filtered by adjusted p-value.
  • ./results/seurat_obj_processed.rds — Seurat object with any computed reductions and cluster assignments.

Output inspection and interpretation

After running a generated script, inspect outputs with these checks and interpret them cautiously.

  • QC plots Check whether the distributions of gene counts, total counts, and mitochondrial percentage look sensible for your sample type. Very high mitochondrial percentages often indicate damaged cells, but thresholds are dataset-specific — 5% is typical for fresh PBMCs and not a universal rule.
  • Filtering results: Note the number of cells and genes retained. If you lose an unexpectedly large fraction (>30–50%) of cells, revisit thresholds and confirm metadata quality (e.g., correct gene name capitalization for mitochondrial genes).
  • Clustering and UMAP: UMAP and cluster labels are descriptive summaries. A clear separation of known cell-type markers across clusters increases confidence, but cluster boundaries can change with preprocessing or neighbor parameter changes.
  • Differential expression tables: Look for columns such as gene name, log fold-change, p-value, and adjusted p-value. Significant adjusted p-values indicate statistical difference under the chosen test and multiple-testing correction, not biological causality.

What plausible results mean — and what they don't:

  • Marker genes with strong log fold-change and low p_adj suggest genes enriched in that cluster under analysis choices (normalization, test). They do not by themselves validate cell identity — you should cross-reference with known marker gene sets and, if possible, orthogonal assays.
  • Absence of significant markers could mean clusters are not biologically distinct, the cluster is too small, or the test lacks power (low cell counts or high variability).

Troubleshooting: symptoms, likely causes, and fixes

  • Symptom: Script errors on loading files (FileNotFoundError / cannot open file).
    Cause: Wrong relative path or missing files.
    Fix: Verify file existence with ls or dir; use absolute paths or check working directory in script (e.g., print getwd() in R / os.getcwd() in Python).
  • Symptom: QC metrics like pct_counts_mt are all zeros or missing.
    Cause: Mitochondrial gene names do not match detection pattern (e.g., 'MT-' vs 'mt-').
    Fix: Inspect var/feature names and adjust the pattern detection (toupper/lower) or provide a list of mitochondrial gene symbols.
  • Symptom: Very few or no variable genes selected.
    Cause: Raw counts not provided or log-normalized values present; params for highly variable gene selection may be inappropriate.
    Fix: Ensure you run appropriate normalization steps before HVG selection or set selection.method/nfeatures to reasonable values.
  • Symptom: DE test fails with NA p-values or warnings about zeros.
    Cause: Low-expression genes or small cluster sizes make statistical tests unstable; some tests require non-zero variance.
    Fix: Filter genes (min.pct, min.cells), or switch to a test more appropriate for small groups (e.g., Wilcoxon, or aggregate pseudo-bulk approaches).
  • Symptom: UMAP layout looks collapsed or clusters overlap completely.
    Cause: PCA not computed or insufficient PCs used; scaling issues.
    Fix: Recompute PCA, increase n_pcs, or re-run neighbor graph construction; check for batch effects that may need correction.

Limitations, version and reference-data caveats, and responsible use

Limitations and practical caveats:

  • AI-generated code is only as good as the prompt and the training distribution of the model. Always read, run, and vet generated scripts before applying them to sensitive data.
  • Different versions of Seurat, Scanpy, and dependent packages change function names, defaults, and returned data structures. Always print package versions at the top of scripts and specify which versions you expect if you share prompts or code.
  • Single-cell pipelines are sensitive to small preprocessing decisions. Results from exploratory analysis are hypothesis-generating, not confirmatory. Biological validation is required for any claims.
  • Public gene name conventions (e.g., capitalization in mitochondrial genes) and reference annotations differ by organism and build. Do not assume gene naming conventions without checking your dataset.

Responsible-use notes:

  • Never execute code that performs destructive file operations (rm, unlink) without explicit manual review. If an assistant proposes file deletion, decline or require safe-guards (e.g., move to backup directories instead).
  • Check network calls in generated code. If code downloads reference data, ensure the source URL is trustworthy and that you are allowed to access it in your environment.
  • Be careful with sensitive human data: ensure proper ethics approvals and data governance before uploading or processing protected data with external services or cloud-based AI assistants.

Concise next-step checklist

  1. Create an examples folder with a small toy dataset (example AnnData or Seurat object) to validate prompts and iterations.
  2. Use the prompt template at the top of this tutorial to request an initial script from your AI assistant. Require that the assistant prints package versions and lists its assumptions.
  3. Run the generated script locally, inspect the outputs listed in the prompt, and record failures or warnings.
  4. Iterate with small, targeted prompts (e.g., "change logfc.threshold to 0.25" or "use Wilcoxon instead of MAST") and rerun checks.
  5. Once stable, save the final prompt and script together in version control (e.g., ./prompts/cluster2_prompt.txt and ./scripts/cluster2_analysis.R).
