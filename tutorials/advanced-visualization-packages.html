Visualizing Single-Cell Data with R Packages

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Learning pathPrevious prerequisiteSingle-Cell RNA-seq Downstream AnalysisBrowseAll tutorialsSuggested nextReturn to single-cell choices

Default Seurat plots work well for quick exploration, but turning them into clear publication figures requires matching each plot type to its data layer, using colour-vision-safe scales, and keeping legends comparable across panels. In about 30 minutes, you will run a self-contained Seurat and ggplot2 script that produces four core single-cell figures, then adapt templates for SCpubr, dittoSeq, and patchwork to your own QC-reviewed object.

Format: Executable core example plus advanced templates. The core script runs from the repository root on a 36-feature by 48-cell synthetic count and metadata fixture using only Seurat and ggplot2; those synthetic plots illustrate code mechanics and are not biological observations. The later SCpubr and dittoSeq blocks are adaptation templates for your own object and were not executed in this revision.

What you will learn and prerequisites

By the end of this lesson, you will be able to:

  • Match categorical embeddings, continuous expression maps, multi-gene marker panels, and donor composition bars to the right R plotting function and assay layer.
  • Control colour scales, quantile or numeric cutoffs, factor ordering, and rasterization so dense or skewed single-cell datasets stay readable.
  • Assemble compatible ggplot objects with patchwork, export grid-based dittoSeq heatmaps cleanly, and diagnose common Seurat v5 plotting errors.

Prerequisites:

  • Completed upstream scRNA-seq processing (cell/gene QC, normalization, PCA, clustering, and UMAP) as covered in Single-Cell RNA-seq Downstream Analysis.
  • For the runnable core: R with Seurat and ggplot2 (tested on R 4.3.3, Seurat 5.0.1, SeuratObject 5.0.1, ggplot2 3.4.4, and uwot 0.1.16).
  • For the optional wrapper templates: your own QC-reviewed Seurat object at data/seurat_obj.rds containing metadata columns (cell_type, condition, patient_id) and a umap reduction, plus SCpubr, dittoSeq, and patchwork.

1. Choosing the right plot type and package

Every single-cell figure answers one visual question: where cell states sit in low-dimensional space, where one gene is active, which genes distinguish clusters, or how cell-type shares vary across donors. Using the wrong visual encoding hides real biology or creates false patterns. For example, plotting raw UMI counts on a UMAP reflects sequencing depth rather than transcriptional identity, whereas per-gene autoscaling makes a noisy background gene look as bright as a canonical lineage marker.

Before writing plotting code, keep four terms straight:

  • Assay layer (data vs. counts): Seurat v5 stores raw integer UMI counts in the counts layer and log-normalized counts in the data layer. Feature maps, dot plots, and heatmaps should read normalized data unless you are explicitly auditing UMI depth.
  • Cutoff clipping (min.cutoff / max.cutoff): Clamping outliers at a high percentile (such as the 95th percentile) prevents a handful of ultra-high cells from compressing the rest of the colour gradient into near-zero grey.
  • Row z-score vs. max-scaling: Centering and scaling each gene across groups highlights relative cluster specificity, while erasing differences in absolute expression magnitude between lowly and highly expressed genes.
  • Compositional closure: Within any sample, cell-type percentages must sum to 100%. An expansion in infiltrating neutrophils shrinks resident T-cell percentages even when absolute T-cell counts are unchanged.

2. Verified core route: Seurat and ggplot2 end-to-end

3. Optional wrapper templates (not executed in this revision)

Once your own QC-reviewed Seurat object is ready at data/seurat_obj.rds, you can adapt the templates below using SCpubr, dittoSeq, and patchwork. The examples use canonical human PBMC markers (CD3D for T cells, NKG7 for NK/cytotoxic lymphocytes, MS4A1 for B cells, LYZ for classical monocytes/DCs, FCGR3A for CD16+ monocytes, and PPBP for megakaryocytes). These wrapper templates were not executed in this revision; verify package versions and your object's metadata columns, assay layers, and feature names before running them.

3.1 Install compatible packages in an isolated library

Install CRAN packages with install.packages() and Bioconductor packages (such as dittoSeq) with BiocManager::install() so Bioconductor matches your R version. For example, Bioconductor Release 3.24 targets R 4.6.0 or higher; on an existing project with an older R version, keep your project's established lockfile rather than upgrading packages mid-analysis.

# Run in R inside your project environment
install.packages(c("Seurat", "SCpubr", "ggplot2", "patchwork"))
if (!requireNamespace("BiocManager", quietly = TRUE)) install.packages("BiocManager")
BiocManager::install("dittoSeq")

stopifnot(all(vapply(c("Seurat", "SCpubr", "ggplot2", "patchwork", "dittoSeq"),
  requireNamespace, logical(1), quietly = TRUE)))
dir.create("results", showWarnings = FALSE)
writeLines(capture.output(sessionInfo()), "results/session_info.txt")

3.2 Load and validate your Seurat object

Fail fast if required metadata columns or reductions are missing. In Seurat v5, also check whether sample layers are still split inside the RNA assay; wrapper functions such as dittoHeatmap() expect unified counts and data layers, so run SeuratObject::JoinLayers() after integration if multiple data.* layers appear.

# Input: data/seurat_obj.rds with 'cell_type', 'condition', 'patient_id', and 'umap'
library(Seurat)
library(SCpubr)
library(dittoSeq)
library(ggplot2)

seurat_obj <- readRDS("data/seurat_obj.rds")
stopifnot(inherits(seurat_obj, "Seurat"))

required_meta <- c("cell_type", "condition", "patient_id")
missing_meta <- setdiff(required_meta, colnames(seurat_obj[[]]))
if (length(missing_meta)) stop("Missing metadata: ", paste(missing_meta, collapse = ", "))
if (!("umap" %in% SeuratObject::Reductions(seurat_obj))) stop("UMAP reduction not found")

# Seurat v5 check: if layers are split by sample, join them before downstream plotting
print(SeuratObject::Layers(seurat_obj[["RNA"]]))
# seurat_obj <- SeuratObject::JoinLayers(seurat_obj)

3.3 Standardized categorical UMAP with SCpubr

Default scatter plots draw factor levels in order, so the last cluster plotted paints over earlier cells at cluster boundaries; SCpubr::do_DimPlot() avoids this by defaulting to shuffle = TRUE, dropping redundant axis ticks on UMAPs, and formatting legends cleanly.

dir.create("results", showWarnings = FALSE)

p_umap <- SCpubr::do_DimPlot(
  sample = seurat_obj,
  reduction = "umap",
  group.by = "cell_type",
  shuffle = TRUE,             # avoid factor-order overplotting
  label = TRUE,
  repel = TRUE,               # push overlapping cluster labels apart
  font.size = 12,
  legend.position = "right"
)

ggsave("results/umap_celltype.png", p_umap, width = 8, height = 6, dpi = 300)
ggsave("results/umap_celltype.pdf", p_umap, width = 8, height = 6)

Check: For datasets above ~50,000 cells, pass raster = TRUE so vector PDFs stay small and quick to open in Illustrator or Inkscape. If repel = TRUE still leaves crowded labels on tiny subclusters, omit on-plot labels (label = FALSE) and rely on a well-ordered legend.

3.4 Feature expression map with explicit scale bounds

Single-cell expression counts often have a long right tail: if two cells have normalized expression of 6.5 while most expressing cells sit between 1.5 and 3.0, autoscaling compresses visual contrast across the rest of the cluster. Pairing a perceptually uniform sequential palette (use_viridis = TRUE, Crameri et al., 2020) with explicit bounds preserves that contrast.

feature <- "LYZ"  # classical monocyte and dendritic-cell marker
stopifnot(feature %in% rownames(seurat_obj))

# Compute a numeric 95th-percentile cutoff (SCpubr expects numeric cutoffs, unlike Seurat's "q95")
expr_vals <- Seurat::FetchData(seurat_obj, vars = feature, layer = "data")[, 1]
q95_cutoff <- unname(stats::quantile(expr_vals, probs = 0.95))
# Guard sparse markers (<5% expressing cells, such as PPBP) where q95 equals 0
if (q95_cutoff <= 0) q95_cutoff <- max(expr_vals)

p_feat <- SCpubr::do_FeaturePlot(
  sample = seurat_obj,
  features = feature,
  reduction = "umap",
  use_viridis = TRUE,
  viridis.palette = "D",
  order = TRUE,               # draw high-expressing cells on top
  min.cutoff = 0,
  max.cutoff = q95_cutoff,    # clamp top 5% to preserve contrast; or use scale.limits = c(0, 4)
  pt.size = 0.5
)

ggsave(sprintf("results/feature_%s.png", feature), p_feat, width = 6, height = 5, dpi = 300)

Seurat vs. SCpubr cutoff trap: Seurat::FeaturePlot() accepts quantile strings such as max.cutoff = "q95", whereas SCpubr::do_FeaturePlot() expects numeric vectors for min.cutoff and max.cutoff (which clip cell values) or scale.limits = c(low, high) (which fixes legend limits across panels without altering underlying values). Always state in the figure caption whether values were clipped.

3.5 Marker specificity dot plot with Seurat and viridis

Seurat::DotPlot() encodes two distinct quantities at once: dot size shows the fraction of cells in a group with nonzero expression (controlled by dot.min and dot.scale), while dot colour shows the z-scored average expression across groups (scale = TRUE by default, clamped to [-2.5, 2.5]). Ordering both cell_type factor levels and marker genes biologically turns a scrambled grid into a clean diagonal block.

# Order cell types and canonical PBMC markers by lineage for a diagonal pattern
lineage_order <- c("CD4+ T cell", "Cytotoxic T", "NK cell",
                   "B cell", "CD14+ mono", "CD16+ mono",
                   "Dendritic cell", "Megakaryocyte")
observed_levels <- unique(as.character(seurat_obj$cell_type))
present_levels <- c(intersect(lineage_order, observed_levels),
                    setdiff(observed_levels, lineage_order))
seurat_obj$cell_type <- factor(seurat_obj$cell_type, levels = present_levels)

pbmc_markers <- c("CD3D", "NKG7", "MS4A1", "LYZ", "FCGR3A", "PPBP")
pbmc_markers <- intersect(pbmc_markers, rownames(seurat_obj))

p_dot <- Seurat::DotPlot(
  object = seurat_obj,
  features = pbmc_markers,
  group.by = "cell_type",
  dot.scale = 6
) +
  ggplot2::scale_color_viridis_c(option = "D") +
  Seurat::RotatedAxis()

ggsave("results/dotplot_top_markers.pdf", p_dot, width = 9, height = 4)

3.6 Donor-level composition bar plot with dittoSeq

dittoSeq::dittoBarPlot() defaults to an Okabe-Ito-inspired categorical palette (dittoColors(); Bunis et al., 2020) and returns a standard ggplot object. Group bars by patient_id (ordered by clinical arm or response) rather than pooling all cells by condition, so readers can see donor-to-donor variation directly. Note that the theme argument in dittoBarPlot() is theme (not plot.theme).

# Order patient_id by condition so donor variability within arms is immediately visible
sample_order <- unique(seurat_obj@meta.data[order(seurat_obj$condition, seurat_obj$patient_id), "patient_id"])
seurat_obj$patient_id <- factor(seurat_obj$patient_id, levels = sample_order)

p_comp <- dittoSeq::dittoBarPlot(
  object = seurat_obj,
  var = "cell_type",
  group.by = "patient_id",
  scale = "percent",          # use "count" to inspect raw cell recovery per donor
  theme = ggplot2::theme_bw(),
  legend.title = "Cell type"
)

ggsave("results/composition_by_patient.png", p_comp, width = 9, height = 4, dpi = 300)

3.7 Multi-annotation marker heatmap with dittoSeq

dittoSeq::dittoHeatmap() wraps pheatmap so you can stack multiple metadata annotation tracks (annot.by = c("cell_type", "condition")) above your marker genes. Pay close attention to scaling: when scaled.to.max = FALSE (the default), pheatmap defaults to scale = "row" (per-gene z-scoring), which emphasizes relative contrast while hiding absolute expression. Setting scaled.to.max = TRUE scales each gene from 0 to 1 relative to its own maximum and automatically forces scale = "none"; pass scale = "none", scaled.to.max = FALSE to inspect unscaled log-normalized values.

p_heat <- dittoSeq::dittoHeatmap(
  object = seurat_obj,
  genes = pbmc_markers,
  annot.by = c("cell_type", "condition"),
  slot = "data",              # log-normalized layer
  scale = "row",              # per-gene z-score; set "none" for unscaled log-normalized values
  scaled.to.max = FALSE,
  show_colnames = FALSE
)

# dittoHeatmap returns a pheatmap list; pass $gtable to ggsave (or pass filename= directly)
ggsave("results/heatmap_top_markers.pdf", plot = p_heat$gtable, width = 8, height = 6)

3.8 Multi-panel assembly with patchwork

patchwork merges legends cleanly across compatible ggplot panels using plot_layout(guides = "collect") and adds publication panel labels with plot_annotation(tag_levels = "A"). Because p_heat is a pheatmap gtable rather than a ggplot, either export it separately or wrap p_heat$gtable inside patchwork::wrap_elements().

library(patchwork)

stopifnot(all(vapply(list(p_umap, p_feat, p_dot), inherits, logical(1), "ggplot")))

combined <- (p_umap + p_feat) / p_dot +
  plot_layout(guides = "collect", heights = c(1.2, 1)) +
  plot_annotation(tag_levels = "A")

ggsave("results/panel_figure.pdf", combined, width = 12, height = 10)
# Optional: combine a ggplot with p_heat$gtable via patchwork::wrap_elements(full = p_heat$gtable)

4. Reading the figures and checking for traps

Before submitting a figure, run this four-point visual audit:

  • UMAP layout: Do clusters match annotated cell_type boundaries, or do you see a bridge of intermediate cells expressing mutually exclusive markers (such as CD3D and MS4A1 together, a classic doublet artifact) or clusters dominated by a single donor (batch effect)?
  • Feature maps: Is signal restricted to the expected lineage, or does a ubiquitous low haze appear everywhere (ambient RNA spillover from abundant transcripts such as LYZ or HBB)?
  • Dot plots and heatmaps: Confirm dot size means detection prevalence, not expression magnitude, and record whether colour shows row z-scores, 0-1 max-scaling, or unscaled log-normalized expression.
  • Composition charts: Always report donor counts (n samples per condition) and cell counts per group, especially for rare populations such as plasmacytoid DCs or megakaryocytes.

5. Common errors and how to fix them

Practice check: spot two figure traps

A collaborator sends two draft panels from a 4-sample PBMC study (2 control donors, 2 treated donors): (1) a FeaturePlot of LYZ where monocytes are bright purple and nearly every T-cell cluster is pale lavender, and (2) a stacked dittoBarPlot showing B cells drop from 24% in Control_1 to 11% in Treated_1, concluding that "LYZ is expressed across T cells and treatment depleted B cells." Identify two plotting or interpretive mistakes before these panels go into a figure.

Check your diagnosis

1. Unchecked ambient spillover or missing cutoff / colour baseline: High-abundance myeloid transcripts like LYZ frequently contaminate T-cell droplets as ambient RNA, and a pale lavender zero/low baseline without checking DotPlot prevalence or setting min.cutoff/max.cutoff makes 1-2 background UMIs look like genuine lineage expression. Verify fraction detected per cluster with DotPlot() before claiming expression.

2. Compositional closure and sample size: Stacked percentages are constrained to sum to 100%, so an expansion of monocytes or neutrophils in Treated_1 mechanically lowers the B-cell percentage even if absolute B-cell numbers did not fall. Moreover, with only n = 2 donors per arm, descriptive bar plots cannot establish a statistically significant compositional shift; test multi-donor counts formally with propeller (speckle) or scCODA once enough biological replicates are available.

Scope, statistical boundaries, and next steps

  • Visualization is not hypothesis testing: For condition-level differential expression within a cell type, aggregate raw UMI counts per donor and cell type into pseudobulks and test with DESeq2 or edgeR rather than running cell-level Wilcoxon tests on pooled cells (Squair et al., 2021; see Differential Expression). For donor-level cell-type abundance shifts, use compositional or neighborhood models such as propeller (speckle; Phipson et al., 2022), scCODA, or miloR.
  • Document transformations in every caption: Always record the dataset, assay and layer (for example, RNA log-normalized data), any cutoff clipping or row z-scoring, and the number of biological donors and cells per group.
  • Reproducibility: Save sessionInfo() alongside exported figures so package defaults remain traceable.

Continue on The Omics Hub: review general colour and layout rules in Data Visualization Fundamentals, check batch structure in Experimental Design and Batch Effects, or move to downstream testing in Single-Cell RNA-seq Downstream Analysis and Transcriptomics Differential Expression.

Author's lab note: Whenever a single-cell feature plot looks misleadingly bright across every cluster, the culprit is almost always autoscaling without an explicit cutoff (max.cutoff = "q95") or misreading DotPlot colour scaling (scale = TRUE scales average expression for colour, while dot size reflects detection percentage). Fixing expression limits globally across panels and exporting resolution-independent vector PDF/SVG files (or 300 DPI raster PNG/TIFF when rasterizing dense point clouds) stops figures from needing last-minute redraws before journal submission.
