Single-Cell Integration: Harmony, RPCA & CCA

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives & prerequisites

By the end of this lesson you will be able to:

  • Understand the conceptual differences between Harmony, RPCA (Reciprocal PCA), and CCA (Canonical Correlation Analysis) for single-cell integration.
  • Run a reproducible comparison of Harmony and Seurat RPCA integration on two PBMC (peripheral blood mononuclear cell) datasets using Seurat v5 and Harmony.
  • Compute and interpret quantitative diagnostics (iLISI and cLISI) to evaluate batch mixing versus biological conservation.

Prerequisites

  • Familiarity with basic single-cell RNA-seq (scRNA-seq) concepts (normalization, HVG selection, PCA, UMAP). If needed, complete the "scRNA-seq Basics" tutorial first.
  • R 4.3+ with Bioconductor/CRAN packages: Seurat v5, harmony, lisi (or the lisi implementation you prefer), patchwork (optional for plotting). Example tested environments: R 4.3.x; this page does not promise exact reproducibility across all minor versions.
  • Two prepared Seurat object files: pbmc3k.rds and pbmc10k.rds (these are example filenames—replace with your datasets). Each should be an unintegrated Seurat object containing raw counts in the "RNA" assay and a sample-level metadata field can be added.

Why integration matters (biological and computational context)

When cells are profiled across different experimental batches (different chemistries, days, or donors), technical variability can dominate the signal. Integration algorithms transform cell embeddings so that cells with the same biological identity from different batches co-locate, enabling joint downstream analysis.

However, integration is fundamentally a mathematical transformation of your data. If biological variation aligns with batch structure (for example, a cell type present in only one batch), aggressive integration may erase that biology (overcorrection). Different algorithms make different assumptions and trade sensitivity to batch vs. preservation of biology. This tutorial contrasts three commonly used approaches:

  • Harmony — iterative correction in PCA space; generally conservative and scalable.
  • RPCA (Reciprocal PCA) — Seurat's reciprocal PCA-based integration that aligns PCA subspaces from pairwise anchors.
  • CCA (Canonical Correlation Analysis) — finds correlated components across datasets; can be more aggressive and is historically popular in Seurat.

Reproducible workflow (R)

The following workflow is sequential and reproducible. Adjust file paths as needed. All commands assume you start from two Seurat objects saved as RDS files: pbmc3k.rds and pbmc10k.rds. Expected outputs are explicitly stated after each step.

# 0. Load libraries
library(Seurat)       # v5+
library(harmony)      # Harmony integration
library(lisi)         # compute_lisi() for LISI metrics
library(patchwork)    # optional, for combining plots

Files to have in your working directory:

  • pbmc3k.rds — Seurat object (raw counts in DefaultAssay "RNA")
  • pbmc10k.rds — Seurat object (raw counts in DefaultAssay "RNA")
# 1. Read and annotate batch metadata
pbmc3k <- readRDS("pbmc3k.rds")   # input: Seurat object file
pbmc3k$batch <- "v1_3k"           # adds metadata column "batch"

pbmc10k <- readRDS("pbmc10k.rds")
pbmc10k$batch <- "v3_10k"

# Merge objects (creates a merged Seurat object)
merged <- merge(pbmc3k, y = pbmc10k, add.cell.ids = c("3k", "10k"))
# output: Seurat object 'merged' with cells from both samples and metadata field 'batch'

Important: keep copies of the original objects if you need to revert. Merging does not modify the original RDS files.

# 2. Standard preprocessing (same pipeline for all methods)
DefaultAssay(merged) <- "RNA"
merged <- NormalizeData(merged, verbose = FALSE)
merged <- FindVariableFeatures(merged, selection.method = "vst", nfeatures = 3000, verbose = FALSE)
merged <- ScaleData(merged, verbose = FALSE)
merged <- RunPCA(merged, npcs = 50, verbose = FALSE)
# output: PCA reduction stored in merged[["pca"]]

Produce an unintegrated baseline UMAP for reference:

# Baseline: UMAP on raw PCA
merged <- RunUMAP(merged, reduction = "pca", dims = 1:30, reduction.name = "umap.pca")
# output: UMAP coordinates stored in merged[["umap.pca"]]

# Example plotting (interactive environment)
DimPlot(merged, reduction = "umap.pca", group.by = "batch")

Interpretation: If batches already co-mingle in this plot, integration may not be necessary. The UMAP is a visualization of the PCA embedding and is not a formal test of integration quality.

Harmony integration

# 3a. Run Harmony (operates on PCA embeddings)
merged_harmony <- merged                       # copy to keep original merged intact
merged_harmony <- RunHarmony(merged_harmony, group.by.vars = "batch", reduction = "pca", dims.use = 1:30)
# output: Harmony reduction stored in merged_harmony[["harmony"]]

# Build UMAP from Harmony
merged_harmony <- RunUMAP(merged_harmony, reduction = "harmony", dims = 1:30, reduction.name = "umap.harmony")
# output: UMAP coords in merged_harmony[["umap.harmony"]]

Notes: Harmony has parameters such as theta (diversity clustering penalty). Higher theta forces stronger mixing; default values are often sensible but test sensitivity.

Seurat RPCA integration

# 3b. Run Seurat RPCA integration workflow (anchors-based)
# Split back into a list of Seurat objects by batch for anchor-based methods
obj_list <- SplitObject(merged, split.by = "batch")

# Standardize preprocessing for each object (these commands are idempotent if already done)
for (i in seq_along(obj_list)) {
  DefaultAssay(obj_list[[i]]) <- "RNA"
  obj_list[[i]] <- NormalizeData(obj_list[[i]], verbose = FALSE)
  obj_list[[i]] <- FindVariableFeatures(obj_list[[i]], selection.method = "vst", nfeatures = 3000, verbose = FALSE)
  obj_list[[i]] <- ScaleData(obj_list[[i]], verbose = FALSE)
  obj_list[[i]] <- RunPCA(obj_list[[i]], npcs = 50, verbose = FALSE)
}

# Find integration anchors using RPCA
anchors_rpca <- FindIntegrationAnchors(object.list = obj_list, anchor.features = 3000, reduction = "rpca", dims = 1:50)
# output: anchors object 'anchors_rpca'

# Integrate
merged_rpca <- IntegrateData(anchorset = anchors_rpca, dims = 1:50)
# output: Seurat object 'merged_rpca' with "integrated" assay
DefaultAssay(merged_rpca) <- "integrated"
merged_rpca <- ScaleData(merged_rpca, verbose = FALSE)
merged_rpca <- RunPCA(merged_rpca, npcs = 50, verbose = FALSE)
merged_rpca <- RunUMAP(merged_rpca, reduction = "pca", dims = 1:30, reduction.name = "umap.rpca")
# output: UMAP coords in merged_rpca[["umap.rpca"]]

Optional: Seurat CCA integration

If you want to compare with CCA-based integration, substitute reduction = "rpca" with reduction = "cca" in FindIntegrationAnchors (CCA may require additional tuning and larger computational resources).

Quantitative diagnostics: LISI (Local Inverse Simpson's Index)

Visual inspection is necessary but insufficient. Compute iLISI (batch mixing) and cLISI (cell-type mixing/purity) to quantify performance.

# Prepare a data.frame of embeddings and metadata for compute_lisi()
# Example for Harmony result
emb_harmony <- Embeddings(merged_harmony, "harmony")[, 1:30]
meta_harmony <- merged_harmony@meta.data
df_harmony <- as.data.frame(emb_harmony)
df_harmony$batch <- meta_harmony$batch
# If you have cell type labels in meta (e.g., "celltype"), include them similarly.

# Compute LISI: columns used for LISI = embedding dims, meta columns to evaluate = "batch" and "celltype"
# compute_lisi expects a data.frame with embeddings and metadata columns
lisi_harmony <- compute_lisi(df_harmony, df_harmony[, c("batch")], perplexity = 30)
# output: matrix with iLISI per cell for 'batch'; summarize with median/mean

# Repeat for RPCA-integrated object
emb_rpca <- Embeddings(merged_rpca, "pca")[, 1:30]
df_rpca <- as.data.frame(emb_rpca)
df_rpca$batch <- merged_rpca@meta.data$batch
lisi_rpca <- compute_lisi(df_rpca, df_rpca[, c("batch")], perplexity = 30)

Interpretation of LISI values for two batches: iLISI ≈ 1 means unmixed (cells only see their own batch locally); iLISI ≈ 2 means perfect mixing across two batches. For cLISI (computed against cell type labels), values near 1 indicate local purity of the same annotated cell type and higher values indicate local mixing of cell types (bad if you expect purity).

Output inspection and interpretation

After generating UMAPs and LISI scores, inspect results along three dimensions:

  1. Batch mixing (visual): Are batch labels distributed across clusters, or is there clear separation driven by batch? If clusters contain a mix of batches, that suggests mixing.
  2. Batch mixing (quantitative): Median iLISI across cells — higher is better for mixing, but interpret relative to baseline (unintegrated) and biological expectations.
  3. Biological conservation: Compute cLISI using known cell type labels (if available) or inspect expression of canonical marker genes. If cLISI increases substantially after integration (local neighborhoods now mix multiple annotated cell types), the method may be overcorrecting.

What a plausible result means:

  • High iLISI and unchanged/low cLISI: likely successful integration — technical batch is reduced while cell type separation is preserved.
  • High iLISI and high cLISI: batch removed but biological identity blurred — possible overcorrection.
  • Low iLISI: integration failed to mix batches — maybe undercorrection or incompatible datasets.

What these diagnostics do NOT prove:

  • LISI does not prove absence of subtle distortions in gene expression values or marker gene relationships.
  • Good mixing on UMAP or LISI does not guarantee preservation of rare or continuous biological trajectories; further downstream checks (marker expression, differential testing using unadjusted data) are needed.

Troubleshooting: symptoms, likely causes, and fixes

  • Symptom: Integration produces perfectly overlapped clusters across batches but marker genes for expected cell types are lost (clusters no longer express markers).
    Likely cause: Overcorrection, possibly due to inappropriate anchor selection or overly aggressive parameters.
    Fix: Reduce integration strength: for Harmony, lower theta or increase lambda (see Harmony docs). For RPCA/CCA, reduce anchor.features, increase k.anchor, or evaluate using fewer dims.
  • Symptom: Batches remain separated after integration (low iLISI).
    Likely cause: Biological differences align with batch (true biological differences), insufficient shared features, or poor preprocessing (inconsistent normalization / HVG selection).
    Fix: Ensure all input objects were preprocessed consistently (same normalization, selection of variable features). Increase anchor.features or dims used; check that there are enough shared cell types across batches.
  • Symptom: RPCA or CCA fails with memory errors or unreasonable run time.
    Likely cause: Large number of cells/features and default parameters that are computationally heavy.
    Fix: Subsample cells for exploratory comparisons, reduce nfeatures or dims, run integration on a high-memory node, or use Harmony which is more scalable.
  • Symptom: LISI throws errors about data frame formats or missing columns.
    Likely cause: compute_lisi expects embeddings and metadata combined in a single data.frame with metadata columns present.
    Fix: Construct the data.frame as shown (embeddings columns followed by metadata columns) and pass the correct column names.

Limitations, version & reference-data caveats, and responsible use

Limitations and caveats:

  • Integration transforms embeddings; they are not the original expression matrix. For differential expression or gene-level analyses, either use uncorrected expression values with covariates or use integration-aware methods that preserve gene-level interpretation.
  • Algorithms rely on the existence of shared biological states across batches. If two datasets are fundamentally different in cell type composition or one lacks a cell type entirely, integration can either fail to mix or will force spurious overlap.
  • Results are sensitive to preprocessing (variable feature selection, scaling, number of PCA components). Keep preprocessing consistent across methods for fair comparisons.
  • Different Seurat and harmony package versions may change behavior or defaults; reproduce results by recording package versions. Example packages to note: Seurat v5.x, harmony v1.x, lisi v0.x.

Responsible-use notes:

  • Always visualize and quantify integration outcomes; do not rely on a single plot or metric.
  • For clinical or translational interpretations avoid using integrated embeddings as direct evidence of biological equivalence — follow up with orthogonal validation (marker staining, independent cohorts).
  • Document your integration choices (parameters, features used) in notebooks or pipelines so analyses are auditable and reproducible.

Next-step checklist (concise)

  1. Ensure you have saved copies of raw, unintegrated Seurat objects (pbmc3k.rds, pbmc10k.rds).
  2. Run the baseline PCA + UMAP and inspect batch separation visually before integration.
  3. Run Harmony and RPCA as separate branches, saving outputs (merged_harmony.rds, merged_rpca.rds).
  4. Compute iLISI and cLISI for each integrated result and compare to baseline.
  5. Inspect marker gene expression across resulting clusters to confirm biological preservation.
  6. If results diverge, iterate on parameters (theta for Harmony, anchor.features/dims for RPCA) and document all parameter choices.
