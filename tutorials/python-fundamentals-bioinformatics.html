Python Fundamentals for Bioinformatics

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

By the end of this lesson you will be able to:

  • Use Python variables, strings, lists, dictionaries, loops, conditions, and functions for small bioinformatics tasks.
  • Read and validate plain-text biological sequence files (FASTA) safely and compute basic statistics: sequence length and GC content.
  • Create a reproducible, modular script with a clear input and output path, and run it inside an isolated virtual environment.
  • Inspect results and understand what the computed statistics imply — and what they do not.

Prerequisites:

  • Basic familiarity with the command line (cd, ls) and an editor (vim, nano, VS Code).
  • Python 3.10 or newer installed. This lesson uses explicit commands for Python 3; adjust to your system's python executable if needed.
  • Approximately 30–60 minutes of hands-on time.

Why these fundamentals matter for bioinformatics

Many bioinformatics workflows reduce to repeated, describable operations on sequence text and tables: parsing files, counting characters, grouping records, filtering rows. Turning manual inspection into a small, testable Python program makes analysis reproducible and inspectable. Learning how to validate input (for example: is this a DNA sequence or corrupted text?) prevents downstream errors and silent misinterpretation. The examples here focus on FASTA sequence files and simple tabular summarization, which map directly to tasks such as quality assessment, quick filtering, and preparing data for downstream tools.

Reproducible workflow: create an environment, inspect FASTA, compute stats

The workflow below is deliberately small and reproducible. Copy each command into a terminal. All file paths are relative to a project directory; use absolute paths if you prefer.

Files you should have before starting (create these or replace with your own):

  • data/raw/example.fasta — a small FASTA file with one or more sequences. Example content is provided below if you need to create it.
  • scripts/compute_fasta_stats.py — the script we'll create in this lesson.

1. Create a project directory and a tiny example FASTA

# Make a project folder and create input directories
mkdir -p ~/projects/python-bioinfo/data/raw ~/projects/python-bioinfo/scripts
cd ~/projects/python-bioinfo

# Create a small example FASTA if you do not already have one
cat > data/raw/example.fasta <<'EOF'
>seq1
ACGTACGTNNACGT
>seq2
acgtacgtacgtacgtacgt
>seq3
AGCTTAGC--NNNN
EOF

# Confirm the file exists and show contents
ls -l data/raw/example.fasta
cat data/raw/example.fasta

What this produces: a FASTA file at data/raw/example.fasta containing three sequence records. The example shows uppercase and lowercase letters, ambiguous base letters (N), and a line with non-standard characters (“-”) to demonstrate validation needs.

2. Create and activate a virtual environment

# Create an isolated environment (will create ~/projects/python-bioinfo/.venv)
python3 -m venv .venv

# Activate the environment (POSIX shells)
source .venv/bin/activate

# Upgrade pip and install recommended packages (optional)
python -m pip install --upgrade pip
python -m pip install biopython pandas

# Record exact versions for reproducibility
python -m pip freeze > envs-requirements.txt

What this produces: a virtual environment in .venv, and envs-requirements.txt listing installed package versions. If you later want to recreate the exact environment, use pip install -r envs-requirements.txt.

3. Write a small, well-tested Python script

Create scripts/compute_fasta_stats.py. The script below is intentionally small, documents assumptions, performs input validation, and writes a CSV summary to outputs/sequence_stats.csv.

#!/usr/bin/env python3
"""
scripts/compute_fasta_stats.py

Read a FASTA file, validate sequences, compute length and GC fraction for each record,
and write a CSV file with summary statistics.

Usage:
  python scripts/compute_fasta_stats.py data/raw/example.fasta outputs/sequence_stats.csv
"""
import sys
import csv
from pathlib import Path

VALID_BASES = set("ACGTN")  # Accept uppercase only after normalization

def normalize(seq):
    "Strip whitespace and convert to uppercase."
    return seq.replace(" ", "").replace("\t", "").upper().strip()

def is_valid_dna(seq):
    "Return True if sequence contains only expected bases A,C,G,T,N."
    return bool(seq) and all(ch in VALID_BASES for ch in seq)

def gc_fraction(seq):
    "Compute GC fraction safely; assumes seq is normalized uppercase."
    if len(seq) == 0:
        return 0.0
    gc = sum(1 for ch in seq if ch in ("G", "C"))
    return gc / len(seq)

def fasta_records(path):
    """Simple, memory-efficient FASTA parser.
    Yields tuples: (header, sequence_string).
    This parser treats any line starting with '>' as header.
    """
    with open(path, "r", encoding="utf-8") as fh:
        name = None
        parts = []
        for raw in fh:
            line = raw.rstrip("\n")
            if not line:
                continue
            if line.startswith(">"):
                if name is not None:
                    yield name, "".join(parts)
                name = line[1:].strip()
                parts = []
            else:
                parts.append(line)
        if name is not None:
            yield name, "".join(parts)

def main():
    if len(sys.argv) != 3:
        print("Usage: python scripts/compute_fasta_stats.py INPUT.fasta OUTPUT.csv", file=sys.stderr)
        sys.exit(2)

    in_path = Path(sys.argv[1])
    out_path = Path(sys.argv[2])
    out_path.parent.mkdir(parents=True, exist_ok=True)

    with open(out_path, "w", newline="", encoding="utf-8") as out_fh:
        writer = csv.DictWriter(out_fh, fieldnames=["id", "length", "gc_fraction", "valid"])
        writer.writeheader()
        for header, seq in fasta_records(in_path):
            seq_norm = normalize(seq)
            valid = is_valid_dna(seq_norm)
            length = len(seq_norm)
            gc = gc_fraction(seq_norm) if valid else ""
            writer.writerow({
                "id": header,
                "length": length,
                "gc_fraction": f"{gc:.5f}" if gc != "" else "",
                "valid": "yes" if valid else "no"
            })

if __name__ == "__main__":
    main()

What this produces: a script that reads a FASTA file, validates sequences against a simple DNA alphabet (A,C,G,T,N), computes length and GC fraction for each record, and writes data to the output CSV path you provide.

4. Run the script

# Run the script with the example FASTA and write results to outputs/
python scripts/compute_fasta_stats.py data/raw/example.fasta outputs/sequence_stats.csv

# Show the resulting CSV
cat outputs/sequence_stats.csv

Expected file: outputs/sequence_stats.csv with columns: id, length, gc_fraction, valid. The exact numeric values depend on the input sequences. The CSV is safe to open in a spreadsheet or to load into pandas for downstream processing.

5. Optional: parse with Biopython for comparison

If you installed Biopython in the virtual environment, you can accomplish the same work using SeqIO. That approach is better for production because it supports many formats and handles edge cases.

# Run an interactive one-liner (while env is activated)
python - <<'PY'
from Bio import SeqIO
from pathlib import Path
p = Path("data/raw/example.fasta")
for rec in SeqIO.parse(str(p), "fasta"):
    seq = str(rec.seq).upper()
    gc = sum(1 for b in seq if b in "GC") / len(seq) if len(seq) > 0 else 0.0
    print(rec.id, len(seq), f"{gc:.5f}")
PY

What this produces: console output listing record id, length, and GC fraction computed from Biopython's record objects. Biopython handles sequence objects and file formats robustly; for learning, we used a minimal parser earlier to show the format mechanics.

Output inspection and interpretation

When you open outputs/sequence_stats.csv, check the following:

  • All expected record IDs are present. Missing IDs may indicate a parsing error or that the input FASTA lines were malformed.
  • Length values reflect the number of characters after normalization (spaces and tabs removed). Very short sequences (length 0–3) should be inspected manually because they may be fragments, adapter sequences, or corrupted lines.
  • gc_fraction is the proportion of G or C bases (0.0–1.0). Values near 0.5 are common for many genomes, but expected GC content depends on organism or target (bacterial genomes can range widely).
  • The valid column flags records where non-standard characters were found (for this lesson that means characters outside A,C,G,T,N). If valid is "no", the gc_fraction field is left blank and you should inspect the corresponding sequence in the FASTA file.

What a plausible result means — and what it does NOT prove:

  • If a sequence has gc_fraction = 0.42, this simply means 42% of the characters in the provided string are G or C. It does not prove the sequence is error-free or biologically meaningful — contamination, assembly artifacts, or sequencing biases can change GC content.
  • Short sequences or sequences labeled invalid may be genuine biological data (e.g., primers with ambiguous bases) or may indicate file corruption. Manual inspection or comparison to original data sources is required.
  • Aggregate summaries (mean GC across records) are descriptive. They are not a substitute for statistical testing if you want to compare groups or draw biological conclusions.

Troubleshooting: symptoms, likely causes, and fixes

Symptom: The script crashes with UnicodeDecodeError when reading the FASTA.

  • Cause: The input file uses a non-UTF-8 encoding (e.g., Windows-1252) or contains binary content.
  • Fix: Convert the file to UTF-8 or open with the correct encoding. Example: iconv -f WINDOWS-1252 -t UTF-8 input.fasta -o output.fasta. Always inspect binary files (e.g., using file and head commands) before processing.

Symptom: Many sequences are flagged valid=no.

  • Cause: The input FASTA contains characters outside the accepted set (e.g., gap character '-', IUPAC codes like R/Y, or quality scores accidentally included).
  • Fix: Decide what extended characters you want to accept (IUPAC codes: R, Y, S, W, K, M, B, D, H, V) and extend VALID_BASES accordingly. Alternatively, pre-filter or clean sequences to remove gap characters if appropriate for your analysis.

Symptom: Output CSV is missing records or header only.

  • Cause: The FASTA file may lack a trailing newline or final header handling. The simple parser expects '>' to start headers; if the file is empty, nothing is written.
  • Fix: Confirm the FASTA file contains at least one header line (beginning with '>') and sequence lines. Use wc -l and grep '^>' to count headers: grep -c '^>' data/raw/example.fasta.

Symptom: Incorrect GC values compared to external tools.

  • Cause: Differences in normalization: some tools ignore ambiguous bases or gaps when computing fractions, others count them in the denominator.
  • Fix: Make your normalization explicit. If you want GC fraction computed as GC / (A+C+G+T) excluding ambiguous bases, implement that rule rather than using the raw length.

Limitations, version and reference-data caveats, and responsible use

Limitations of this lesson and script:

  • The simple parser is educational and works for most single-sequence FASTA files. It does not validate FASTA headers against any controlled schema (for example, headers with embedded tabs or spaces), nor does it support FASTQ, multi-line headers with specific metadata, or indexed formats. For production work, prefer robust libraries (Biopython SeqIO, scikit-bio).
  • Validation here is limited to a user-defined alphabet (A, C, G, T, N). Biological sequences sometimes include IUPAC ambiguity codes or gap characters (e.g., '-'). Decide which characters your pipeline should accept and document that choice.
  • Floating-point representation of GC fraction uses simple rounding for readability; for downstream statistical analysis you may want more precision or native numeric types (not formatted strings).

Version and reference-data caveats:

  • Different versions of Biopython, pandas, or Python may change behavior (for example, encoding defaults or CSV dialect handling). Record exact versions with pip freeze or conda list for reproducibility.
  • Reference genome sequences and annotations can change over time. If you are comparing GC content to published values, ensure you are using the same assembly and coordinate convention as the reference.

Responsible use notes:

  • Do not assume computed statistics imply biological meaning without appropriate controls and metadata assessment (sample origin, library preparation, sequencing platform).
  • Be cautious when sharing sequence-derived files that may include sensitive or personally identifying information. Follow institutional policies and data-use agreements.
  • Never run or paste unreviewed code into tools that will give it network access or elevate privileges. The examples here are safe for local file processing and avoid destructive commands (no rm, mv, or system calls that touch other directories).

Next-step checklist

  1. Run the script on your own FASTA files and confirm outputs/sequence_stats.csv contains expected rows and values.
  2. Decide how to treat ambiguous bases and update VALID_BASES and gc_fraction semantics accordingly.
  3. If you need to process large FASTA files, consider switching to Biopython SeqIO for robustness and memory-efficient streaming.
  4. Write small unit tests for gc_fraction and is_valid_dna using the pytest framework to ensure behavior is stable as you refactor.
  5. Store envs-requirements.txt in version control and add instructions for recreating the environment in your project README.
