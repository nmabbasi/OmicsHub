Summarize FASTQ and Annotation Files with Bash

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

← Previous tutorialAll tutorialsNext tutorial →

Build one small Bash program that streams either FASTQ reads or a tab-separated annotation table, validates the assumptions it can check, and writes a reproducible summary table. The two input types need different checks, so you select the mode explicitly rather than guessing from the first line.

Before you run the examples

You should be comfortable moving around the shell and using basic commands such as ls, cd, cat, and grep. Work in a disposable directory. This walkthrough uses Bash, awk, gzip, sort, and standard file utilities; it does not require a biological dataset.

The FASTQ mode accepts the common four-line record layout: identifier line beginning with @, sequence, separator beginning with +, and quality string. This example checks record structure and equal sequence/quality lengths. FASTQ variants and multiline records need a format-aware tool rather than this deliberately narrow summarizer. The annotation mode expects tab-separated columns in this order: chromosome, start, end, feature ID, strand. It calculates inclusive interval lengths as end - start + 1, so use one-based inclusive coordinates or adjust the formula for your file's coordinate convention.

Make a disposable example dataset

The following files are synthetic teaching fixtures. Their values test the mechanics of the script; they are not biological observations.

mkdir -p ~/shell-tutorial/test_data ~/shell-tutorial/results

cat > ~/shell-tutorial/test_data/annotations.tsv <<'TSV'
chr	start	end	feature_id	strand
chr1	100	200	geneA	+
chr1	300	350	geneB	-
chr2	50	400	geneC	+
TSV

cat > ~/shell-tutorial/test_data/example.fastq <<'FASTQ'
@read1
ACTGACTGACTG
+
IIIIIIIIIIII
@read2
ACTGACTG
+
IIIIIIII
FASTQ
gzip -c ~/shell-tutorial/test_data/example.fastq > ~/shell-tutorial/test_data/example.fastq.gz

gzip -c sends compressed bytes to standard output and leaves the uncompressed fixture in place. The annotation table includes a header so the script can skip it explicitly.

Write the summarizer

Save this as ~/shell-tutorial/summarize.sh. Choose fastq or annotations as the first argument, then supply an input path and output path. A filename ending in .gz is integrity-tested and streamed through gzip; uncompressed input is streamed with cat. The program writes to a temporary file beside the destination and replaces the destination only after successful processing. An existing output with that name will therefore be replaced on success.

#!/usr/bin/env bash
# Usage: summarize.sh {fastq|annotations} INPUT_FILE OUTPUT.tsv
set -euo pipefail

if [[ $# -ne 3 ]]; then
  echo "Usage: $0 {fastq|annotations} INPUT_FILE OUTPUT_TSV" >&2
  exit 2
fi
mode=$1
input=$2
output=$3
if [[ $mode != fastq && $mode != annotations ]]; then
  echo "Mode must be fastq or annotations" >&2
  exit 2
fi
if [[ $input != - && ! -r $input ]]; then
  echo "Input is not readable: $input" >&2
  exit 1
fi
mkdir -p "$(dirname -- "$output")"
tmp=$(mktemp "${output}.tmp.XXXXXX")
trap 'rm -f -- "$tmp"' EXIT

if [[ $input == *.gz ]]; then
  gzip -t -- "$input"
  stream=(gzip -dc -- "$input")
elif [[ $input == - ]]; then
  stream=(cat)
else
  stream=(cat -- "$input")
fi

case $mode in
  fastq)
    {
      printf '#type\tcount\tmin_len\tmax_len\tmean_len\n'
      "${stream[@]}" | awk '
        { sub(/\r$/, "") }
        NR % 4 == 1 && substr($0, 1, 1) != "@" {
          print "Invalid FASTQ: record header must start with @ (line " NR ")" > "/dev/stderr"; bad=1; exit 1
        }
        NR % 4 == 2 {
          seq=$0
          if (seq == "") { print "Invalid FASTQ: empty sequence (line " NR ")" > "/dev/stderr"; bad=1; exit 1 }
          n=length(seq); sum+=n
          if (count==0 || n<min) min=n
          if (n>max) max=n
          count++
        }
        NR % 4 == 3 && substr($0, 1, 1) != "+" {
          print "Invalid FASTQ: separator line must start with + (line " NR ")" > "/dev/stderr"; bad=1; exit 1
        }
        NR % 4 == 0 && length($0) != length(seq) {
          print "Invalid FASTQ: sequence and quality lengths differ (record " count ")" > "/dev/stderr"; bad=1; exit 1
        }
        END {
          if (bad) exit 1
          if (NR == 0 || NR % 4 != 0) { print "Invalid FASTQ: empty or incomplete four-line record" > "/dev/stderr"; exit 1 }
          printf "reads\t%d\t%d\t%d\t%.2f\n", count, min, max, sum/count
        }'
    } > "$tmp"
    ;;
  annotations)
    {
      printf '#chr\tfeature_count\tavg_length\n'
      "${stream[@]}" | awk -F '\t' '
        NF==0 || $0 ~ /^#/ { next }
        tolower($1)=="chr" && tolower($2)=="start" { next }
        {
          if (NF < 3 || $1 == "" || $2 !~ /^[0-9]+$/ || $3 !~ /^[0-9]+$/ || $2 < 1 || $3 < $2) {
            print "Invalid annotation at line " NR ": expected chromosome and 1-based inclusive start/end with start <= end" > "/dev/stderr"; bad=1; exit 1
          }
          if (!($1 in count)) chromosomes++
          len=$3-$2+1; count[$1]++; sum[$1]+=len
        }
        END {
          if (bad) exit 1
          if (chromosomes==0) { print "No annotation rows found" > "/dev/stderr"; exit 1 }
          for (chr in count) printf "%s\t%d\t%.2f\n", chr, count[chr], sum[chr]/count[chr]
        }' | sort -k1,1
    } > "$tmp"
    ;;
esac
mv -f -- "$tmp" "$output"
trap - EXIT
echo "Wrote summary to $output" >&2

Make the file executable, then run one command per input type:

chmod 755 ~/shell-tutorial/summarize.sh
~/shell-tutorial/summarize.sh fastq \
  ~/shell-tutorial/test_data/example.fastq.gz \
  ~/shell-tutorial/results/fastq_summary.tsv
~/shell-tutorial/summarize.sh annotations \
  ~/shell-tutorial/test_data/annotations.tsv \
  ~/shell-tutorial/results/annotations_summary.tsv

Read the output and check the assumptions

Inspect the small tables with cat or a spreadsheet program:

cat ~/shell-tutorial/results/fastq_summary.tsv
cat ~/shell-tutorial/results/annotations_summary.tsv

For the synthetic files above, the FASTQ table should report two reads, lengths 8 and 12, and mean length 10.00. The annotation table should report two intervals on chr1 with mean inclusive length 76.00, and one interval on chr2 with length 351.00. These are deterministic checks of the fixture arithmetic, not QC results about a sequencing experiment or genome.

  • A FASTQ input with an incomplete record, a misplaced header/separator, an empty sequence, or a sequence/quality length mismatch exits with an error. The temporary output is removed rather than installed as the requested summary.
  • A gzip file is checked with gzip -t before its contents are processed. A failed integrity test stops the script. Compression format and filename suffix must agree: only a .gz suffix triggers decompression.
  • Annotation rows with non-numeric coordinates, a start below 1, or an end before the start fail. Comment lines beginning with # and the described header row are skipped. The code does not validate chromosome names, strand values, feature IDs, overlap, genome build, or biological plausibility.
  • Read length alone says nothing about per-base quality, adapter contamination, mapping, or whether trimming was appropriate. Use a dedicated sequencing QC workflow for those questions.

Why the shell checks matter

set -euo pipefail asks Bash to stop on many unhandled command failures, unset variables, and failed commands within a pipeline. In particular, pipefail prevents an upstream decompressor error from being hidden by a successful downstream command. The temporary file keeps incomplete results out of the destination, and mv installs the completed file only at the end.

The awk program reads line records, checks the assumptions for its selected mode, and accumulates counts and lengths. In FASTQ mode, every fourth input line is treated as one record component; this is why wrapped or multiline sequence records are rejected rather than silently miscounted. Annotation output is sorted by chromosome name for stable row order. Bash arrays and [[ ... ]] are Bash features, so run the script with Bash rather than sh.

Common failures and safe adjustments

  • gzip: ... not in gzip format or a failed integrity test: verify the file type and transfer integrity. Do not strip the suffix or treat a damaged compressed file as plain text without checking it.
  • FASTQ structure error: inspect the first records and confirm the file follows the four-line layout used here. FASTQ has variants; use a dedicated parser for wrapped records or other nonstandard layouts rather than weakening validation to accept ambiguous input.
  • No annotation rows found: check that the table is tab-delimited, contains the stated columns, and has at least one data row after its header/comments. Change the explicit column mapping if your file uses a different schema.
  • Lengths are off by one: confirm the source coordinate convention. The included end - start + 1 calculation is for 1-based inclusive intervals. For zero-based half-open intervals, length is end - start.
  • Need to process many files: iterate over paths with a quoted loop rather than expanding a large wildcard into one command. For example, from the directory containing the inputs:
for file in data/*.fastq.gz; do
  [[ -e $file ]] || continue
  name=${file##*/}
  name=${name%.fastq.gz}
  ~/shell-tutorial/summarize.sh fastq "$file" "results/${name}.summary.tsv"
done

The loop handles spaces in filenames and the no-match case; the script still checks each compressed input. Choose output names that do not collide with files you need to keep.

Permissions and longer-running jobs

chmod 755 summarize.sh gives the owner read, write, and execute permissions and gives group and other users read and execute permissions, subject to the directory's access controls. If others should not be able to read the script, choose a narrower mode such as chmod 700 summarize.sh.

For a long run, redirect both output streams to a log and run it in the background:

nohup ~/shell-tutorial/summarize.sh fastq large.fastq.gz \
  results/large_summary.tsv > results/large_summary.log 2>&1 &

Record the job ID printed by the shell, inspect the log, and check completion before treating the output as finished. jobs lists jobs in the current shell; ps can inspect processes more broadly. A background process may still be running or may fail, so starting it is not evidence that the summary completed.

Scope and reproducibility

This is a small streaming summary, not a replacement for validated parsers, large-scale statistical analysis, or biological QC. It uses simple awk arithmetic and reports arithmetic mean lengths; for analyses needing other statistics, validated input semantics, or larger numeric ranges, use tools suited to that analysis. The local example was checked on the synthetic fixtures described above. Results can differ across awk and utility implementations, so test on the target system and record tool versions when portability matters. Do not run examples on irreplaceable or controlled data without following the relevant access and data-handling rules. Record input checksums and software versions when you need an auditable workflow.
