Choosing and Checking Cell-Type Annotation Methods

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Cell-type labels are hypotheses supported by expression measurements and biological context. Choose an annotation method according to the evidence you have, then check the labels against markers and the method's uncertainty output.

Scope and inputs. The examples below assume a quality-controlled, clustered human scRNA-seq Seurat object called pbmc, with RNA counts and normalized data, and a cell-level cluster identity in Idents(pbmc). Reference-based methods also need a labeled reference with compatible features. These are example contracts, not supplied data or a tested environment.

Choose a method from the evidence you have

The lesson focuses on these six established workflows. A previous draft also named CyteTypeR, but its purported package API, output contract, and claims about multi-agent behavior could not be checked against an authoritative project source. It is omitted rather than presented as runnable or validated. An LLM-generated annotation, if used elsewhere, should be treated as an unverified hypothesis and checked against dataset-derived evidence.

Prepare the object and preserve the input contract

Do not assume that “normalized expression” means the same input for every method. SingleR accepts expression data and its current vignette demonstrates a SummarizedExperiment reference; CellAssign specifically expects raw counts. Confirm feature identifiers and cell order before binding any result back to the object.

library(Seurat)
pbmc <- readRDS("data/pbmc_seurat.rds")
dir.create("results", showWarnings = FALSE)
stopifnot(inherits(pbmc, "Seurat"), ncol(pbmc) == length(Idents(pbmc)))
stopifnot("RNA" %in% Assays(pbmc))

This is a minimal object check, not proof that normalization, clustering, metadata, or biological QC is appropriate. Check available assay layers for your installed SeuratObject version; direct slot access such as @assays$RNA@data is version-sensitive and may not work with current layered assays.

Run reference-based workflows

SingleR with a celldex reference

SingleR scores each test cell against labels in a reference. The reference and test data need overlapping, consistently named genes. HPCA is a bulk/microarray-derived reference, so its labels and platform may not resolve every state in a single-cell query.

library(SingleR)
library(celldex)
library(Seurat)

hpca <- HumanPrimaryCellAtlasData()
test_data <- GetAssayData(pbmc, assay = "RNA", layer = "data")
pred <- SingleR(test = test_data, ref = hpca, labels = hpca$label.main)
pbmc$SingleR_label <- pred$labels
write.csv(data.frame(cell = rownames(as.data.frame(pred)),
                     label = pred$labels,
                     delta.next = pred$delta.next),
          "results/singleR_predictions.csv", row.names = FALSE)

Use a normalized test matrix whose genes are rows and cells are columns; inspect the reference's logcounts assay and labels before running. The exact accessor for Seurat data differs by version and assay storage. The code assumes the selected layer="data" exists and uses a matching gene identifier convention. SingleR's returned rows correspond to test cells; its score matrix and delta diagnostics can help flag ambiguity. A small delta is uncertainty, not a universal rejection threshold.

Seurat label transfer

This path is conditional on data/ref_seurat.rds existing and containing the cell-level metadata field celltype_label. Use compatible assays and preprocessing. Seurat defaults to PCA projection with 30 dimensions; a hard-coded dimension range can fail when the reference has fewer usable dimensions or unsuitable preprocessing.

ref <- readRDS("data/ref_seurat.rds")
stopifnot("celltype_label" %in% colnames(ref[[]]))
anchors <- FindTransferAnchors(reference = ref, query = pbmc)
transfer <- TransferData(anchorset = anchors,
                         refdata = ref$celltype_label)
pbmc <- AddMetaData(pbmc, metadata = transfer)
write.csv(transfer, "results/seurat_transfer_predictions.csv")

TransferData returns predictions and associated scores for categorical labels when called without a query argument. Review the prediction-score fields as well as labels. Transferred labels describe resemblance to the reference; they do not establish that query cells have the same biological state.

scmap-cluster with a labeled reference

scmap uses SingleCellExperiment objects. The reference must carry cluster labels in the selected column, here celltype_label; select features and build the cluster index on the reference. Confirm that its log-expression assay and gene symbols are suitable for the query.

library(SingleCellExperiment)
library(scmap)
query_sce <- as.SingleCellExperiment(pbmc)
ref_sce <- readRDS("data/ref_sce.rds")
stopifnot("celltype_label" %in% colnames(colData(ref_sce)))
ref_sce <- selectFeatures(ref_sce)
ref_sce <- indexCluster(ref_sce, cluster_col = "celltype_label")
scmap_res <- scmapCluster(
  projection = query_sce,
  index_list = list(reference = metadata(ref_sce)$scmap_cluster_index)
)
write.csv(scmap_res$combined_labs,
          "results/scmap_cluster_predictions.csv", row.names = FALSE)

The output includes combined labels and method-specific similarity results. Inspect similarity and any unassigned cells; do not treat a nearest reference cluster as proof that the query has no novel type.

Run marker-driven workflows

scCATCH: cluster markers and tissue-specific matching

scCATCH's documented sequence is to create an object from normalized expression and one cluster label per cell, identify markers using its supported marker data, then score cell types. Its vignette does not support passing Seurat's FindAllMarkers output in the marker parameter as the prior draft did. This revised outline avoids an unsupported mapping; follow the package vignette for the version-specific accepted marker object and supported tissue terms.

library(scCATCH)
sc_data <- GetAssayData(pbmc, assay = "RNA", layer = "data")
clusters <- as.character(Idents(pbmc))
stopifnot(ncol(sc_data) == length(clusters))
sc_obj <- createscCATCH(data = sc_data, cluster = clusters)
# Supply the package's supported marker data and tissue context as documented:
# sc_obj <- findmarkergene(sc_obj, species = "Human",
#                           marker = cellmatch, tissue = "Blood")
# sc_obj <- findcelltype(sc_obj)

The database's supported tissue labels and organism coverage constrain this approach. Do not interpret an “unknown” or empty annotation as evidence that a cell type is biologically absent.

Garnett: define and audit marker rules

Garnett requires a CellDataSet, a marker file and a species-appropriate AnnotationDb package for gene-ID conversion. Its marker file is an input that you must author and justify, not an automatic consequence of clustering. A minimal format looks like this:

>B cells
expressed: CD19, MS4A1

>T cells
expressed: CD3D

After converting the Seurat data into a compatible CDS and confirming identifier types, the documented sequence is check_markers(), train_cell_classifier(), then classify_cells(). Conversion from Seurat and package interfaces vary by release, so this is a method outline rather than a complete command sequence. Check marker specificity and gene-ID mapping before training; broad markers can blur neighboring labels.

CellAssign: counts and marker matrix must align

CellAssign takes raw counts as a cell-by-gene matrix (or a suitable SummarizedExperiment) and a gene-by-cell-type binary marker matrix. Seurat expression matrices are typically genes by cells, so transpose counts for a matrix input and ensure marker rows match the gene columns exactly. The earlier draft passed a genes-by-cells matrix and used s=1 without defining size factors; that did not meet the documented input contract.

counts_gene_cell <- GetAssayData(pbmc, assay = "RNA", layer = "counts")
counts_cell_gene <- t(as.matrix(counts_gene_cell))
markers <- readRDS("data/cellassign_markers.rds") # genes x cell types, 0/1
stopifnot(identical(colnames(counts_cell_gene), rownames(markers)))
fit <- cellassign::cellassign(
  exprs_obj = counts_cell_gene,
  marker_gene_info = markers
)
saveRDS(fit, "results/cellassign_fit.rds")

In practice, reorder marker rows to match count gene columns before the check if the same genes appear in a different order, and subset counts and markers to shared genes. The package can estimate size factors when s is omitted. Read cell labels through fit$cell_type; inspect model diagnostics and posterior estimates where available. The output path is a fitted object, not a CSV of posterior probabilities. Batch covariates require explicit, correctly shaped input through the documented X argument; do not call CellAssign “robust to batch effects” without defining and evaluating that model.

Compare results without mistaking agreement for validation

Methods here return labels at different levels: SingleR, Seurat transfer, scmap, Garnett and CellAssign can label cells, while scCATCH is cluster-oriented. Align labels by cell identifier before comparing. Do not repeat a cluster label for each cell and then interpret the inflated count as independent evidence.

  1. Make a per-cell table keyed by stable cell IDs; retain each tool's original label and confidence/score field.
  2. Summarize label proportions by cluster and inspect cluster-level disagreement separately from per-cell uncertainty.
  3. Plot dataset-derived expression for discriminating markers (for example, CD3D or MS4A1 only where relevant to the tissue and assay). Check whether the evidence is present in the cells bearing each label.
  4. For disagreements, revisit reference fit, gene naming, assay layer, tissue context, and marker definitions before changing cluster resolution or selecting a “winner.”
  5. Record software versions, reference identity/version, preprocessing and all manual decisions.

A contingency table is descriptive agreement, not a gold-standard accuracy measure. Methods can share reference or marker biases. Lack of agreement points to a review task; agreement cannot rule out a shared error. A marker's absence can reflect dropout, low depth, state variation or an unsuitable marker, not necessarily a wrong label.

Common failure patterns

Unexpected broad labels or low scores

Check species, feature identifiers, reference composition and assay compatibility. Compare score separation and pruned/unknown calls; avoid inventing a universal score cutoff.

Many unassigned clusters

Check scCATCH tissue selection and detected cluster markers, or scmap reference labels and similarity. Preserve abstention as information while investigating markers and reference coverage.

Before accepting a label: verify that the method received the expected assay and orientation; the reference/marker genes match the dataset; the label granularity fits the evidence; and at least one independent line of evidence supports the interpretation.

Limits and responsible interpretation

Automated annotation depends on reference coverage, marker specificity, tissue context, sequencing depth and preprocessing. Rare or novel states may not be represented. A confidence score is method-specific and is not a calibrated probability that a biological label is true. Cell-type annotation is not a clinical diagnosis. For consequential claims, seek orthogonal evidence such as protein measurements or targeted validation and report what was actually tested.

Practice: audit one disputed cluster

Choose a cluster where two methods disagree. Write down each tool's input, reference or marker source, label and uncertainty metric. Check the dataset's expression for the strongest discriminating markers, then state what further evidence would resolve the disagreement. A sound outcome may remain “unresolved” when available data cannot distinguish the candidates.
