Choosing and evaluating scRNA-seq integration: Harmony, RPCA, and CCA

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Integration changes the representation used to compare cells. This lab compares Harmony with Seurat's anchor-based RPCA workflow, explains where CCA differs, and builds a diagnostic comparison that asks whether batch mixing improves while known biology remains recognizable.

What you will produce: baseline, Harmony, and RPCA embeddings; per-cell iLISI scores for batch and cLISI scores for known cell labels; and a written assessment that combines those diagnostics with marker expression.

Prerequisites: basic scRNA-seq preprocessing (normalization, variable features, PCA, UMAP), R, and Seurat. The code below uses the classic Seurat anchor workflow with log-normalized RNA data; it is not a promise that package versions or object layouts are interchangeable. Seurat v5 also offers layer-based integration via IntegrateLayers. Input files are user-provided Seurat objects, not downloaded by this lesson.

Decide whether integration is justified

Batch separation in an embedding can reflect technical effects, genuine biology, or both. Integration is useful when datasets share biological states that should be aligned for joint analysis. If a cell type occurs in only one batch, an algorithm cannot establish that it has a counterpart elsewhere; forced overlap can obscure the distinction. Keep an unintegrated analysis as a reference and do not use an integrated embedding as corrected gene-expression data for differential expression.

Start with the unintegrated comparison. Plot cells by batch and, where available, trusted cell labels. If batches already mix within comparable cell states, integration may add little. If batch dominates shared populations, compare methods. A UMAP is a view of a chosen representation, not a formal quality test.

Input contract and setup

Prepare two RDS files, pbmc3k.rds and pbmc10k.rds (replace these illustrative names). Each must contain a Seurat object with a raw-count RNA assay and cell metadata. Objects must use compatible gene identifiers and have enough shared features and biological states for meaningful alignment. This example assigns each object one batch label; for multiple samples, use a metadata column that identifies the actual batch for every cell. Preserve original files and record package versions before analysis.

library(Seurat)
library(harmony)
library(lisi)

pbmc3k <- readRDS("pbmc3k.rds")
pbmc10k <- readRDS("pbmc10k.rds")
stopifnot(inherits(pbmc3k, "Seurat"), inherits(pbmc10k, "Seurat"))
stopifnot("RNA" %in% Assays(pbmc3k), "RNA" %in% Assays(pbmc10k))
pbmc3k$batch <- "v1_3k"
pbmc10k$batch <- "v3_10k"
merged <- merge(pbmc3k, y = pbmc10k, add.cell.ids = c("3k", "10k"))
stopifnot("batch" %in% colnames(merged[[]]))
print(table(merged$batch))

The checks catch wrong object types and absent assays; they do not prove that counts are raw, features are comparable, or labels are biologically appropriate. If RNA is absent, stop and identify the intended assay rather than silently switching assays. Confirm the printed cell counts and batch labels before proceeding.

Build a common preprocessing baseline

Use a consistent RNA preprocessing path before branching. Here the objects are merged and normalized together; the RPCA branch below is then split by batch and each object receives PCA for reciprocal anchor finding. The choices of 3,000 variable features and 50 PCs are example settings, not universal thresholds; reduce dimensions if the data do not support them. If your Seurat v5 object has split assay layers that prevent the legacy commands from operating as intended, follow the current layer-based vignette instead of forcing this workflow.

DefaultAssay(merged) <- "RNA"
merged <- NormalizeData(merged, verbose = FALSE)
merged <- FindVariableFeatures(merged, selection.method = "vst",
                               nfeatures = 3000, verbose = FALSE)
merged <- ScaleData(merged, verbose = FALSE)
merged <- RunPCA(merged, npcs = 50, verbose = FALSE)
merged <- RunUMAP(merged, reduction = "pca", dims = 1:30,
                  reduction.name = "umap.pca")
DimPlot(merged, reduction = "umap.pca", group.by = "batch")

Inspect whether batch separation occurs within comparable populations. Save an unintegrated object or retain the original files so every integrated branch can be compared against this baseline.

Run Harmony and RPCA as separate analyses

Harmony: correct PCA embeddings

Harmony takes a computed PCA reduction and a batch variable. Its corrected coordinates are stored as a reduction, so make the UMAP from that reduction; the RNA assay remains the expression source.

merged_harmony <- RunHarmony(merged, group.by.vars = "batch",
                             reduction = "pca", dims.use = 1:30)
merged_harmony <- RunUMAP(merged_harmony, reduction = "harmony",
                          dims = 1:30, reduction.name = "umap.harmony")
DimPlot(merged_harmony, reduction = "umap.harmony", group.by = "batch")

theta controls a diversity-clustering penalty; lambda is a ridge-regression penalty, and lower positive lambda produces more aggressive correction according to Harmony's reference. Do not assume that increasing theta or changing lambda will improve the biological result. Tune one setting at a time and recheck both batch mixing and biology.

RPCA: find reciprocal anchors

RPCA finds anchors using reciprocal PCA spaces across a list of objects. The example repeats preprocessing per batch so the reciprocal reductions exist. Seurat's current API accepts reduction = "rpca" and an AnchorSet can be passed to IntegrateData.

obj_list <- SplitObject(merged, split.by = "batch")
for (i in seq_along(obj_list)) {
  DefaultAssay(obj_list[[i]]) <- "RNA"
  obj_list[[i]] <- NormalizeData(obj_list[[i]], verbose = FALSE)
  obj_list[[i]] <- FindVariableFeatures(obj_list[[i]],
      selection.method = "vst", nfeatures = 3000, verbose = FALSE)
  obj_list[[i]] <- ScaleData(obj_list[[i]], verbose = FALSE)
  obj_list[[i]] <- RunPCA(obj_list[[i]], npcs = 50, verbose = FALSE)
}
anchors_rpca <- FindIntegrationAnchors(object.list = obj_list,
    anchor.features = 3000, reduction = "rpca", dims = 1:50)
merged_rpca <- IntegrateData(anchorset = anchors_rpca, dims = 1:50)
DefaultAssay(merged_rpca) <- "integrated"
merged_rpca <- ScaleData(merged_rpca, verbose = FALSE)
merged_rpca <- RunPCA(merged_rpca, npcs = 50, verbose = FALSE)
merged_rpca <- RunUMAP(merged_rpca, reduction = "pca", dims = 1:30,
                       reduction.name = "umap.rpca")
DimPlot(merged_rpca, reduction = "umap.rpca", group.by = "batch")

The integrated assay/reduction is for dimensional analysis. Preserve the original RNA assay for expression-level inspection. This classic workflow is not the same API as Seurat v5's layer-based IntegrateLayers; choose the workflow that matches your object structure and verify its version-specific instructions.

Where CCA fits

CCA is another anchor-finding reduction and can be compared by changing reduction = "rpca" to reduction = "cca" in FindIntegrationAnchors, then repeating the integration branch. CCA and RPCA make different alignment choices; neither is categorically superior. Seurat describes RPCA as faster and more conservative in its v5 integration overview. Compare outcomes on the same inputs and preprocessing rather than relying on that general characterization as a dataset-specific prediction.

Measure local mixing with LISI

The R lisi::compute_lisi contract is a coordinate matrix with one row per cell and a metadata data frame with corresponding rows. It returns one score per cell and requested categorical label. The earlier practice of passing a combined data frame as the first argument is not this package's documented interface.

# These row names must identify the same cells in the same order.
score_lisi <- function(object, reduction, dims, labels) {
  coords <- Embeddings(object, reduction)[, dims, drop = FALSE]
  meta <- object[[]][rownames(coords), labels, drop = FALSE]
  stopifnot(identical(rownames(coords), rownames(meta)))
  lisi::compute_lisi(coords, meta, label_colnames = labels, perplexity = 30)
}

# Batch mixing for all three representations
lisi_pca <- score_lisi(merged, "pca", 1:30, "batch")
lisi_harmony <- score_lisi(merged_harmony, "harmony", 1:30, "batch")
lisi_rpca <- score_lisi(merged_rpca, "pca", 1:30, "batch")
summary(lisi_harmony$batch)

For a two-batch label, iLISI is an effective number of locally represented categories: values near 1 indicate neighborhoods dominated by one batch; values closer to 2 indicate greater mixing. The attainable value depends on local category proportions and neighborhood scale. For known cell-type labels, cLISI uses the same calculation: values near 1 indicate local label purity, while larger values indicate more label mixing. Calculate it only when labels are available and credible:

# Example assumes a metadata column named celltype is present.
lisi_harmony_both <- score_lisi(merged_harmony, "harmony", 1:30,
                                c("batch", "celltype"))
summary(lisi_harmony_both$batch)    # iLISI direction: higher mixing
summary(lisi_harmony_both$celltype) # cLISI direction: higher label mixing

For a fair comparison, use the same cells, dimensions policy, labels, and perplexity when comparing branches. Missing labels, a missing batch, too few cells relative to perplexity, or misaligned cell ordering can invalidate or break the calculation. These metrics describe local category diversity; they do not establish that the correction is biologically right.

Interpret the comparison and investigate failures

  • Batch scores rise, cell-type scores remain near their baseline, markers remain recognizable: evidence consistent with improved batch mixing while retaining those annotated distinctions. Inspect rare populations and continuous states separately.
  • Batch and cell-type mixing both rise: possible overcorrection or label/annotation issues. Compare known markers and the unintegrated representation before deciding.
  • Batch scores stay low or batches remain separated: check batch labels, shared features/states, preprocessing consistency, and whether the split reflects genuine biology. More aggressive correction is not automatically the answer.
  • RPCA errors or high resource use: confirm each object has enough shared features and a valid PCA; reduce feature/dimension counts for exploration. Subsampling is a diagnostic, not evidence that full-data results will match.
  • LISI reports missing columns or dimension errors: check that coordinate rows and metadata rows refer to identical cells in identical order, requested label columns exist, and selected dimensions are available.

Use marker expression and appropriate downstream analyses as checks. Integrated coordinates are not corrected counts. For differential expression, use unintegrated expression with a design that accounts for relevant covariates or an appropriate integration-aware method; do not treat embedding separation or LISI as a substitute for an inferential model. Clinical or translational equivalence requires independent evidence.

Reproducibility record

Save the original objects, record R and package versions, input identities, metadata definitions, selected dimensions/features, integration settings, and the exact cell labels used for evaluation. Save each branch separately if you need to revisit it. A fixed perplexity and parameters make a comparison more reproducible, but do not make it universally optimal.
