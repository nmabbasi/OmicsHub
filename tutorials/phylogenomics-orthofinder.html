Phylogenomics with OrthoFinder

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

OrthoFinder compares protein-coding genes across proteomes, groups related genes, infers gene trees and a species tree, and reports orthology and duplication relationships. This guide follows the evidence from input files to a defensible interpretation; the program does not turn every orthogroup into a one-to-one marker or prove a biological explanation for a gene-family change.

Prerequisite: predicted protein sequences in FASTA format for each species, with consistent and unique sequence identifiers. The commands below assume OrthoFinder is installed and available as orthofinder. No particular annotation pipeline is required.

1. Prepare the proteomes

Put one protein FASTA file per species in a directory. OrthoFinder treats each file as a species-level input; use filenames that identify the species and keep sequence IDs unique within each file. Its input is amino-acid sequences, not genome assemblies or nucleotide coding sequences. The official project documents FASTA extensions including .fa, .faa, .fasta, .fas and .pep.

proteomes/
  speciesA.faa
  speciesB.faa
  speciesC.faa

Before the run, check that each file parses as FASTA, contains protein sequences rather than nucleotide strings, and has at least one record. Check for duplicated headers and truncated or poorly supported gene models. Uneven annotation completeness can change which orthogroups appear complete, so record the assembly, annotation and proteome versions used. A BUSCO assessment can provide a separate completeness check; matching BUSCO and OrthoFinder markers is useful context, not proof that either set is error-free.

2. Run OrthoFinder and locate the results

From the directory containing proteomes/, run:

orthofinder -f proteomes/

The -f option points to the directory of input FASTA files. A standard run searches sequences across proteomes, infers orthogroups and gene trees, and uses gene-tree information to infer a species tree and orthology relationships. The exact search and tree-inference components depend on OrthoFinder version and configuration; do not assume every release uses the same executable defaults.

OrthoFinder creates a results directory under the input area. Read the run log for the exact path and version, then inspect that run's output tree. In current results, the rooted species tree is normally named SpeciesTree_rooted.txt under the species-tree results directory. The distribution and naming of orthogroup files vary by version. In particular, the older Orthogroups/Orthogroups.tsv is described as deprecated in the current project documentation; newer runs provide phylogenetic hierarchical orthogroups. Consult the results guide for the version you ran rather than copying a path from an unrelated run.

Checkpoint: Keep the run command, software version, input filenames and complete results directory together. If the run reports missing external programs, malformed FASTA, or failed search steps, resolve that failure before interpreting partial files as a completed analysis.

3. Read orthogroups as gene families, not automatic markers

An orthogroup contains genes descended from one ancestral gene at the last common ancestor of the species represented in that group. A species can contribute multiple genes after duplication, or no gene because of loss, missing sequence, incomplete annotation, or the group’s taxonomic scope. Therefore, orthogroup membership alone does not establish one-to-one orthology.

Inspect species membership and copy number for candidate groups. An all-species, single-copy orthogroup has exactly one sequence from every species in your chosen set, making sequence correspondence easier to interpret. It is a useful marker candidate, not a guarantee of correct alignment, neutrality, or an uncontested species history. Check gene-tree quality and alignment, and consider whether the taxon sampling, missing data and evolutionary rates make the locus appropriate.

Restricting selection to all taxa may leave few candidates when proteomes are incomplete or species differ greatly in gene content. A relaxed occupancy threshold can retain more loci, but creates missing entries and changes the set of taxa represented at each locus. State the threshold and its rationale; do not describe a partial-occupancy set as universally single-copy.

4. Interpret the species tree and choose downstream analysis

OrthoFinder’s rooted species tree is inferred from orthogroup gene trees: STAG estimates an unrooted species tree from gene-tree information and STRIDE infers a root from gene-duplication evidence. OrthoFinder does not simply concatenate the alignments of all single-copy genes to produce that tree. Its inferred topology and root depend on the input proteomes, sampled taxa, available gene-tree signal, software version and settings. Treat the tree as an estimate to inspect, not a guaranteed true history.

For a separate phylogenomic analysis, aligned loci can be concatenated and analysed as a partitioned supermatrix, or gene trees can be estimated locus by locus and summarized with a coalescent method such as ASTRAL. These approaches answer related but distinct modeling questions. Concatenation can be useful, but a single-tree model may be inadequate when loci have discordant histories. Coalescent summary methods use gene-tree information and also inherit gene-tree estimation error; they are not automatically superior for every dataset. Compare results and support, and investigate causes of disagreement. Discordance alone does not identify incomplete lineage sorting: duplication, gene flow, model misspecification, alignment error, sampling and weak signal can also contribute.

Worked review task

  1. Record the OrthoFinder version, species filenames, input sequence type and results path.
  2. Choose one orthogroup and count sequences contributed by each species. Label it all-species single-copy only if every species contributes exactly one.
  3. Inspect the matching gene tree and note missing taxa, multiplicity, weakly supported or long branches, and alignment concerns.
  4. Open SpeciesTree_rooted.txt and compare its taxa and topology with the sample design and any independently estimated tree. Record disagreements as questions to investigate, not as proof of a specific evolutionary process.

Deliverable: a short annotated table of candidate groups with per-species copy counts, inclusion decision, evidence and caveats, plus the software/version metadata and the species tree examined.

Common problems and interpretation limits

  • Very few shared single-copy groups: check proteome completeness, annotation quality, taxon sampling and whether the group’s taxonomic scope matches the analysis before relaxing occupancy.
  • Apparent family expansion: check assembly and annotation differences, fragmented or duplicated gene models, identifiers and sampling before proposing biological expansion or adaptation. Comparative counts alone do not establish selection or function.
  • Unexpected tree topology: verify species labels, input versions, outgroup/root assumptions, orthogroup occupancy and gene-tree/alignment quality. A rooted output is not equivalent to independent validation of its root.
  • Concatenation and gene-tree summary disagree: report the disagreement and inspect locus support and model assumptions. Do not attribute it to ILS without additional evidence.
