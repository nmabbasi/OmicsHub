Functional Pathway Analysis with HUMAnN 3

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

Prerequisites: You should have completed a basic metatranscriptomics workflow that produced quality-filtered, ribosomal RNA (rRNA)-depleted mRNA reads (FASTQ or FASTA). You should be comfortable with the command line, understand basic read mapping and gene-family abundance tables, and know how to work with tabular text files (TSV/CSV).

Learning objectives: After following this lesson you will be able to

  • Run HUMAnN 3 to profile active microbial functions from mRNA reads and map gene families to metabolic pathways using the MetaCyc database.
  • Understand HUMAnN's tiered search strategy (nucleotide and translated searches) and the types of output files it produces.
  • Normalize and inspect pathway abundance and coverage outputs and correctly interpret what pathway-level signals indicate (and what they do not prove).
  • Troubleshoot common problems and understand limitations such as database versions, multi-mapping, and compositional data issues.

Why map transcripts to pathways? Biological and computational context

Metatranscriptomics measures the pool of RNA transcripts produced by a microbial community. Mapping transcripts to functional gene families and then to metabolic pathways provides a higher-level view of which biochemical processes are actively transcribed in the community. This approach helps answer questions such as: which metabolic routes are currently expressed, which species contribute to those routes, and how pathway expression changes across conditions.

Important caveats: transcriptional activity does not equal enzymatic activity. Detection of mRNA for pathway genes is evidence of expression but not direct proof of metabolic flux or reaction rates. Also, metatranscriptomes are compositional: reported abundances depend on library depth and experimental protocol; appropriate normalization and statistical modeling are essential for valid comparisons.

Reproducible workflow (step-by-step)

Below is a sequential, reproducible workflow using HUMAnN 3. The example assumes you already have rRNA-depleted reads in compressed FASTQ. Replace sample names and paths to match your environment. Each command lists expected inputs and outputs.

Files you should have before starting

  • Input reads: data/sampleA_mRNA.fastq.gz (rRNA-depleted, quality-filtered)
  • Optional taxonomic profile: metaphlan/sampleA_profile.tsv (from MetaPhlAn 3) — if you have this, HUMAnN will skip its internal taxonomic profiling step.
  • Output directory: humann_out/ (will be created by HUMAnN)

1) Run HUMAnN 3

HUMAnN 3 performs a tiered search: a nucleotide-level search against strain pangenomes (fast) and a translated protein search for unmapped reads (sensitive). Provide the path to a taxonomic profile if you have one to speed execution and ensure reproducibility.

humann --input data/sampleA_mRNA.fastq.gz \
       --output humann_out/sampleA/ \
       --threads 12 \
       --metaphlan-options "--input_type fastq" \
       --taxonomic-profile metaphlan/sampleA_profile.tsv

Inputs: data/sampleA_mRNA.fastq.gz (FASTQ). Optional: metaphlan/sampleA_profile.tsv (MetaPhlAn taxonomic profile). Outputs (created under humann_out/sampleA/):

  • sampleA_genefamilies.tsv — gene-family abundances (UniRefX family IDs).
  • sampleA_pathabundance.tsv — pathway abundance table (MetaCyc pathway IDs and names).
  • sampleA_pathcoverage.tsv — pathway coverage values (fraction or completeness metric).
  • log files (humann logs, run parameters).

2) Rename and organize results for multi-sample projects

If you are processing multiple samples in a loop or with a workflow manager, collect per-sample HUMAnN outputs into a single results directory. Example command renames and moves files into a consistent structure:

# Example (run once per sample)
mkdir -p humann_out/merged_tables/
cp humann_out/sampleA/sampleA_pathabundance.tsv humann_out/merged_tables/sampleA_pathabundance.tsv
cp humann_out/sampleA/sampleA_pathcoverage.tsv  humann_out/merged_tables/sampleA_pathcoverage.tsv
cp humann_out/sampleA/sampleA_genefamilies.tsv  humann_out/merged_tables/sampleA_genefamilies.tsv

3) Join per-sample tables into a matrix

HUMAnN includes helper utilities to join tables across samples. These produce a single table with pathway IDs as rows and samples as columns.

# Join pathway abundance tables (run from humann_out/merged_tables)
humann_join_tables --input . --file_name sampleA_pathabundance.tsv --output merged_pathabundance.tsv --name-by sample
humann_join_tables --input . --file_name sampleA_pathcoverage.tsv --output merged_pathcoverage.tsv --name-by sample
humann_join_tables --input . --file_name sampleA_genefamilies.tsv --output merged_genefamilies.tsv --name-by sample

Inputs: the per-sample TSVs in humann_out/merged_tables/. Outputs: merged tables in the current directory (merged_pathabundance.tsv etc.).

4) Normalize for visualization or downstream methods

HUMAnN reports different abundance units (copies per million, reads per kilobase, etc.). Choose normalization carefully depending on the downstream method.

# Example: create copies-per-million (CPM) normalized pathway table for plotting
humann_renorm_table --input merged_pathabundance.tsv \
                    --output merged_pathabundance_cpm.tsv \
                    --units cpm

Inputs: merged_pathabundance.tsv. Output: merged_pathabundance_cpm.tsv (values scaled to copies per million). Do not treat CPM-normalized values as raw counts for count-based models like DESeq2.

5) (Optional) Split stratified tables by species

HUMAnN outputs stratified values (e.g., PATHWAY and PATHWAY|Species). You can separate taxon-stratified contributions using provided utilities or by simple text parsing if you prefer species-level matrices for targeted analyses.

# Example: Unstratify pathway abundance to separate community-level vs. stratified contributions
humann_split_stratified_table --input merged_pathabundance.tsv \
                              --output merged_pathabundance_unstratified.tsv

Input: merged_pathabundance.tsv. Output: merged_pathabundance_unstratified.tsv where stratified entries have been separated into distinct columns.

Output inspection and interpretation

HUMAnN produces three main categories of output: gene-family abundances (UniRef-based), pathway abundances (MetaCyc-based), and pathway coverage. Here is how to interpret each and what to beware of.

What to look for

  • Pathway abundance (pathabundance.tsv): A numeric estimate of pathway-level expression. Higher values indicate more transcript evidence mapped to the constituent gene families for that pathway.
  • Pathway coverage (pathcoverage.tsv): A measure of completeness: how many key steps in the pathway are supported by detected gene families. Low coverage with a high abundance can indicate a few highly expressed genes but not the full pathway.
  • Gene-family table (genefamilies.tsv): Use this to trace which specific UniRef families drive pathway signals and to evaluate multi-mapping or ambiguous assignments.
  • Stratified outputs: Entries like PATHWAY|Escherichia_coli indicate species-specific contribution. Compare stratified and unstratified totals to confirm the community vs species-specific roles.

What a plausible result means

Example interpretation (conceptual): if a glycolysis pathway shows moderate-to-high abundance and high coverage across samples, the community is transcribing most glycolytic enzymes, suggesting active sugar catabolism at the transcriptional level. If most of that pathway is stratified to a single taxon, it suggests that taxon is the dominant transcriber of glycolysis genes.

What the outputs do NOT prove

  • Transcript detection does not confirm protein abundance, enzyme activity, or metabolic flux. Post-transcriptional regulation and enzyme kinetics are not measured here.
  • High pathway abundance may be driven by a single highly expressed gene shared among multiple pathways, so examine gene-family contributions and coverage.
  • Cross-sample comparisons require appropriate normalization and statistical modeling; raw normalized values are not sufficient for robust inference without accounting for compositionality, batch effects, and library size.

Troubleshooting

Below are common symptoms, likely causes, and recommended fixes.

Symptom: HUMAnN runs very slowly or appears stalled

  • Likely cause: DIAMOND translated search on large unmapped read sets; insufficient threads or IO bottlenecks.
  • Fixes:
    • Provide a pre-computed MetaPhlAn profile with --taxonomic-profile to skip the internal taxonomic profiling.
    • Increase --threads and ensure scratch disk has enough space and good IO performance.
    • Limit DIAMOND sensitivity options if you need speed over sensitivity (consult HUMAnN docs), but be aware this trades sensitivity for time.

Symptom: Most reads map to "unclassified" and pathway coverage is low

  • Likely cause: samples contain novel taxa or poorly represented genomes in the pangenome/UniRef databases, or mRNA reads are too short/low-quality for confident mapping.
  • Fixes:
    • Check read length and quality; consider re-trimming or adjusting minimum read length before HUMAnN.
    • If many reads are unclassified, inspect DIAMOND results (if saved) and consider updating reference databases (UniRef, MetaCyc) or supplementing with custom protein databases relevant to your environment.
    • Use appropriate DIAMOND settings (e-value, sensitivity) to increase detection, but document changed parameters.

Symptom: Unexpected taxonomic assignments in stratified outputs

  • Likely cause: shared gene families across taxa, multi-mapping, or inaccurate taxonomic profile used to build pangenomes.
  • Fixes:
    • Inspect gene-family rows to see if the UniRef entries are conserved across taxa; review the species profile used by HUMAnN.
    • Run MetaPhlAn independently on the same reads to confirm the taxonomic profile.
    • Be conservative in attributing pathway function to a species when stratified contributions are small or when gene families are highly conserved.

Limitations, version and reference-data caveats, and responsible use

Limitations to consider when planning or reporting HUMAnN-based metatranscriptomic analyses:

  • Database versions matter: MetaCyc releases and UniRef clusters are periodically updated. Always record the exact database versions (MetaCyc release date, UniRef90/50 version) and HUMAnN version used. Differences across database versions can change pathway mappings and abundances.
  • Stratification ambiguity: Gene-family to species mappings can be ambiguous for conserved genes. Use stratified outputs conservatively and validate key assignments with additional evidence (e.g., genome bin contigs, targeted qPCR).
  • Compositional data: Metatranscriptomic libraries are compositional; relative abundances can be misleading if interpreted as absolute expression differences. Use proper normalization and, if possible, spike-ins or internal standards to estimate absolute transcript abundances.
  • Biological interpretation: Presence of transcripts is suggestive of biological activity but not definitive. Combine metatranscriptomics with metaproteomics, metabolomics, or activity assays when claiming functional activity or metabolic flux.
  • Reproducibility: Share exact command lines, HUMAnN and database versions, and sample metadata to enable reproducible interpretation.

Next-step checklist

  1. Confirm you have recorded HUMAnN version and the MetaCyc/UniRef database versions used.
  2. Inspect genefamilies.tsv to identify which UniRef families drive pathway signals of interest.
  3. Examine pathcoverage.tsv: prioritize pathways with both high abundance and high coverage for interpretation.
  4. Choose appropriate normalization for your downstream analysis (CPM for visualization; raw counts or appropriate count-like values + DESeq2 for differential testing, following method-specific input rules).
  5. For key findings, validate with complementary approaches (targeted qPCR, metaproteomics, metabolomics) before asserting functional activity or ecological roles.
