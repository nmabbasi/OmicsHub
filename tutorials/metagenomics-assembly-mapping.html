Metagenomics Assembly

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

Learning objectives

  • Design and execute a basic metagenomic assembly pipeline using metaSPAdes (SPAdes metagenome mode).
  • Remove host-derived reads (host screening) and retain non-host paired reads for assembly.
  • Map reads back to assembled contigs with BWA (Burrows–Wheeler Aligner) and summarize support with Samtools.
  • Interpret coverage patterns and assembly support; identify likely assembly artefacts and next steps.

Prerequisites

  • Familiarity with the Unix command line (basic navigation, pipes, and redirection).
  • Basic knowledge of paired-end sequencing and FASTQ format.
  • Completion of a read quality-control tutorial (trimming, adapter removal) so that inputs are cleaned reads: sample_R1.fastq.gz and sample_R2.fastq.gz.
  • Installed tools (recommended via conda/mamba): spades (includes metaSPAdes), bwa, samtools, and optionally igv (for visualization).

Why assembly and mapping matter in metagenomics

Shotgun metagenomics sequences DNA from an entire microbial community. Reads are short fragments (commonly 100–300 base pairs) sampled from many genomes at highly variable abundances. Two complementary operations are central to many analyses:

  • De novo assembly reconstructs contiguous sequences (contigs) from reads without using a single reference. Assemblies can reveal novel genes, genome fragments, and help bin genomes.
  • Read mapping back to contigs evaluates how well the observed reads support the assembled contigs. Mapping provides per-contig coverage, helps detect chimeric contigs, and quantifies abundance.

Proper host read removal is often essential for host-associated samples (for privacy, to save computational resources, and to avoid misassembly driven by dominant host sequences). Mapping reads back to the assembled contigs also provides a reproducible audit trail documenting which contigs are supported by reads.

Inputs and assumptions

This workflow assumes you have these files in your working directory:

  • sample_R1.fastq.gz — forward reads (paired-end)
  • sample_R2.fastq.gz — reverse reads (paired-end)
  • For host removal (if applicable): a host reference FASTA, named host_ref.fa. Preserve the source URL and checksum in your project manifest.

All commands below use explicit input and output paths. Adjust thread (-t/-@) and memory parameters for your environment. Do not run destructive commands (like rm) here; if you choose to remove files, do so intentionally and after confirming paths.

Reproducible sequential workflow

1. Prepare tools (example using mamba/conda)

# Create or activate a conda environment, then install tools
mamba create -n metaenv -y python=3.11 spades bwa samtools igv -c conda-forge -c bioconda
mamba activate metaenv

# Verify versions (record them for reproducibility)
spades.py --version
bwa
samtools --version

Record the exact versions printed by these commands in your project manifest for future reference.

2. Host read removal (optional but recommended for host-associated samples)

Purpose: remove read pairs where either mate maps to the host to protect privacy and reduce downstream misassembly.

# 2.1 Download a trusted host reference and verify
curl -L -o host_ref.fa.gz "https://ftp.ncbi.nlm.nih.gov/genomes/all/GCF/000/001/405/GCF_000001405.40_GRCh38.p14/GCF_000001405.40_GRCh38.p14_genomic.fna.gz"
sha256sum host_ref.fa.gz  # copy the checksum into your manifest
gunzip host_ref.fa.gz
# Now host_ref.fa is present (document its URL and checksum)

# 2.2 Index the host reference for BWA
bwa index host_ref.fa

# 2.3 Map reads to host and save alignments (sorted BAM)
bwa mem -t 8 host_ref.fa sample_R1.fastq.gz sample_R2.fastq.gz \
  | samtools sort -@ 4 -o host_mapped.bam

samtools index host_mapped.bam

# 2.4 Extract read pairs where both mates are unmapped (retain proper pairing)
# -f 12 keeps reads where both mates are unmapped; -F 256 excludes secondary alignments.
samtools view -b -f 12 -F 256 host_mapped.bam \
  | samtools sort -n -@ 4 -o nonhost.name_sorted.bam

# 2.5 Convert name-sorted BAM back to paired FASTQ
samtools fastq -n \
  -1 microbial_R1.fastq.gz \
  -2 microbial_R2.fastq.gz \
  -0 /dev/null -s /dev/null \
  nonhost.name_sorted.bam

# Record read counts before/after:
samtools view -c -f 1 sample_mapped.bam || true  # (if you had a pre-existing BAM)
# Alternatively, count FASTQ reads:
zcat sample_R1.fastq.gz | echo $((`wc -l`/4))  # approximate pairs before
zcat microbial_R1.fastq.gz | echo $((`wc -l`/4))  # after

What these commands produce:

  • host_mapped.bam — primary alignment file for host mapping (sorted).
  • nonhost.name_sorted.bam — name-sorted BAM of read pairs where both mates were unmapped.
  • microbial_R1.fastq.gz and microbial_R2.fastq.gz — paired FASTQ files of putatively non-host reads, to use for assembly.

Notes: if your sample is environmental and unlikely to contain host DNA, document the reasoning if you skip host removal.

3. De novo metagenomic assembly with metaSPAdes

metaSPAdes is a SPAdes mode tuned for metagenomes; it attempts to manage uneven coverage and strain variation. Provide cleaned, host-filtered paired reads as input.

# Run metaSPAdes
spades.py --meta \
  -1 microbial_R1.fastq.gz \
  -2 microbial_R2.fastq.gz \
  -o spades_output \
  -t 16 -m 64

# Important output files in spades_output/:
# - contigs.fasta       : assembled contigs (primary file to inspect)
# - scaffolds.fasta     : scaffolded sequences (if scaffolding ran)
# - spades.log          : logging and assembly parameters
# - params.txt          : parameters used (record this)

Be explicit about output: spades_output/contigs.fasta is the main assembled sequence file to use for downstream mapping and binning. Keep the contents of spades_output/params.txt with your project record.

4. Map reads back to assembled contigs

Mapping reads back to contigs quantifies support per contig and reveals coverage variation that may indicate assembly errors or multiple strains.

# 4.1 Index assembled contigs for BWA
bwa index spades_output/contigs.fasta

# 4.2 Map the same non-host reads to contigs
bwa mem -t 8 spades_output/contigs.fasta microbial_R1.fastq.gz microbial_R2.fastq.gz \
  | samtools sort -@ 4 -o reads_to_contigs.bam

samtools index reads_to_contigs.bam

# 4.3 Summaries: overall mapping stats and per-contig depth
samtools flagstat reads_to_contigs.bam > reads_to_contigs.flagstat.txt
samtools idxstats reads_to_contigs.bam > reads_to_contigs.idxstats.txt

# Per-base depth across contigs (tab-delimited: contig, position, depth)
samtools depth -a reads_to_contigs.bam > contig_depth.tsv

# Per-contig average coverage (simple awk-based aggregation)
awk '{cov[$1]+= $3; len[$1]++} END{for(c in cov) print c, cov[c]/len[c]}' contig_depth.tsv \
  > contig_mean_coverage.tsv

Files produced:

  • reads_to_contigs.bam — sorted BAM of alignments of reads to contigs.
  • reads_to_contigs.flagstat.txt — mapping summary (percent mapped, paired reads, etc.).
  • contig_depth.tsv — base-level depth across all contigs (can be large).
  • contig_mean_coverage.tsv — per-contig mean coverage estimate (simple average).

5. Visualize assemblies (optional but recommended)

IGV (Integrative Genomics Viewer) can display BAM alignments against the contig FASTA. Prepare an IGV session or use the desktop app to load:

  • Reference: spades_output/contigs.fasta (ensure it is indexed by the IGV/FAI index function: samtools faidx).
  • Alignment: reads_to_contigs.bam and its index reads_to_contigs.bam.bai.
# Create FASTA index for contigs (IGV and samtools need it)
samtools faidx spades_output/contigs.fasta
# Launch IGV (if installed locally)
# igv.sh or igv depends on your platform; alternatively export the files for local visualization.

Output inspection and interpretation

After running the mapping, inspect these key files:

  • reads_to_contigs.flagstat.txt: reports the total number of reads aligned, fraction mapped, and properly paired reads. High mapping percentage to contigs suggests the assembly captured many reads; low mapping percentage indicates many reads did not assemble into contigs (common in very complex or low-depth samples).
  • contig_mean_coverage.tsv: per-contig average coverage. Contigs with extremely low average coverage (for example, average <5x depending on read length and sample complexity) are weaker evidence and more likely to be assembly artefacts.
  • contig_depth.tsv: used to inspect coverage variation along a contig. Sharp drops or abrupt changes can indicate chimeric joins or misassemblies.
  • spades_output/contigs.fasta: inspect top contigs for length distribution. Many short contigs (<500 bp) are common in metagenomes and may be less informative.

What a plausible result means (examples of interpretation):

  • Contigs with consistent, even coverage and a substantial length (e.g., several kilobases) are more likely to represent true genomic sequence from a medium- to high-abundance organism.
  • Contigs with very high coverage spikes may derive from highly conserved sequences (e.g., rRNA, mobile elements) or collapsed repeats; treat these carefully.
  • Contigs supported by few or single paired reads at junctions are suspect; inspect paired-read orientation and insert sizes in IGV to detect misjoins.

What the mapping does NOT prove:

  • Read mapping does not guarantee the contig is a complete or correctly binned genome—it only shows reads align to that sequence.
  • High coverage alone does not confirm correct assembly of repeats or strain-resolved sequences—complex strain mixtures can collapse into a single consensus contig.
  • Absence of mapping for some reads may be due to low complexity regions, contaminants, or sequences too divergent to assemble, not necessarily a failed experiment.

Troubleshooting

Symptom: Very low fraction of reads map back to contigs (flagstat shows low mapped percentage).

  • Likely causes:
    • Insufficient sequencing depth for the community complexity.
    • Excessive filtering or accidental trimming losses prior to assembly.
    • Large fraction of host reads remained or were erroneously removed.
  • Fixes:
    • Confirm pre-assembly read counts and compare with post-screening counts. Re-run host-screening with different alignment stringency if needed.
    • Consider co-assembling multiple related samples if appropriate to boost coverage of rare members (but document the approach clearly).
    • Evaluate alternative assemblers or adjust k-mer sizes in SPAdes (see SPAdes documentation for advanced tuning).

Symptom: Many short contigs and few long contigs.

  • Likely causes:
    • High community complexity and low per-genome coverage.
    • Conservative assembler settings or aggressive read trimming.
  • Fixes:
    • Increase sequencing depth or enrich target organisms if possible.
    • Adjust SPAdes parameters: try different k-mer sizes (SPAdes picks defaults, but explicit k values can help), or try alternative assemblers specialized for low-coverage metagenomes.

Symptom: Contigs show abrupt coverage changes or conflicting paired-read orientations in IGV.

  • Likely causes: chimeric assemblies or misjoins (e.g., assembler joined sequences from different strains/genomes).
  • Fixes:
    • Split suspect contigs at low-coverage regions or re-assemble with stricter parameters.
    • Use long-read sequencing or proximity ligation (Hi-C) data if available to disambiguate structural joins.

Limitations, caveats, and responsible use

Limitations and caveats:

  • Assemblies from short-read metagenomes frequently collapse closely related strains into consensus contigs; strain resolution is limited without long reads or linked-read data.
  • metaSPAdes performs well on many datasets but can be resource intensive; monitor memory and CPU usage and save logs and params.txt for reproducibility.
  • Host removal relies on the quality and completeness of the host reference. If the host reference is incomplete, some host-derived reads may persist in the microbial dataset and cause spurious contigs.

Responsible-use notes:

  • For human-derived samples, do not upload raw reads or assembled contigs containing human sequences to public repositories without clear approvals and appropriate consent. Maintain a manifest recording host-reference sources and checksums.
  • Document every major step (commands, versions, input file checksums) in a project log so results can be audited and reproduced.

Next-step checklist

  • Save the following in a results directory and your project manifest:
    • spades_output/contigs.fasta
    • reads_to_contigs.bam, reads_to_contigs.bam.bai
    • reads_to_contigs.flagstat.txt, contig_mean_coverage.tsv
    • Tool version outputs and host reference URL/checksum
  • Inspect contigs with high and low coverage in IGV to validate suspicious joins.
  • Consider downstream analyses: binning (e.g., with MetaBAT, MaxBin), taxonomic classification (e.g., with Kraken2, Kaiju), and functional annotation (e.g., Prokka, eggNOG mapper).
  • If necessary, iterate: refine host-screening thresholds, adjust SPAdes k-mer choices, or incorporate long-read data to resolve ambiguity.
