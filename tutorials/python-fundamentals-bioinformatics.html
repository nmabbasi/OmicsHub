Sequence files (FASTA) often wrap DNA across multiple lines, mix uppercase and lowercase letters for repeat masking, and include ambiguous N bases or alignment dashes. Shell one-liners like grep and awk break easily on multi-line records, so this lab teaches core Python 3 constructs by building a clean, constant-memory FASTA summary script from scratch. Readers following the R-first track can jump to R and Tidyverse Fundamentals or open the collapsible base-R comparison in Step 5.

Format: Hands-on lab. Builds a complete Python 3 standard-library FASTA validator and summary CLI from individual language building blocks, with locally executed Python 3.12 outputs at every step and no external package requirement.

What you will build and prerequisites

By the end of this tutorial, you will take raw multi-record nucleotide sequences and produce a checked CSV summary table (id, length, gc_fraction, valid) using a reusable script (scripts/compute_fasta_stats.py).

  • Skills practiced: normalizing sequence strings and computing reverse complements, writing reusable functions with set validation and explicit GC denominators, counting k-mers with dictionaries, streaming large files with yield generators, and isolating optional packages in a local virtual environment.
  • Prerequisites and time: basic terminal navigation (Command-Line Navigation and Micromamba Environments), Python 3.10 or newer (tested locally on Python 3.12.3), and roughly 25 minutes. No prior Python experience is required.
  • How to follow along: run Steps 1-4 in an interactive Python prompt (type python3 in your terminal, or save each snippet to a small test file and run python3 test.py), then assemble the full project in Step 5.

Step 1: Strings, slicing, and reverse complements

DNA is double-stranded, and sequencing primers or reference downloads routinely arrive with trailing newlines, spaces, or lowercase soft-masked bases (used by RepeatMasker to mark repetitive DNA without deleting it). Before matching motifs or computing base composition, normalize whitespace and case, and know how to reverse-complement a primer sequence.

Python strings are immutable (unchangeable in place) sequences with zero-based indexing: index 0 is the first base, and slicing seq[0:3] returns characters at indices 0, 1, and 2 (stopping before 3). Reversing uses slice step -1 (seq[::-1]), and str.maketrans() builds a fast 1-to-1 character lookup table for complementing bases:

raw_seq = "  acgtacgtnnacgt \n"
seq = "".join(raw_seq.split()).upper()
complement_table = str.maketrans("ACGTN", "TGCAN")
rev_comp = seq.translate(complement_table)[::-1]

print(f"Normalized: {seq} (length = {len(seq)}, first_codon = {seq[:3]})")
print(f"Reverse complement: {rev_comp}")

Observed output (Python 3.12.3):

Normalized: ACGTACGTNNACGT (length = 14, first_codon = ACG)
Reverse complement: ACGTNNACGTACGT

Key lines explained and check:

  • "".join(raw_seq.split()) vs raw_seq.strip(): .strip() trims whitespace only at the start and end, whereas .split() splits on all whitespace (including internal newlines in wrapped FASTA blocks) and "".join(...) stitches the chunks back together.
  • Order matters: call .upper() before .translate(complement_table). Because str.maketrans("ACGTN", "TGCAN") maps only uppercase letters, any lowercase a left behind would pass through untranslated.
  • Check: confirm len(seq) is 14 and rev_comp begins with ACGTNN. Notice that if raw_seq contained RNA U or a dash -, translate() would leave it unchanged, which is why Step 2 validates the alphabet explicitly.

Step 2: Functions, sets, and the GC denominator trap

GC content (the proportion of G and C bases) influences PCR primer annealing temperature, sequencing coverage, and CpG-island annotation. A common reproducibility bug occurs when two tools report different GC fractions on the same sequence because one includes ambiguous N bases in the denominator and the other drops them.

To prevent silent errors, put validation and calculation into named functions (def) and store allowed characters in a set. Checking ch in VALID_BASES on a set runs in constant average time (O(1)) rather than scanning a list element by element. Notice also the bool(seq) guard: in Python, all(...) on an empty string returns True (vacuous truth), so bool(seq) ensures empty records return False instead:

VALID_BASES = set("ACGTN")

def is_valid_dna(seq: str) -> bool:
    return bool(seq) and all(ch in VALID_BASES for ch in seq)

def gc_fraction(seq: str, include_n: bool = True) -> float:
    denom = len(seq) if include_n else sum(1 for ch in seq if ch in "ACGT")
    if denom == 0:
        return 0.0
    return sum(1 for ch in seq if ch in "GC") / denom

seq = "ACGTACGTNNACGT"
print(
    f"Valid: {is_valid_dna(seq)} | "
    f"GC (with N): {gc_fraction(seq, True):.5f} | "
    f"GC (A/C/G/T only): {gc_fraction(seq, False):.5f}"
)

Observed output (Python 3.12.3):

Valid: True | GC (with N): 0.42857 | GC (A/C/G/T only): 0.50000

Why the two numbers differ: seq has 6 G/C bases, 6 A/T bases, and 2 N bases. Dividing by all 14 bases gives 6 / 14 = 0.42857; dividing by only called A/C/G/T bases gives 6 / 12 = 0.50000. In Biopython (>= 1.80), Bio.SeqUtils.gc_fraction(seq) (which replaced the older 0-100 GC() function) defaults to ambiguous="remove", excluding N from the denominator (0.50000), whereas ambiguous="ignore" keeps N in the full length (0.42857). Also check the if denom == 0 guard: passing "NNNN" with include_n=False returns 0.0 cleanly instead of crashing with ZeroDivisionError.

Step 3: Loops and dictionaries for k-mer counting

A k-mer is a DNA substring of fixed length k (for example, a 4-mer is 4 bases long). Genome assemblers, metagenomic classifiers, and motif-enrichment tools count k-mers across reads using hash tables. In Python, a dictionary (dict) maps each unique k-mer string to its integer count.

For a sequence of length 14 and k = 4, valid start indices run from 0 through 10, giving len(seq) - k + 1 = 11 overlapping windows. Skipping any window containing "N" (such as "GTNN" or "NNAC") avoids polluting the table with uncalled bases:

seq = "ACGTACGTNNACGT"
k = 4
kmers: dict[str, int] = {}
for i in range(len(seq) - k + 1):
    kmer = seq[i : i + k]
    if "N" not in kmer:
        kmers[kmer] = kmers.get(kmer, 0) + 1

print("Unambiguous 4-mers:", kmers)

Observed output (Python 3.12.3):

Unambiguous 4-mers: {'ACGT': 3, 'CGTA': 1, 'GTAC': 1, 'TACG': 1}

Common beginner error (KeyError): Writing kmers[kmer] += 1 before a key exists in kmers raises KeyError: 'ACGT'. Using kmers.get(kmer, 0) + 1 safely defaults unseen keys to 0 (for larger scripts, collections.Counter from the standard library also handles this automatically).

Step 4: Streaming large FASTA files with generators (yield)

Reading an entire FASTA file into a Python list works for three toy sequences, but the uncompressed human reference genome (GRCh38) is roughly 3.1 GB, and sequencing read sets can be much larger. A generator function replaces return with yield: it pauses after producing one (header, sequence) record and resumes only when the for loop asks for the next record, keeping only one sequence in RAM at a time.

Run this small in-memory example (using io.StringIO to simulate a file) to see how yield behaves and why a generator can only be consumed once:

import io

fasta_stream = io.StringIO(">chr1_frag\nACGT\nACGT\n>chr2_frag\nTTAA\n")

def iter_toy_fasta(handle):
    header = None
    chunks: list[str] = []
    for raw in handle:
        line = raw.strip()
        if not line:
            continue
        if line.startswith(">"):
            if header is not None:
                yield header, "".join(chunks)
            header = line[1:].strip()
            chunks = []
        else:
            chunks.append(line)
    if header is not None:
        yield header, "".join(chunks)

records = iter_toy_fasta(fasta_stream)
for header, seq_piece in records:
    print(f"{header}: {len(seq_piece)} bp -> {seq_piece}")
print("Second pass count:", len(list(records)))

Observed output (Python 3.12.3):

chr1_frag: 8 bp -> ACGTACGT
chr2_frag: 4 bp -> TTAA
Second pass count: 0

Watch out for single-pass exhaustion: Because records streams on demand rather than storing data in memory, looping over the same records object a second time yields 0 items. If you need multiple passes over a file, call the generator function again on a freshly opened file handle.

Step 5: Complete FASTA-to-CSV command-line workflow

Now combine Steps 1-4 into a standalone command-line script that reads any FASTA file, checks every record against the A/C/G/T/N alphabet, and writes a clean CSV summary.

1. Set up the project and create the starter FASTA fixture

mkdir -p ~/projects/python-bioinfo/data/raw ~/projects/python-bioinfo/scripts ~/projects/python-bioinfo/outputs
cd ~/projects/python-bioinfo

cat > data/raw/example.fasta <<'EOF'
>seq1
ACGTACGTNNACGT
>seq2
acgtacgtacgtacgtacgt
>seq3
AGCTTAGC--NNNN
EOF

cat data/raw/example.fasta

seq2 is lowercase (simulating soft-masked repeats) and seq3 intentionally includes alignment gap characters (--) so you can confirm that invalid records are flagged (valid=no, blank gc_fraction) rather than silently altered.

2. Optional isolated environment for third-party packages

The main CLI script in Subsection 3 uses only Python's built-in standard library (csv, pathlib, sys), so you can skip package installation completely unless you want Biopython for Subsection 5 or pytest for unit tests. When you do install third-party packages, first check whether the project already uses a dependency manager (such as uv.lock, pyproject.toml for Poetry/uv, Pipfile, or environment.yml for Conda/Micromamba) and match that tool instead of running a global pip install. For a plain project directory with no existing lockfile, create a local .venv and invoke .venv/bin/pip and .venv/bin/python explicitly:

# Check if an existing dependency manager or lockfile is already configured
ls uv.lock poetry.lock Pipfile environment.yml requirements.txt pyproject.toml 2>/dev/null || true

# Isolated venv + pip workflow (only needed for optional third-party packages)
python3 -m venv .venv
# Optional only if you want Subsection 5's Biopython comparison:
# .venv/bin/pip install biopython
# .venv/bin/pip freeze > requirements.txt

To reproduce that environment on another machine later, create .venv and run .venv/bin/pip install -r requirements.txt (or use micromamba as covered in Micromamba Environments for Bioinformatics).

3. Save scripts/compute_fasta_stats.py

#!/usr/bin/env python3
"""Read FASTA records, validate A/C/G/T/N after normalization, and write CSV."""
import csv
from pathlib import Path
import sys

VALID_BASES = set("ACGTN")

def normalize(seq: str) -> str:
    return "".join(seq.split()).upper()

def is_valid_dna(seq: str) -> bool:
    return bool(seq) and all(ch in VALID_BASES for ch in seq)

def gc_fraction(seq: str) -> float:
    if not seq:
        return 0.0
    return sum(1 for ch in seq if ch in ("G", "C")) / len(seq)

def fasta_records(path: Path):
    with open(path, "r", encoding="utf-8") as fh:
        name = None
        parts: list[str] = []
        for raw in fh:
            line = raw.strip()
            if not line:
                continue
            if line.startswith(">"):
                if name is not None:
                    yield name, "".join(parts)
                name = line[1:].strip()
                if not name:
                    raise ValueError("FASTA header is empty")
                parts = []
            elif name is None:
                raise ValueError("Sequence text found before the first FASTA header")
            else:
                parts.append(line)
        if name is not None:
            yield name, "".join(parts)

def main() -> None:
    if len(sys.argv) != 3:
        print("Usage: python3 scripts/compute_fasta_stats.py INPUT.fasta OUTPUT.csv", file=sys.stderr)
        sys.exit(2)
    in_path = Path(sys.argv[1])
    out_path = Path(sys.argv[2])
    if in_path.resolve() == out_path.resolve():
        print("Input and output paths must be different", file=sys.stderr)
        sys.exit(2)
    out_path.parent.mkdir(parents=True, exist_ok=True)
    with open(out_path, "w", newline="", encoding="utf-8") as out_fh:
        writer = csv.DictWriter(out_fh, fieldnames=["id", "length", "gc_fraction", "valid"])
        writer.writeheader()
        for header, seq in fasta_records(in_path):
            seq_norm = normalize(seq)
            valid = is_valid_dna(seq_norm)
            writer.writerow({
                "id": header,
                "length": len(seq_norm),
                "gc_fraction": f"{gc_fraction(seq_norm):.5f}" if valid else "",
                "valid": "yes" if valid else "no",
            })

if __name__ == "__main__":
    main()

Defensive checks built into this script: main() exits with status 2 if you pass the wrong number of arguments or accidentally pass the input FASTA path as the output CSV path (preventing file clobbering), and fasta_records() raises a clear ValueError on empty headers (>) or sequence lines appearing before any header. Note that line[1:].strip() keeps the full header string; if your FASTA headers include descriptions after a space (for example >TP53_ENST00000269305 Homo sapiens) and you want only the accession token, change that line to line[1:].strip().split()[0] to match Biopython's rec.id.

seq2,20,0.50000,yes

5. Optional Biopython and base-R counterparts

When Biopython is installed inside your isolated environment (.venv/bin/python), Bio.SeqIO.parse(path, "fasta") handles FASTA parsing and header splitting (rec.id vs rec.description) while leaving alphabet and GC-denominator policies explicit. For very large FASTA files with millions of records, Biopython also provides Bio.SeqIO.FastaIO.SimpleFastaParser, which yields plain (title, sequence) string tuples without allocating SeqRecord objects:

from Bio import SeqIO

valid_bases = set("ACGTN")
for rec in SeqIO.parse("data/raw/example.fasta", "fasta"):
    seq = "".join(str(rec.seq).split()).upper()
    valid = bool(seq) and all(base in valid_bases for base in seq)
    gc_text = f"{sum(1 for b in seq if b in 'GC') / len(seq):.5f}" if valid else ""
    print(rec.id, len(seq), gc_text, "yes" if valid else "no")

Example output (illustrative; requires Biopython):

seq1 14 0.42857 yes
seq2 20 0.50000 yes
seq3 14  no

When to use shell tools vs standard-library Python vs Biopython

Choose the lightest tool that keeps your assumptions visible and testable:

ApproachBest suited forTrade-offs
Shell (grep, awk, seqkit)Quick header counts (grep -c '^>'), fast filtering, and one-off CLI checks on clean FASTA/FASTQ.Multi-line wrapping and custom per-base validation are error-prone in plain awk.
Standard-library PythonCustom validation rules, HPC or container scripts with zero third-party dependencies, and tailored CSV/TSV summaries.Supports only the formats you write or wrap yourself (for example FASTA, not GenBank or BAM).
Biopython (SeqIO, SeqUtils)Multi-format parsing (FASTA, FASTQ, GenBank, EMBL), IUPAC-aware gc_fraction(), and record metadata handling.Requires an isolated environment dependency; default gc_fraction(..., ambiguous="remove") differs from total-length denominators.

Practice exercise: accept IUPAC codes while still rejecting gaps

Suppose your FASTA file comes from a consensus sequence containing IUPAC ambiguity codes (R, Y, S, W, K, M, B, D, H, V) in addition to A, C, G, T, N, plus Windows carriage returns (\r\n), and you still want to reject gap dashes (-). Update the allowed-base set and test it on " acgtRYsw-n \r\n" before opening the solution.

Show solution and locally run output 
IUPAC_DNA = set("ACGTNRYSWKMBDHV")
test_seq = "  acgtRYsw-n \r\n"
cleaned = "".join(test_seq.split()).upper()
has_gap = "-" in cleaned
valid_iupac = bool(cleaned) and all(ch in IUPAC_DNA for ch in cleaned)
print(f"Cleaned: {cleaned} | valid_iupac: {valid_iupac} | has_gap: {has_gap}")

Observed output (Python 3.12.3):

Cleaned: ACGTRYSW-N | valid_iupac: False | has_gap: True

Because "-" is not in IUPAC_DNA, valid_iupac returns False while .split() strips both spaces and \r\n cleanly. Removing - (only when appropriate for unaligned sequence summaries) flips valid_iupac to True.

Common errors, checkpoints, and scope limits

  • UnicodeDecodeError on input: the file uses non-UTF-8 encoding (such as Windows-1252) or is gzipped/binary. Inspect it first with file input.fasta and head -n 5 input.fasta; decompress .fa.gz files or convert encoding with iconv -f WINDOWS-1252 -t UTF-8 input.fasta -o output.fasta.
  • Many records flagged valid=no: the file contains alignment gaps (-), IUPAC ambiguity codes outside ACGTN, RNA U bases, or FASTQ quality lines. Decide which alphabet belongs in VALID_BASES and document that choice.
  • Header-only or empty CSV: confirm the FASTA has at least one > header line using grep -c '^>' data/raw/example.fasta. The parser raises ValueError if sequence lines appear before the first > header, while a completely empty file writes a header-only CSV.
  • GC mismatch against external tools: check whether the comparison tool excludes N from the denominator (Biopython's default ambiguous="remove") or keeps N in total length (this script and Biopython's ambiguous="ignore"). Also compare values only across the same reference genome assembly and soft-masking policy.
  • Scope of this script: fasta_records() yields one record at a time so total memory stays proportional to the longest single chromosome or contig rather than the whole file. It handles FASTA (not FASTQ quality scores or indexed random access) and formats gc_fraction as a 5-decimal string; for downstream statistics, keep raw numeric floats or compute counts directly.

Recap and next steps

You practiced core Python 3 sequence handling (.split(), .upper(), slicing, str.maketrans()), wrote deterministic validation and GC helpers, counted k-mers in dictionaries, streamed FASTA records with yield, and packaged the workflow into scripts/compute_fasta_stats.py.

  1. Continue along the learning path to Statistics for Bioinformatics, or explore Data Visualization Fundamentals and Reproducible Workflows with Snakemake and Nextflow.
  2. Write small unit tests for is_valid_dna and gc_fraction (covering empty strings, all-N sequences, and lowercase input) using pytest inside your project's isolated environment.
  3. When your project adds third-party packages, keep requirements.txt (or your tool's lockfile) alongside the repository and document the Python version used.

Author's lab note: Writing custom Python parsers without checking for blank lines, trailing carriage returns (\r\n), or lowercase soft-masked nucleotides is the classic trap when handling external FASTA downloads. Stripping whitespace cleanly and deciding early whether masked lowercase bases stay separate or get folded with .upper() keeps downstream GC and length scripts predictable.
