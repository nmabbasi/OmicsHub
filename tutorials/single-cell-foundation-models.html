Single-Cell Foundation Models

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: scGPT, Geneformer, Scanpy

Learning objectives and prerequisites

Learning objectives

  • Understand the concept of single-cell foundation models (SFMs) and how they differ from conventional single‑cell methods.
  • Integrate a pre-trained transformer-based model (for example, scGPT-style models) into an AnnData-based single-cell workflow for embedding, visualization, and zero‑shot cell type annotation.
  • Compare and interpret model-derived embeddings against standard Scanpy preprocessing and clustering results, and apply simple diagnostics to check species and gene-identifier compatibility.

Prerequisites

  • Familiarity with single-cell RNA-seq (scRNA-seq) concepts and workflows (e.g., Scanpy/AnnData or Seurat).
  • Comfort using the command line and creating Python virtual environments.
  • Basic knowledge of PyTorch and Hugging Face transformers is useful but not required.
  • A small, preprocessed scRNA-seq dataset in AnnData/HDF5AD format (example filename: my_data.h5ad).

Why single-cell foundation models matter

Single-cell foundation models (SFMs) are large neural networks trained on many millions of individual cell transcriptomes rather than human language. By learning patterns across enormous and diverse single‑cell datasets, SFMs can produce contextualized embeddings of cells and sometimes perform tasks such as zero‑shot cell type annotation or batch correction without per‑dataset retraining.

This approach shifts some decisions away from classical heuristics (e.g., how many principal components to use) toward learned representations that capture nonlinear relationships in gene co‑expression across experiments. SFMs are promising for rapid exploration, for seeding downstream analyses, and for enabling users to leverage broad population-level knowledge. However, they are sensitive to input conventions (species, gene identifiers, preprocessing) and should be used alongside—rather than as a replacement for—standard quality control, marker inspection, and domain knowledge.

Reproducible workflow (step‑by‑step)

The steps below assume you have a local project directory and the following file:

  • data/my_data.h5ad — an AnnData file containing raw or normalized counts, cell metadata (adata.obs), and gene names in adata.var_names.

All commands assume a Unix-like shell. Use explicit paths so others can reproduce your run.

1) Create a controlled Python environment

# From project root

source .venv/bin/activate

# Upgrade pip

# PyTorch and Hugging Face (CPU or GPU variants)

3) Confirm gene identifier and species compatibility

Most SFMs are trained with a specific gene vocabulary (e.g., human HGNC gene symbols). Before encoding, make sure your adata.var_names match the model's expected gene identifiers. If your data uses Ensembl IDs (e.g., ENSG00000000003), convert them to symbols using a deterministic mapping (biomaRt, gget, or a local lookup table).

# Example using gget (install separately if used)
# pip install gget
python - <<'PY'
import scanpy as sc
adata = sc.read_h5ad("data/my_data.h5ad")

# Example naive check for Ensembl-like names
ensembl_like = any(name.startswith("ENSG") for name in adata.var_names[:50])
print("Looks like Ensembl IDs:", ensembl_like)

# Save a copy for auditing before any conversion
adata.write_h5ad("data/my_data_orig.h5ad")
print("Saved audit copy to data/my_data_orig.h5ad")
PY

What this produces:

  • An audit copy data/my_data_orig.h5ad to preserve the exact input.
  • A simple check whether gene names look like Ensembl IDs.

5) Downstream visualization and zero‑shot annotation

Common downstream steps are neighborhood graph construction, UMAP visualization, and label transfer or nearest‑neighbor classification using embeddings.

# Example analysis pipeline using Scanpy
python - <<'PY'
import scanpy as sc
adata = sc.read_h5ad("data/my_data_with_sfm.h5ad")

# Use the foundation-model embedding as the basis for neighbors
sc.pp.neighbors(adata, use_rep="X_sfm", n_neighbors=15)
sc.tl.umap(adata, min_dist=0.5)
sc.pl.umap(adata, color=["batch", "some_existing_label"], save="_sfm_umap.png")

# Simple zero-shot label propagation using k-NN to a small reference set
# Suppose you have reference embeddings and labels saved as numpy files:
#   data/ref_embeddings.npy  (shape: n_ref x d)
#   data/ref_labels.npy      (shape: n_ref,)
import numpy as np
ref_emb = np.load("data/ref_embeddings.npy")
ref_labels = np.load("data/ref_labels.npy")

from sklearn.neighbors import KNeighborsClassifier
knn = KNeighborsClassifier(n_neighbors=5)
knn.fit(ref_emb, ref_labels)
preds = knn.predict(adata.obsm["X_sfm"])
adata.obs["sfm_pred"] = preds

# Save annotated AnnData
adata.write_h5ad("data/my_data_with_sfm_annotated.h5ad")
print("Saved annotated AnnData to data/my_data_with_sfm_annotated.h5ad")
PY

What these commands produce:

  • UMAP figures saved to the configured Scanpy plotting directory (e.g., figures/umap_sfm_umap.png).
  • Annotated AnnData with predicted labels in adata.obs['sfm_pred'].

Output inspection and interpretation

After running the workflow, inspect the following:

  • Embedding shape: ensure adata.obsm['X_sfm'] has shape (n_cells, embedding_dim)—e.g., (10,000, 512). If the shape is incorrect, the model likely returned a per-gene vector or an error occurred.
  • UMAP and neighborhood graph: visualize the UMAP colored by known metadata (sample, batch, QC flags) and by sfm_pred (zero‑shot labels). Coherent separation by known biological labels suggests the embedding preserves biological signal; complete mixing may indicate excessive batch effects, or mismatch between model expectations and input.
  • Concordance with marker genes: pick a few canonical marker genes and plot expression on the UMAP. A good sign is that model-predicted labels correspond to marker expression (e.g., predicted T cells are enriched for CD3D expression). Discrepancies require manual validation.

What a plausible result means—and does NOT prove:

  • If predicted labels align with marker-gene expression and expected clusters, it suggests the SFM embedding is informative for your dataset.
  • It does NOT prove the predictions are absolutely correct or transferable to clinical decision-making. Zero‑shot labels are model inferences and may reflect biases in the training corpus.
  • Good visual separation does not guarantee accurate gene-level imputation or differential expression; follow up with conventional differential testing and marker validation.

Troubleshooting

Below are common symptoms, likely causes, and concrete fixes.

Symptom: Model fails to load or raises import errors

  • Cause: Missing package or incompatible version of transformers/PyTorch.
  • Fix: Verify package versions (pip list) and reinstall recommended versions from the model documentation. On clusters, ensure the CUDA driver matches the PyTorch wheel (check nvidia-smi).

Symptom: adata.obsm['X_sfm'] contains NaNs or zeros

  • Cause: The model may expect nonzero counts or particular normalization; tokenization may have failed for many genes.
  • Fix: Check that gene names match the model vocabulary. Re-run tokenization/encoding with a small subset of cells (10–100) while printing diagnostic messages.

Symptom: Predictions are dominated by a single class or by batch labels

  • Cause: Species mismatch, incorrect gene IDs, or reference labels mismatched to your data.
  • Fix: Confirm species and gene ID mapping. Use marker-gene diagnostics to determine whether the model is learning biology or batch. Try subsampling to equalize batches for a sanity check.

Symptom: Inference is extremely slow on CPU

  • Cause: SFMs are compute intensive; transformer layers have high memory and compute cost.
  • Fix: Use GPU nodes with sufficient VRAM (>=16 GB recommended). For large datasets, embed in batches and save intermediate files. Consider model quantization or CPU-optimized inference frameworks if GPU not available.

Limitations, version caveats, and responsible use

  • Model training biases: SFMs are trained on public or consortium datasets and can reflect sampling bias (overrepresentation of certain tissues, cell types, or species). Interpret zero‑shot outputs with caution, especially for rare or poorly represented cell states.
  • Gene vocabulary and species: Many models expect a specific gene vocabulary (human HGNC symbols are common). Always map and document gene identifier conversions; keep an audit copy of the original AnnData.
  • Preprocessing sensitive: Tokenization strategies (discretization bins, normalization) may be required or assumed; check the model README for preprocessing steps. Differences in pre-processing can change embedding geometry substantially.
  • Versioning: Record exact versions of model checkpoints, package versions, and input files. Save the model id or checkpoint hash (e.g., a Hugging Face model id) and the script used to generate embeddings so results are reproducible.
  • Responsible use: SFMs are research tools. Do not use zero‑shot annotations for clinical decision-making or to make unvalidated biological claims without orthogonal validation (e.g., orthogonal assays, curated markers, or manual expert review).

  • Inspect canonical marker genes across predicted labels and clusters; document any mismatches.

  • If results are promising, consider fine‑tuning the model on a modestly sized labeled dataset for your domain following the model's fine-tuning instructions.
