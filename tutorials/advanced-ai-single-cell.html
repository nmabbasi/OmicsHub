AI-Assisted Cell-Type Annotation: Models, Limits, and Review

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

← Previous tutorialAll tutorialsNext tutorial →

Cell annotation tools assign labels by comparing a query dataset with learned classes, reference profiles, or embedded representations. Treat each assignment as a proposal: its usefulness depends on what the model or reference contains and whether the evidence fits your cells.

Format: Advanced template. For readers familiar with Python and AnnData who already have an authorized, human immune-cell .h5ad query with documented raw counts and gene symbols. You will run one CellTypist prediction, save reviewable labels and diagnostics, and inspect reference fit; the input is prepared by you, not supplied here.

Choose a method by its input and comparison

These methods do not share one interchangeable “AI annotation” interface. CellTypist is a logistic-regression classifier with downloadable or custom models. SingleR transfers labels by comparing query expression with a labeled reference. The published CELLama method converts ranked expressed genes, and optionally metadata, into text for sentence-transformer embeddings; the study evaluates embedding-based cell typing against reference cells. Geneformer and scGPT are separate projects with distinct representations and task workflows. A model's general-purpose or foundation-model label does not establish support for every annotation task.

What is being compared, and what to check before trusting a label
ApproachComparisonReview before interpretation
CellTypistQuery expression scored by a selected logistic-regression modelSpecies, tissue and label coverage; gene identifiers; input normalization; per-cell scores and any majority-voting refinement
SingleRQuery expression compared with labeled reference profilesReference compatibility, label granularity, score separation and pruned assignments
CELLama (published method)Ranked top-gene text embedded and compared with reference embeddingsGene-ranking and sentence construction, metadata included, reference design, and the paper's evaluation scope

A shared output label does not make the methods' scores equivalent. Compare each result using its own documented diagnostics.

Run and inspect a CellTypist prediction

This advanced template expects a reader-prepared my_data.h5ad: AnnData with cells in rows, genes in columns, unique human gene-symbol feature names, and an explicitly documented raw-count matrix. Start in a dedicated working directory, create an isolated Python environment, and install the two packages (the current releases and dependency resolution may change):

mkdir -p celltypist-review
cd celltypist-review
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install scanpy celltypist
python -c "import scanpy, celltypist; print('scanpy', scanpy.__version__, 'celltypist', celltypist.__version__)"
# Put your authorized input here; this template will write results beside it:
# celltypist-review/my_data.h5ad

Record the environment actually used with python -m pip freeze > requirements-record.txt; this captures your resolved environment and is not a tested or guaranteed version lock. For an official worked AnnData/count-layer example, see Scanpy’s preprocessing and clustering tutorial, which demonstrates saving counts before normalization. Use its documented public dataset only if appropriate and authorized for your purpose—this page does not bundle a compatible CellTypist fixture. The selected built-in model below is an example for human immune annotation, not a universal model.

Before running, inspect the object’s provenance and layer names in your own preparation notebook. The code below deliberately requires a counts layer with verified raw counts; if absent, establish the correct source from the upstream pipeline rather than guessing from values. Stop if counts are unavailable, transformed, negative, non-finite, or not integer-like. Numerical checks can reject obvious violations, but cannot prove count provenance.

import numpy as np
import scanpy as sc
import celltypist
from celltypist import models

adata = sc.read_h5ad("my_data.h5ad")
assert adata.n_obs > 0 and adata.n_vars > 0, "Empty input: stop and check the file"
assert adata.var_names.is_unique, "Duplicate feature names: resolve before prediction"
assert "counts" in adata.layers, "No verified raw-count layer; stop rather than infer provenance"
# User must verify from upstream records that this layer is untransformed raw counts.
counts = adata.layers["counts"]
values = counts.data if hasattr(counts, "data") and hasattr(counts, "indptr") else np.asarray(counts)
assert np.isfinite(values).all() and (values >= 0).all(), "Counts contain invalid values"
assert np.allclose(values, np.rint(values)), "Values are not integer-like raw counts"
adata.X = counts.copy()
# This changes X only; the verified count layer remains available for provenance.
sc.pp.normalize_total(adata, target_sum=1e4)
sc.pp.log1p(adata)

# Inspect available models and choose one for the query's species and context.
print(models.models_description())
models.download_models(force_update=False)
model = models.Model.load("Immune_All_Low.pkl")
pred = celltypist.annotate(adata, model=model, majority_voting=True)
adata.obs["celltypist_label"] = pred.predicted_labels["majority_voting"].to_numpy()
adata.obs["celltypist_cell_label"] = pred.predicted_labels["predicted_labels"].to_numpy()
# Keep both cell-level and majority-vote labels for comparison.
prob = pred.probability_matrix
assert prob.shape[0] == adata.n_obs, "Prediction rows do not match input cells"
assert prob.shape[1] >= 2, "Need at least two model classes to calculate a margin"
ordered = np.sort(np.asarray(prob), axis=1)
adata.obs["celltypist_top_probability"] = ordered[:, -1]
adata.obs["celltypist_probability_margin"] = ordered[:, -1] - ordered[:, -2]
# Compact review table keyed by original cell IDs; labels remain proposals.
review = adata.obs[["celltypist_label", "celltypist_cell_label",
                    "celltypist_top_probability", "celltypist_probability_margin"]].copy()
review.index.name = "cell_id"
review.to_csv("celltypist-review.csv")
adata.write_h5ad("celltypist-annotated.h5ad")
print(review.head())
print("probability matrix:", prob.shape)

CellTypist expects gene symbols and supports AnnData input. Its annotate function returns an AnnotationResult, including predicted labels, decision scores, and a probability matrix. The review CSV and annotated H5AD are written in the working directory; the preview should show original cell IDs, both label versions, and two per-cell diagnostics, while the matrix row count must equal the number of cells. A successful run establishes only that input was processed and outputs were written—not that labels are biologically correct. If an assertion fails or output is empty, stop and inspect the input/model compatibility rather than weakening checks. Majority voting is optional and may use heuristic over-clustering when none is supplied; inspect its basis and retain the unrefined cell-level labels. Scores are diagnostics, not calibrated biological certainty. Follow the saved table with marker, cluster-coherence, and reference-context review before accepting assignments.

Stop if the input contract is unclear

Do not silently convert Ensembl IDs to symbols by trimming version suffixes or assume symbols are species-correct. Resolve identifiers with an appropriate mapping, check duplicates and gene overlap, and confirm which layer contains raw counts. A wrong feature mapping or unsuitable model can produce plausible-looking labels with little biological relevance.

Review predictions against independent evidence

For each cluster or cell group under review, make a small decision record. Include the model's label, an appropriate marker panel, the tissue/species/condition covered by the reference, and a reason to accept, revise, or leave the label unresolved. Marker panels are context-dependent; use positive and counter-markers where possible, and examine whether a cluster mixes distinct populations. A label match alone does not validate a novel cell state or biological mechanism.

  1. Check the data and model. Record species, tissue, assay, preprocessing, model/reference identifier and software version. Check gene overlap and whether the query has conditions absent from the reference.
  2. Inspect ambiguity. Compare available score/probability diagnostics across candidate labels. For SingleR, inspect score patterns and pruned.labels; pruning can leave uncertain assignments unlabelled. A narrow score gap or unresolved output is a reason to review, not a command to force the nearest label.
  3. Compare biology. Check known positive and conflicting markers, cluster coherence and tissue context. Investigate discordance instead of choosing whichever tool sounds more advanced.
  4. Write the disposition. Save the predicted label, evidence, reference limitation and decision (accept, revise, unresolved). Revisit the call when improved references or orthogonal evidence become available.

Practice: build an annotation review row

Choose one cluster from a non-sensitive dataset you are authorized to use. Record its proposed label, the reference/model and version, two supporting markers and any conflicting marker evidence, a score/ambiguity observation, and an accept/revise/unresolved decision with one-sentence rationale.

Check: The row is reproducible and makes the evidence and reference limitation visible. If no compatible reference or informative markers are available, “unresolved” is a defensible outcome.

Failure cases worth checking

  • Unmapped or duplicated genes: inspect feature identifiers and overlap with the model/reference. Unexpectedly low overlap can make predictions unreliable or fail outright.
  • Reference mismatch: a human immune model is not suitable simply because the query contains immune cells; species, tissue, disease and assay context affect transfer.
  • Strong scores with contradictory markers: investigate preprocessing, doublets, mixed clusters and classes missing from the reference. A classifier still assigns the closest available class in best-match mode.
  • Majority-vote labels erase heterogeneity: compare refined labels with per-cell predictions and the clustering used for refinement. The result depends on over-clustering choices.
  • External processing of sensitive data: keep patient-linked counts, metadata and cell identifiers within approved systems; do not send them to a third-party service without institutional authorization.

References and version checks

Check current project documentation before running the code: APIs, model inventories and defaults may change. The code here is an instructional example, not a claim that the current site environment or a biological dataset was executed.

  • CellTypist prediction function: accepted inputs, model selection, majority voting and result object.
  • CellTypist documentation: tool overview and current documentation entry point.
  • SingleR Bioconductor vignette: reference-based annotation, score diagnostics and pruning.
  • CELLama primary paper: ranked-gene sentence construction, embeddings and study evaluation. Results in that paper do not establish performance on an unrelated dataset.
  • Scanpy normalize_total and log1p: normalization calls used in the example.
