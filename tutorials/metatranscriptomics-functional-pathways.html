Metatranscriptomic Pathway Analysis with HUMAnN 3

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

← Previous tutorialAll tutorialsNext tutorial →

HUMAnN estimates microbial gene-family and pathway abundances from metagenomic or metatranscriptomic reads. This walkthrough follows quality-controlled, rRNA-depleted reads through per-sample profiling, table joining, normalization, and interpretation. It is a computational profile of transcript evidence, not a direct measurement of enzyme activity or metabolic flux.

What you need and what you will produce

Start with one quality-controlled FASTQ/FASTA file per sample. The example below uses compressed FASTQ. You need HUMAnN 3 installed, its configured nucleotide and translated-search databases available, and command-line access. HUMAnN's exact release and reference database versions affect mappings, so record them with your analysis; the commands are examples, not evidence that a particular installation or dataset was run here.

For each sample HUMAnN writes gene-family, pathway-abundance, pathway-coverage, and log/output files. The feature tables can include community-level rows and taxon-stratified rows. After this exercise you will have joined pathway abundance and coverage matrices, plus a copies-per-million (CPM) abundance table for descriptive visualization.

Scope: HUMAnN uses MetaCyc pathway definitions and UniRef-based gene families. A transcript-derived pathway estimate reflects mapped RNA evidence. It does not establish protein abundance, reaction rate, or flux. Comparisons also depend on library composition, sequencing depth, protocol, database, and statistical design.

Run HUMAnN for each sample

  1. Prepare the input. Use reads after quality control and rRNA depletion appropriate to the study. Keep sample IDs consistent and avoid reusing an output directory containing another sample's results.
  2. Profile the sample. Replace the example path and sample ID. An optional MetaPhlAn profile can be supplied with --taxonomic-profile; it is an input profile used to select taxa for the custom pangenome search. It is not a raw-reads shortcut and must correspond to the sample or a deliberate joint profile. 
    humann \
  --input data/sampleA_mRNA.fastq.gz \
  --output humann_out/sampleA \
  --threads 12

    Without a supplied profile, HUMAnN runs its own taxonomic prescreen as part of its workflow. The required reference databases must already be installed/configured. For a multi-sample analysis, repeat with a distinct input and output directory for each sample.

  3. Check the run before aggregating. Inspect the HUMAnN log for errors, note the command, software/database versions, and confirm the expected files exist under the chosen output directory. The per-sample gene-family, pathway-abundance, and pathway-coverage filenames carry the sample identifier. Stop and investigate missing or empty outputs rather than treating them as zero-valued biology.

Join per-sample pathway tables

HUMAnN's join utility selects files by a filename substring. Use a suffix common to all samples, not one sample's full filename, or the command may join only one table. From the project directory:

humann_join_tables \
  --input humann_out \
  --file_name _pathabundance.tsv \
  --output merged_pathabundance.tsv

humann_join_tables \
  --input humann_out \
  --file_name _pathcoverage.tsv \
  --output merged_pathcoverage.tsv

The input directory is searched for matching HUMAnN tables; the output is a multi-sample table with features and sample columns. Review the joined header and confirm every intended sample appears once. For gene families, use the corresponding _genefamilies.tsv suffix. Do not include a previous merged output in the input directory if its filename also matches the selected substring.

Checkpoint: If only one sample appears, inspect the input directory and the --file_name substring. If the join reports no files, check the table suffix, directory, and whether HUMAnN completed successfully.

Normalize for descriptive plots

HUMAnN reports gene-family and pathway abundance in RPK units. CPM in HUMAnN means copies per million, a total-sum-scaled abundance, not raw sequencing counts per million. Convert the joined pathway table when CPM is useful for visualization:

humann_renorm_table \
  --input merged_pathabundance.tsv \
  --output merged_pathabundance_cpm.tsv \
  --units cpm

CPM is not a raw count matrix and should not be passed to count-based differential-expression methods as if it were counts. Choose a statistical method and input representation appropriate to the study and method; normalization alone does not address compositionality, covariates, or batch effects. Keep the unnormalized HUMAnN output and document any downstream transformation.

Separate community and taxon-stratified rows

Rows with a taxonomic suffix (for example, a pathway followed by |taxon) report stratified contributions; an unstratified pathway row summarizes the community-level estimate. To write these into separate tables, pass an output directory to HUMAnN's split utility:

humann_split_stratified_table \
  --input merged_pathabundance.tsv \
  --output split_pathabundance

The utility writes two tables in that directory, one stratified and one unstratified. Check the generated filenames and inspect the rows before analysis. This is a file split, not a transformation into separate taxon columns. Apply the same operation to coverage only if separate stratified and unstratified coverage tables are needed.

Interpret abundance and coverage together

  • Pathway abundance summarizes mapped gene-family evidence assigned to a MetaCyc pathway. A larger estimate indicates more mapped abundance under the chosen profiling and normalization context; it is not a direct rate of pathway operation.
  • Pathway coverage is a pathway completeness/coverage estimate based on detected pathway components. Interpret its scale and calculation in the HUMAnN version and output format used; do not describe it as a direct assay of every enzymatic step.
  • Gene-family rows help trace which UniRef families contribute to a pathway estimate. Shared or ambiguously mapped functions can contribute to multiple interpretations.
  • Stratification attributes contributions using the taxonomic profile and reference mappings. Treat small or uncertain taxon contributions cautiously, especially for conserved gene families.

Worked interpretation (hypothetical): Suppose a pathway has appreciable abundance and broad coverage in a sample. This supports the interpretation that transcripts mapping to multiple components of that pathway were detected. It does not show that the pathway carried flux. If the signal is concentrated in one taxon-stratified contribution, check the underlying gene families and taxonomic profile before describing that taxon as the source.

Troubleshoot before drawing conclusions

  • Run is slow: translated search can be computationally demanding, particularly when many reads remain after nucleotide search. Check logs, available threads, storage/I/O, and database configuration. Any sensitivity or bypass option changes what is searched; consult the installed version's help and document the change rather than applying an undocumented speed tweak.
  • Few reads map or coverage is low: check read quality and length, rRNA depletion, database versions and configuration, and logs for failed search stages. Novel organisms or functions absent from references can also limit mapping. Low mapping is not by itself evidence that the biological function is absent.
  • Unexpected taxon attribution: inspect stratified and unstratified rows, contributing gene families, and the taxonomic profile supplied to HUMAnN. Shared families and profile errors can complicate attribution. A second taxonomic profile on the same reads is a useful diagnostic, not independent confirmation of function.
  • Samples differ after normalization: review library depth, sample processing, study design, and compositional effects. CPM rescales totals; it does not make absolute transcript abundance comparable or replace a statistical model.

Report the analysis reproducibly

Keep the exact HUMAnN version, database identities/releases, commands and options, input processing steps, sample metadata, and any filtering or normalization decisions with the results. Database releases can change mappings. For important biological claims, use complementary evidence such as metaproteomics, metabolomics, targeted assays, or activity measurements, selected to answer the specific claim.
