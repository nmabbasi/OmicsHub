Protein Structure Design with AI

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: ESM3, AlphaFold3, PyMOL

Learning objectives and prerequisites

By the end of this lesson you will be able to:

  • Prepare a FASTA sequence and run quick structure predictions using hosted services for AlphaFold and ESMFold.
  • Generate a candidate sequence with a generative foundation model (ESM3-style approach) and fold it with ESMFold or AlphaFold.
  • Inspect the resulting PDB (Protein Data Bank) files, interpret common confidence metrics, and decide what claims are and are not supported by an in-silico prediction.

Prerequisites Prerequisites: basic molecular-biology vocabulary (primary, secondary, tertiary, quaternary structure), familiarity with the command line and Python (for example, running python scripts and using curl). This tutorial assumes you have access to a networked workstation or cloud instance capable of invoking REST APIs and saving files locally. You do not need to install AlphaFold databases or a GPU to follow the hosted-API workflow outlined here.

Why this matters: biological and computational context

Protein structure underlies molecular function. Predicting how a polypeptide sequence folds into a 3D shape enables hypotheses about binding sites, enzymatic mechanisms, and stability. Foundation models—large neural networks trained on millions of protein sequences and structures—have changed how practitioners approach both structure prediction and de novo design. Two representative types are:

  • High-accuracy structure predictors (e.g., AlphaFold) that leverage evolutionary information and multiple sequence alignments (MSAs) to predict atomic coordinates with per-residue confidence scores.
  • Sequence generation models (e.g., ESM3 family) that can propose novel sequences consistent with a learnt protein grammar; these can be used to design scaffolds or enforce local sequence motifs.

Important conceptual cautions: model predictions are hypotheses about thermodynamically plausible folds under idealized in silico assumptions. They do not prove function, stability in a cellular context, binding specificity, or safety. Every in-silico design requires orthogonal experimental validation (biochemistry, biophysics, structural methods, and biological assays) before making biological claims.

Reproducible workflow (sequential)

Below are reproducible, realistic commands and short Python snippets for a typical learning workflow. All file paths are explicit and safe. The steps use public hosted services to avoid the large local database and GPU requirements of a full AlphaFold installation.

What you should have before starting

  • A directory to hold inputs and outputs. This tutorial uses a single working directory to store those files.protein-design in the current working directory.
  • An input FASTA file with a single sequence. Example small test sequence is provided below. Do not use sequences derived from controlled or sensitive contexts unless you have appropriate approvals.
  • curl and python3 available on your system (or an equivalent HTTP client and Python interpreter).

Step 0 — prepare directories and a FASTA

mkdir -p protein-design/{inputs,results}
cat > protein-design/inputs/example.fasta <<'EOF'
>example_protein
MKTAYIAKQRQISFVKSHFSRQDILD
EOF

Files created:

  • protein-design/inputs/example.fasta — contains the input sequence in FASTA format.
  • No outputs yet — the next steps produce PDB files.

Step 1 — fetch a precomputed AlphaFold structure from the AlphaFold Protein Structure Database

If your sequence exactly matches a UniProt canonical sequence available in the AlphaFold DB, you can download a precomputed PDB. This is a fast way to inspect a model without running prediction locally.

# Example: download AlphaFold model for UniProt ID P04637 (TP53)
# Save into the results folder. This command will create protein-design/results/AF-P04637-F1-model_v4.pdb
curl -fSL https://alphafold.ebi.ac.uk/files/AF-P04637-F1-model_v4.pdb -o protein-design/results/AF-P04637-F1-model_v4.pdb

What this produces:

  • protein-design/results/AF-P04637-F1-model_v4.pdb — PDB-format structure predicted by AlphaFold for UniProt entry P04637. The model file may contain pLDDT values encoded in the B-factor column.

Notes: AlphaFold model versions and file naming conventions can change; always check the AlphaFold DB page for the target UniProt ID: https://alphafold.ebi.ac.uk.

Step 2 — quick fold with ESMFold via the public endpoint

ESMFold is optimized for rapid single-sequence folding and can be used via a hosted API for prototyping. The endpoint and request format below follow the ESM Atlas public API (current at the time of writing). Replace or check the API documentation before use.

# Submit sequence in example.fasta to ESMFold public endpoint and save the PDB
# This uses curl; the API accepts plain sequence or FASTA depending on endpoint
curl -sS \
  -H "Content-Type: text/plain" \
  --data-binary @protein-design/inputs/example.fasta \
  https://api.esmatlas.com/foldSequence/v1/pdb/ \
  -o protein-design/results/esmfold_example.pdb

What this produces:

  • protein-design/results/esmfold_example.pdb — predicted structure in PDB format returned by ESMFold.

If the endpoint requires a specific format (plain sequence vs FASTA), adjust the request to send only the sequence string. Always consult the API docs: https://esmatlas.com and the project repo: https://github.com/facebookresearch/esm.

Step 3 — generate candidate sequences using a generative model (ESM3-type) via SDK or API

Generative models can propose full-length sequences given constraints such as a motif, a binding-site-localized pattern, or a target length. Many providers expose REST/SDK APIs; below is a conceptual Python example using a hypothetical SDK interface. Replace YOUR_API_KEY and check the provider SDK for exact call signatures before running.

from typing import List
# Pseudocode / template - adapt to the official SDK you use
from esm.sdk import client
from esm.sdk.api import ESMProtein, GenerationConfig

# Initialize client (this is a conceptual example; concrete SDKs will differ)
c = client(model="esm3-large", token="YOUR_API_KEY")

# Define a scaffold with a short fixed motif (e.g., a putative binding motif 'HXXH')
sequence_length = 120
motif = "HXXH"
# Create an initial prompt where underscores are placeholders or use model-specific masking
prompt = "_" * 50 + "HXXH" + "_" * (sequence_length - 54)

config = GenerationConfig(max_length=sequence_length, temperature=0.8, top_p=0.95)
response = c.generate_sequence(prompt=prompt, generation_config=config)

# Save the generated sequence to FASTA for folding
generated_seq = response.sequence  # actual field names vary by SDK
with open("protein-design/inputs/generated_candidate.fasta", "w") as fh:
    fh.write(">candidate_esm3\\n")
    fh.write(generated_seq + "\\n")

Files produced:

  • protein-design/inputs/generated_candidate.fasta — a model-generated sequence to fold with ESMFold or AlphaFold.

Follow up by folding the generated FASTA with ESMFold (see Step 2), or submit to AlphaFold if you have access to a cloud AlphaFold service.

Output inspection and interpretation

After producing PDB files, inspect them with a molecular viewer (PyMOL, UCSF ChimeraX, or Mol*). Relevant checks and what they mean:

  • Per-residue confidence (pLDDT): AlphaFold encodes predicted lDDT (pLDDT) in the B-factor column of the PDB. Approximate interpretation:
    • >90: very high confidence — backbone and many side-chains are predicted with high accuracy for isolated domains.
    • 70–90: generally reliable for overall fold/backbone; side-chain placement less certain.
    • 50–70: low to medium confidence — consider flexible loops or alternative conformations.
    • <50: model likely disordered or not well predicted.
  • Predicted aligned error (PAE) (AlphaFold): PAE is a pairwise error estimate between residue positions and helps identify well-defined domain orientations. Low PAE between two regions suggests the relative orientation is predicted confidently; high PAE means the relative orientation is uncertain.
  • Geometry checks: visualize clashes, unusual bond lengths/angles, and unrealistic side-chain rotamers. These can arise from prediction artifacts and indicate regions to inspect or redesign.
  • Secondary structure agreement: compare predicted helices/sheets to expectations from sequence-based predictors (e.g., PSIPRED) to look for gross inconsistencies.

What a plausible result supports:

  • That the sequence is likely to adopt the predicted fold under idealized conditions and in isolation (especially when pLDDT is high and PAE is low for domain orientations).
  • That the structure can be used to hypothesize binding pockets, surface-exposed residues, or to plan mutagenesis that tests specific structural hypotheses.

What a prediction does NOT prove:

  • Biological function, catalytic activity, or ligand-binding specificity in a cellular context.
  • Stability under physiological conditions — thermostability and aggregation propensity require experimental validation (DSF, SEC, CD, etc.).
  • Safety or viability for therapeutic applications—those require regulatory, toxicological, and ethical oversight plus wet-lab validation.

Troubleshooting (symptom → likely cause → suggested fix)

  • Symptom: API returns 400 or malformed response when sending FASTA.
    • Cause: endpoint expects plain sequence string or different content-type header.
    • Fix: Inspect API docs and send only the raw sequence with Content-Type: text/plain, or strip the FASTA header before POSTing.
  • Symptom: PDB file lacks pLDDT or B-factor values appear zero.
    • Cause: the service returned a reduced format (e.g., only coordinates) or a different confidence metric encoding.
    • Fix: Check the service documentation for how confidence is encoded. For AlphaFold DB, pLDDT is in the B-factor column; some APIs provide separate JSON or CSV confidence outputs.
  • Symptom: Predicted structure shows many steric clashes or unrealistic bond geometry.
    • Cause: automated minimization steps may be omitted; model may have low confidence for those regions.
    • Fix: run a short energy minimization with an appropriate molecular mechanics tool (for inspection only), or reassess confidence maps and consider redesigning low-confidence regions.
  • Symptom: Generated sequence is unusually hydrophobic or contains long repeats.
    • Cause: generation parameters (temperature/top-p) produced degenerate output, or model prompt insufficiently constrained.
    • Fix: adjust generation parameters (lower temperature, tighter top-p), add biological constraints (e.g., limit hydrophobic residue runs), or filter outputs computationally (e.g., compute hydrophobicity, charge).
  • Symptom: AlphaFold download fails with 404 for a UniProt ID you expect to exist.
    • Cause: the AlphaFold DB may not provide models for that specific isoform or the model version has a different filename pattern.
    • Fix: search the AlphaFold DB web interface for the UniProt accession and follow the provided download link.

Limitations, version and data-source caveats, responsible-use notes

Limitations and caveats you must consider:

  • Model versions matter. AlphaFold model versions and training data evolve; always report the exact model version and database snapshot used (for example, model_v4 and the UniProt/AlphaFold DB date). For ESM-family models, record the model name and Git commit or release tag.
  • AlphaFold relies heavily on MSAs (multiple sequence alignments) and template information; sequences with poor evolutionary context may be less confidently predicted. ESMFold and single-sequence predictors may perform better for orphan sequences but still have limitations for complex multi-domain arrangements and protein complexes.
  • Predictions are not experimental validation. Use them to guide experiments, not to replace them. For any biological or safety-related designs, obtain institutional approvals and follow applicable biosafety, biosecurity, and ethical guidelines.
  • Data provenance: keep the input FASTA and the exact API responses alongside the PDBs so results are reproducible. Example files in this tutorial: protein-design/inputs/example.fasta, protein-design/inputs/generated_candidate.fasta, and outputs under protein-design/results/.

Responsible-use considerations:

  • Do not design or evaluate sequences intended to enable pathogenicity, increased transmissibility, or evasion of detection. If your research touches on dual-use risks, consult institutional biosafety committees and relevant regulations before proceeding.
  • Be transparent about limitations in any public dissemination: indicate that structural models are computational predictions and list confidence metrics and generation parameters.

Next-step checklist (concise)

  1. Verify that you can re-run the same API calls and reproduce the PDB outputs from the saved FASTA files.
  2. Open the PDBs in PyMOL or ChimeraX and annotate pLDDT and PAE (if available).
  3. For promising designs, compute simple in-silico filters: hydrophobic patches, predicted isoelectric point (pI), and predicted secondary structure vs design intent.
  4. Plan bench experiments: gene synthesis, small-scale expression/purification, and at minimum circular dichroism (CD) or size-exclusion chromatography (SEC) to check folding/aggregation.
  5. Record and report all model versions, API endpoints, and timestamps used to obtain your results.
