Cell-Cell Communication

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

By the end of this lesson you will be able to:

  • Run a reproducible cell–cell communication analysis pipeline on single-cell RNA-seq (scRNA-seq) data using LIANA for multi-method ligand–receptor (LR) inference and CellChat for pathway-level network modeling.
  • Produce and inspect ranked LR tables and pathway network objects suitable for downstream visualization and experimental follow-up.
  • Understand the assumptions, common pitfalls, and validation strategies required to interpret inferred signaling hypotheses responsibly.

Prerequisites (complete before starting):

  • Familiarity with scRNA-seq basics (normalization, dimensionality reduction) and how to annotate cell types.
  • An R environment with Seurat v5-compatible data structures or a SingleCellExperiment object. This tutorial uses R code; basic R/Seurat experience is assumed.
  • Installed packages (see the Software and data files section below).

Why infer cell–cell communication from scRNA-seq?

Cells communicate using secreted ligands, membrane-bound ligands/receptors, and downstream signaling cascades. Single-cell RNA-seq measures gene-level expression per cell, enabling hypothesis generation about which cell types could be sending ligands and which could be receiving via cognate receptors. These inferred interactions are useful to (a) prioritize candidate signaling pairs for experimental testing, (b) compare signaling between conditions (e.g., disease vs. control), and (c) integrate with spatial or proteomic validation.

Important caveat: scRNA-seq measures mRNA, not protein localization, abundance, or post-translational regulation. Inference identifies candidate interactions — not proven biochemical binding or functional signaling.

Files, software, and expected inputs/outputs

Before you start, prepare the following files in a working directory (example path: /project/cellcomm/):

  • seurat_obj.rds — a Seurat v5 object with normalized counts, cluster or cell-type annotations in Idents(seurat_obj) or a metadata column named cell_type. The object should include per-cell metadata (sample, batch) if you plan sample-aware analyses.
  • metadata.tsv (optional) — tab-delimited metadata including sample, condition, and cell-type mapping if not already embedded in the Seurat object.

Expected outputs from the analysis steps below:

  • liana_aggregate_results.csv — a table of aggregated ligand–receptor predictions with sender/receiver labels and method consensus metrics.
  • cellchat_object.rds — a saved CellChat object containing inferred networks and pathway-level aggregation.
  • Figures (PNG/PDF) and intermediate tables for inspection.

Reproducible workflow (R): LIANA then CellChat

We present a sequential workflow: first use LIANA to get a consensus LR list across multiple methods; then use CellChat to model pathway-level communication and network topology. Commands assume an R session and working directory /project/cellcomm/. Install packages according to their official instructions if needed; package versions and databases can affect results (see Limitations below).

1) Load data and set up environment

# Working directory (change to your project path)
setwd("/project/cellcomm/")

# Load Seurat and check object
library(Seurat)
seurat_obj <- readRDS("seurat_obj.rds")      # Input file you should have prepared

# Quick checks
stopifnot("Seurat" %in% class(seurat_obj))
table(seurat_obj$cell_type)                  # ensure a cell_type column exists

What this produces: loads the Seurat object; the table call shows the number of cells per annotated cell type.

2) Run LIANA to generate method-aggregated LR predictions

LIANA wraps multiple inference algorithms and can produce consensus rankings. The commands below illustrate a minimal LIANA run; tune parameters (expression thresholds, aggregation strategy) to your data and questions.

# Install and load LIANA (follow package install docs if not present)
library(liana)
library(dplyr)

# Basic LIANA run: uses Seurat object, the metadata column "cell_type" for grouping
liana_out <- liana_wrap(seurat_obj,
                       group_by = "cell_type",
                       exprs_values = "data",      # use normalized data assay slot name as appropriate
                       min_cells = 10,             # require 10 cells per group, adjust as needed
                       return_list = TRUE)

# Aggregate across methods to get consensus ranking
liana_agg <- liana_aggregate(liana_out,
                             group_by = c("source","target","ligand","receptor"),
                             aggfun = "harmonic_mean")   # example aggregation function

# Save results
write.csv(liana_agg, "liana_aggregate_results.csv", row.names = FALSE)
saveRDS(liana_out, "liana_raw_results.rds")

Inputs: seurat_obj.rds. Outputs: liana_raw_results.rds (per-method outputs) and liana_aggregate_results.csv (consensus table).

3) Inspect LIANA outputs (quick checks)

# Read and inspect top rows
liana_agg <- read.csv("liana_aggregate_results.csv")
head(liana_agg)

# Simple filters: top interactions by consensus score (adjust column names as LIANA version dictates)
top_lr <- liana_agg %>%
  arrange(consensus_score) %>%         # lower score = higher rank in some LIANA versions
  head(20)

write.csv(top_lr, "liana_top20.csv", row.names = FALSE)

Look for columns indicating source (sender cell type), target (receiver), ligand, receptor, method-specific scores, and aggregated consensus metrics. Confirm that expected cell types are present and that extreme results are not driven by tiny cell counts.

4) Build a CellChat object for pathway-level modeling

CellChat uses curated ligand–receptor and signaling pathway databases and produces network visualizations and pathway aggregation. You can use LIANA results to inform CellChat or run CellChat independently. Below is a standard CellChat pipeline using the same Seurat object.

library(CellChat)

# Create CellChat object
cellchat <- createCellChat(object = seurat_obj, group.by = "cell_type")

# Choose the organism database; replace with CellChatDB.mouse when analyzing mouse
CellChatDB <- CellChatDB.human
cellchat@DB <- CellChatDB

# Preprocessing and inference
cellchat <- subsetData(cellchat)                         # subset expression data for signaling genes
cellchat <- identifyOverExpressedGenes(cellchat)
cellchat <- identifyOverExpressedInteractions(cellchat)

# Compute communication probabilities and aggregate by signaling pathway
cellchat <- computeCommunProb(cellchat)
cellchat <- computeCommunProbPathway(cellchat)
cellchat <- aggregateNet(cellchat)

# Save object
saveRDS(cellchat, "cellchat_object.rds")

Inputs: seurat_obj.rds. Outputs: cellchat_object.rds with network slots (@net) and pathway results.

Output inspection and interpretation

What to examine and how to interpret results — treat all as hypotheses:

  • LIANA ranked table: Focus on top-ranked LR pairs that are supported by multiple methods. Columns to check: sender (source), receiver (target), ligand, receptor, per-method p-values/scores, and the aggregated consensus metric. A top-ranked pair suggests co-expression patterns consistent with possible communication.
  • CellChat pathway scores: CellChat aggregates LR interactions into signaling pathways (e.g., NOTCH, WNT). High pathway-level communication means many LR pairs within that pathway show expression consistent with signaling between cell groups.
  • Network topology: Visualizations — circle plots, heatmaps of interaction strength, hierarchy plots — help identify dominant senders or receivers. Use these to prioritize experimental tests (e.g., a cell type that is a central sender across multiple pathways).

What these results do NOT prove:

  • That the ligand and receptor proteins are present at sufficient concentration or correctly localized.
  • That ligand–receptor binding occurs, or that downstream signaling is triggered in the target cell.
  • That observed differences are not due to confounders (batch effects, sample composition differences) without additional controls.

Troubleshooting

Below are common symptoms, likely causes, and suggested fixes.

  • Symptom: Very few predicted interactions or empty results.
    Likely causes: Low expression thresholds, sparse data, wrong assay slot (e.g., using raw counts vs normalized data), or group labels missing.
    Fixes: Confirm you used the correct assay name in LIANA (exprs_values), ensure each cell type has enough cells (min_cells), increase sensitivity by lowering minimum expression thresholds cautiously, or merge very small clusters.
  • Symptom: Top interactions driven by a single method while others disagree.
    Likely causes: Methods have different assumptions (e.g., thresholding, permutation).
    Fixes: Inspect per-method scores in LIANA raw output to understand disagreements; consider relying on consensus or restricting to methods appropriate for your data type.
  • Symptom: Unexpected cell types as dominant senders/receivers.
    Likely causes: Mis-annotated cell types, doublets (two-cell captures), or sample composition bias.
    Fixes: Re-check cluster annotations, run doublet detection (e.g., scDblFinder), and inspect marker gene expression for suspicious clusters.
  • Symptom: CellChat fails with database mismatch errors.
    Likely causes: Using a mouse Seurat object but setting human DB, or vice versa.
    Fixes: Use CellChatDB.human for human data and CellChatDB.mouse for mouse. Confirm gene symbols match the DB (e.g., human HGNC names vs mouse gene symbols).

Limitations, versioning, and responsible use

Key limitations and caveats to be explicit about:

  • mRNA ≠ protein or function: scRNA-seq measures transcripts; protein abundance, subcellular localization, secretion, cleavage, and inhibitors determine actual signaling. Treat LR inference as hypothesis generation.
  • Spatial information: Standard droplet scRNA-seq loses tissue spatial context. Use spatial transcriptomics or imaging-based validation to confirm proximity when proximity matters.
  • Database and version effects: Both LIANA and CellChat rely on curated LR and pathway databases. Different database versions (and organism choices) change which pairs/pathways are available and their annotations. Record database versions and package versions in your analysis metadata.
  • Methodological assumptions: Methods vary in how they score an interaction (expression thresholds, permutation strategies). Aggregated rankings can reduce method-specific biases but may also hide method-specific strengths.
  • Batch and compositional confounding: Unequal sampling or batch effects can produce apparent differences in signaling that are technical. Always check sample metadata and consider sample-aware analyses or aggregating by sample before comparing conditions.

Responsible-use notes:

  • Always treat inferred interactions as starting points for wet-lab validation (spatial transcriptomics, immunostaining, functional assays).
  • Document all software, database versions, and parameters so results are reproducible and comparable across analyses.
  • Be cautious about potential clinical interpretation; these are mechanistic hypotheses, not direct evidence for therapeutic targets.

Next-step checklist

  • Save a snapshot of your R session including package versions: sessionInfo() or the output of renv::snapshot().
  • Inspect liana_aggregate_results.csv for top-ranked LR pairs and export a prioritized candidate list for experimental follow-up.
  • Visualize CellChat networks (circle plots, heatmaps) and export figures for the most relevant pathways.
  • Plan validation experiments: select 3–5 high-confidence LR pairs with clear biological rationale; design spatial or protein-level validation.
  • Record database versions and provide them alongside result tables (e.g., LIANA DB, CellChatDB version). Save seeds for random steps to improve reproducibility.
