Statistics for Bioinformatics

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives and prerequisites

By the end of this lesson you will be able to:

  • Differentiate biological from technical replicates and state the experimental unit.
  • Explain effect size, uncertainty (confidence intervals), p-values, and the false discovery rate (FDR).
  • Choose and implement a simple two-group comparison without violating independence assumptions.
  • Describe when and how to correct for multiple testing and how to report limits of a result.
  • Write a brief, reproducible analysis plan that lists outcome, predictor, experimental unit, covariates, replicates, diagnostic plots, and interpretation limits.

Prerequisites:

  • Basic algebra and familiarity with a data-frame structure in R or Python.
  • Installed software: R (recommended >= 4.0), Python (recommended >= 3.8), and the libraries used below (installation commands included).

Why these statistics matter in bioinformatics

Bioinformatics analyses commonly measure many features (for example, thousands of genes or proteins) on a relatively small number of independent biological samples. This creates two important issues:

  • Multiple testing: evaluating thousands of hypotheses inflates the probability of false positives; controlling a family-wise or false discovery rate is essential.
  • Limited replicates: with few independent biological replicates, variability and effect size dominate inference—p-values alone are not sufficient evidence of biological importance.

Good analysis emphasizes: (1) a clear statement of what is being tested (null hypothesis), (2) whether the experimental units are independent, (3) appropriate diagnostics (plots and assumptions checks), (4) reporting effect sizes with uncertainty, and (5) transparent multiple-testing handling. The reproducible workflows below show how to run a simple two-group comparison, inspect outputs, and interpret results cautiously.

Reproducible sequential workflow

The example workflow compares a single gene (or any single numeric feature) between a control and treated group, demonstrating diagnostics, a two-sample test, effect-size calculation, and FDR correction placeholder for many features. Files and directories used in the example:

  • data/control.csv — one-column CSV of control measurements (one row per biological replicate).
  • data/treated.csv — one-column CSV of treated measurements.
  • results/ — directory to hold generated plots and text outputs.

Create the directories and example CSVs (no destructive commands):

# from a shell
mkdir -p data results

# Example CSVs: do not overwrite real data. These are small illustrative files.
printf "value\n8.9\n9.8\n10.4\n9.5\n" > data/control.csv
printf "value\n11.2\n10.7\n12.1\n11.4\n" > data/treated.csv

Python: diagnostics, t-test, Cohen's d, and FDR step

Required Python packages: numpy, pandas, scipy, matplotlib, statsmodels.

# Install (if needed)
python -m pip install --user numpy pandas scipy matplotlib statsmodels

# Script: scripts/compare_groups.py
# Usage: python scripts/compare_groups.py data/control.csv data/treated.csv results/

#!/usr/bin/env python3
# scripts/compare_groups.py
import sys
import numpy as np
import pandas as pd
from scipy import stats
from statsmodels.stats.multitest import multipletests
import matplotlib.pyplot as plt
from math import sqrt

control_path, treated_path, outdir = sys.argv[1], sys.argv[2], sys.argv[3]

# Read inputs
ctrl = pd.read_csv(control_path)['value'].dropna().to_numpy()
trt  = pd.read_csv(treated_path)['value'].dropna().to_numpy()

# Diagnostics: simple boxplot and histogram
plt.figure()
plt.boxplot([ctrl, trt], labels=['control', 'treated'])
plt.title('Boxplot: control vs treated')
plt.savefig(f'{outdir}/boxplot_control_treated.png', dpi=150)

plt.figure()
plt.hist(ctrl, alpha=0.6, label='control')
plt.hist(trt,  alpha=0.6, label='treated')
plt.legend()
plt.title('Histograms')
plt.savefig(f'{outdir}/histograms.png', dpi=150)

# Summary statistics
summary = {
    'n_control': len(ctrl),
    'n_treated': len(trt),
    'mean_control': float(np.mean(ctrl)),
    'mean_treated': float(np.mean(trt)),
    'sd_control': float(np.std(ctrl, ddof=1)),
    'sd_treated': float(np.std(trt, ddof=1))
}
pd.Series(summary).to_csv(f'{outdir}/summary_stats.csv')

# Welch's t-test (does not assume equal variances)
tt = stats.ttest_ind(trt, ctrl, equal_var=False)
with open(f'{outdir}/ttest_result.txt', 'w') as fh:
    fh.write(f'pvalue_welch\t{tt.pvalue}\n')
    fh.write(f'statistic\t{tt.statistic}\n')

# Cohen's d (pooled SD version)
pooled_sd = sqrt(((len(ctrl)-1)*np.var(ctrl, ddof=1) + (len(trt)-1)*np.var(trt, ddof=1)) / (len(ctrl) + len(trt) - 2))
cohens_d = (np.mean(trt) - np.mean(ctrl)) / pooled_sd if pooled_sd > 0 else float('nan')
with open(f'{outdir}/effect_size.txt', 'w') as fh:
    fh.write(f'cohens_d\t{cohens_d}\n')

# Placeholders for multiple testing: if you have p-values vector for many features, use multipletests
# Example:
# pvals = np.loadtxt('pvalues_all_features.txt')
# adj = multipletests(pvals, alpha=0.05, method='fdr_bh')[1]
# np.savetxt(f'{outdir}/pvalues_adj.txt', adj)

What the script produces (paths):

  • results/boxplot_control_treated.png and results/histograms.png — diagnostic plots.
  • results/summary_stats.csv — sample counts, means, and standard deviations.
  • results/ttest_result.txt — t-statistic and p-value from Welch's t-test.
  • results/effect_size.txt — Cohen's d value.

R: equivalent reproducible workflow

Required R packages: readr, ggplot2 (for plotting). The R commands mirror the Python workflow.

# Install packages in R if needed:
# install.packages(c("readr", "ggplot2"))

# Script: scripts/compare_groups.R
# Usage: Rscript scripts/compare_groups.R data/control.csv data/treated.csv results/
args <- commandArgs(trailingOnly = TRUE)
control_path <- args[1]
treated_path <- args[2]
outdir <- args[3]

library(readr)
library(ggplot2)

ctrl <- read_csv(control_path, show_col_types = FALSE)$value
trt <- read_csv(treated_path, show_col_types = FALSE)$value

# Diagnostics
df <- data.frame(value = c(ctrl, trt),
                 group = rep(c("control","treated"), c(length(ctrl), length(trt))))
p1 <- ggplot(df, aes(group, value)) + geom_boxplot() + ggtitle("Boxplot: control vs treated")
ggsave(file.path(outdir, "boxplot_control_treated.png"), p1, dpi = 150, width = 6, height = 4)

p2 <- ggplot(df, aes(value, fill = group)) + geom_histogram(alpha = 0.6, bins = 12, position = "identity") +
  ggtitle("Histograms")
ggsave(file.path(outdir, "histograms.png"), p2, dpi = 150, width = 6, height = 4)

# Summary
summary_stats <- tibble::tibble(
  n_control = length(ctrl),
  n_treated = length(trt),
  mean_control = mean(ctrl),
  mean_treated = mean(trt),
  sd_control = sd(ctrl),
  sd_treated = sd(trt)
)
write.csv(summary_stats, file = file.path(outdir, "summary_stats.csv"), row.names = FALSE)

# Test: Welch two-sample t-test
res <- t.test(trt, ctrl, var.equal = FALSE)
writeLines(c(paste0("statistic\t", res$statistic),
             paste0("pvalue\t", res$p.value)), con = file.path(outdir, "ttest_result.txt"))

# Cohen's d (pooled SD)
pooled_sd <- sqrt(((length(ctrl)-1)*var(ctrl) + (length(trt)-1)*var(trt)) / (length(ctrl) + length(trt) - 2))
cohens_d <- (mean(trt) - mean(ctrl)) / pooled_sd
writeLines(paste0("cohens_d\t", cohens_d), con = file.path(outdir, "effect_size.txt"))

Output inspection and interpretation

When you examine the produced outputs, follow these steps and questions:

  • Open diagnostic plots:
    • Boxplot: Are there extreme outliers in one group? Outliers may indicate technical problems (measurement error) or true biological extremes—inspect raw data and metadata.
    • Histogram: Are distributions extremely skewed? Strong skew can violate t-test assumptions and warrant transformation (log-scale) or a nonparametric test (see troubleshooting).
  • Summary statistics:
    • Check sample sizes (n_control, n_treated). Very small n (e.g., n<3 per group) severely limit confidence and power.
    • Compare means and standard deviations. Large variability relative to mean difference implies low power.
  • t-test output:
    • P-value: a small p-value indicates data are unlikely under the null hypothesis given model assumptions; it is not the probability that the null is true.
    • Test statistic and degrees of freedom describe the standardized difference given variance and sample size.
  • Effect size (Cohen's d):
    • Provides a scale-free measure of the difference: small (~0.2), medium (~0.5), large (~0.8) are conventional heuristics, but context matters.
    • Report effect size with its uncertainty when possible (e.g., bootstrap CI) rather than a single point estimate.

What a plausible result means and what it does NOT prove:

  • Significant p-value + substantial effect size: evidence that the groups differ for this feature under the assumptions used. It does not prove causality, nor generalize beyond the sampled population if sampling was biased.
  • Non-significant p-value: does not prove absence of effect. A non-significant result could reflect low power (small sample size, large variability), inappropriate test, or a genuinely small effect below biological relevance.
  • Many tests across features without correction: high risk of false positives. Use FDR control (Benjamini–Hochberg or other methods) when analyzing many features.

Troubleshooting: symptoms, likely causes, and fixes

Symptom: Very small p-value but tiny absolute difference (e.g., mean difference = 0.02).

  • Cause: Very large sample size can make trivial differences statistically significant.
  • Fix: Report and interpret effect size and confidence interval; judge biological relevance separately from statistical significance.

Symptom: Non-significant result, yet means look different in plots.

  • Cause: High variability, small sample size, or outliers inflating variance.
  • Fix: Check plots and raw data; consider removing technical outliers with documented criteria, transform data (e.g., log), or increase sample size for adequate power.

Symptom: Test warnings about normality or extreme skew.

  • Cause: Data do not meet t-test assumptions (approximate normality of residuals or homoscedasticity—equal variances).
  • Fix: Use nonparametric tests (e.g., Mann–Whitney U for independent two-group comparisons) or apply a transformation (e.g., log, Box–Cox) and re-run diagnostics. For count-like genomic data (RNA-seq), use models tailored to counts (e.g., edgeR, DESeq2 in R) rather than t-tests.

Symptom: Too many apparent positives when testing thousands of features.

  • Cause: Multiple testing inflates false positives.
  • Fix: Apply FDR-control methods (Benjamini–Hochberg) or more conservative family-wise error corrections if appropriate. Pre-filter features with low signal to reduce tests, but pre-specify filters to avoid bias.

Limitations, version and reference-data caveats, and responsible use

  • Assumptions: Classical t-tests assume that observations are independent and, for the pooled-variance t-test, that variances are similar. Violations require alternative methods or careful modelling.
  • Biological vs technical replicates: only biological replicates count toward inference about population variability. Technical replicates should be summarized (e.g., mean per biological sample) or modeled explicitly with mixed models if you want to partition variance.
  • Versioning: analysis software and library versions can change defaults (for example, how missing values are handled, or statistical test implementations). Record the R and Python package versions used in any report. Example: R >= 4.0, SciPy >= 1.7, statsmodels >= 0.13 are common minimums as of the time of this writing.
  • Reference data: when using annotated genome references or gene models, record the exact reference version (e.g., GRCh38.p13, Ensembl release X) and gene identifier mappings—these affect which features map to which tests.
  • Responsible reporting: always report effect sizes and uncertainty, exact sample counts, the test used (including its parameters), any data transformations, and the multiple-testing correction method and threshold. Do not reduce interpretation to "significant" vs "not significant" without context.

Next-step checklist

  1. Write a one-paragraph analysis plan: outcome, predictor, experimental unit, covariates, replicate definition, and primary diagnostic plot.
  2. Run the scripts above on your data files and review the diagnostic plots for outliers and distributional problems.
  3. If many features are tested, compute and report adjusted p-values (FDR). Keep raw p-values for transparency.
  4. Report: sample sizes, means, standard deviations, effect sizes (Cohen's d or fold-change), confidence intervals (where feasible), test name and parameters, and multiple-testing method.
  5. If results will inform experimental follow-up, plan a power analysis to determine necessary sample size for the smallest biologically meaningful effect size.
