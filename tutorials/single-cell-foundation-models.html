Evaluating scGPT & Geneformer Embeddings

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

← Previous tutorialAll tutorialsNext tutorial →
Scope and tested boundary. This lesson evaluates precomputed cell embedding exports; it does not load scGPT/Geneformer weights, run inference, generate embeddings, or infer regulatory networks. The scoring code below is executable offline, but no pretrained model output or biological accuracy claim is supplied. All teaching fixtures are explicitly synthetic.

scGPT and Geneformer have distinct input representations and checkpoint conventions. A matrix called “embedding” is not enough to establish which model produced it. This walkthrough makes the checkpoint-to-embedding step an auditable upstream handoff and then tests whether the exported vectors support a narrow, donor-held-out cell-label retrieval task.

Goals and assumptions

  • Validate CSV embeddings, dimensions, finite values, and exact cell-ID alignment before comparing labels.
  • Prevent donor overlap between reference and held-out test cells.
  • Run deterministic Euclidean k-nearest-neighbor transfer with disclosed tie handling and top-vote uncertainty; report accuracy, macro-F1, per-class scores, confusion matrix, and donor-level results.
What you will produce. A strict JSON report of nearest-reference predictions and descriptive metrics from supplied vectors, plus an audit trail for the cell-ID join and donor split. The Python evaluator uses only the standard library. It is a small software check, not a replacement for study-specific validation, Scanpy, scIB metrics, or biological review.

Model-specific embedding generation handoff (not executed here)

Use the official implementation and the exact checkpoint’s documented preprocessing to make real embeddings; export one stable cell identifier per row and the corresponding vector with provenance kept separately. Never relabel arbitrary values or synthetic test coordinates as model output.

  • scGPT: its official repository links a reference-mapping tutorial (embed query cells and map against reference embeddings) and an integration tutorial. The model zoo documents distinct checkpoint choices and paired vocabularies; species, gene identifiers, selected checkpoint and the tutorial’s data-preparation conventions must match. The repository describes loading checkpoints via its documented utilities; there is no generic model.encode(adata) API assumed here.
  • Geneformer: the official getting-started docs direct users to install the repository with Git LFS and point to examples for transcriptome tokenization and extracting/plotting cell embeddings. The official examples include tokenizing_scRNAseq_data.ipynb and extract_and_plot_cell_embeddings.ipynb. Follow the selected Geneformer version/checkpoint’s tokenizer, input schema, gene-ID mapping and species expectations; these are not interchangeable with scGPT preprocessing.

Check the actual official notebook and checkpoint/version you will use. Both projects evolve. This lesson intentionally does not claim to have tested either model inference path or provide heavyweight model-install commands. Save model/repository revision, checkpoint identifier/hash, tokenizer/vocabulary, organism, input assay/count conventions, preprocessing, cell-ID mapping, embedding layer/pooling, and export date alongside your vectors.

Input contract

Save two UTF-8 CSV files. The embedding table must have a header with cell_id and one or more embedding_* columns; every subsequent row has exactly one numeric value per dimension. Metadata must have exactly the fields cell_id,donor_id,label,split, with one row per cell. Split must be train (reference) or test. Every donor must occur in one split only. Row ordering may differ because join-by-ID is explicit.

cell_id,embedding_0,embedding_1
ref_001,0.13,-0.28
ref_002,0.07,0.31
test_101,0.22,-0.06
cell_id,donor_id,label,split
ref_001,donor_A,T-cell,train
ref_002,donor_B,B-cell,train
test_101,donor_C,T-cell,test
Split before tuning. These values illustrate the file format only; they are not data or model outputs. Put every cell from a donor in one split. Where the intended claim concerns transfer across sites, studies, or batches, hold out that unit too. Choose the checkpoint, preprocessing, distance metric, k, and thresholds using training/reference-only validation, never the held-out test labels.

Run the evaluator: first a software check, then real embeddings

Download the evaluator and test suite into the same new working folder. The commands below use a macOS/Linux-style shell; Python 3.12 on Linux was tested. The example needs only Python's standard library, not model weights or a GPU.

mkdir embedding-evaluation
cd embedding-evaluation
# Save both downloaded Python files in this folder.
python3 -m unittest -v test_foundation_embedding_workflow.py

A. Reproduce a small, deliberately synthetic software check

The four vectors below are hand-written coordinates, not scGPT or Geneformer outputs. They make the expected nearest-neighbor decisions obvious and let you test the file contract without a model account or download. Their class separation is constructed on purpose; no model-quality or biological result can be inferred from the score.

python3 - <<'PY'
from pathlib import Path
folder = Path("synthetic_demo")
folder.mkdir()
(folder / "embeddings.csv").write_text(
    "cell_id,embedding_0,embedding_1\n"
    "ref_T,0,0\nref_B,10,10\n"
    "query_T,0.1,0.2\nquery_B,9.8,10.1\n", encoding="utf-8")
(folder / "metadata.csv").write_text(
    "cell_id,donor_id,label,split\n"
    "ref_T,D_reference,T-cell,train\n"
    "ref_B,D_reference,B-cell,train\n"
    "query_T,D_heldout,T-cell,test\n"
    "query_B,D_heldout,B-cell,test\n", encoding="utf-8")
PY
python3 foundation_embedding_workflow.py \
  --embeddings synthetic_demo/embeddings.csv \
  --metadata synthetic_demo/metadata.csv \
  --output synthetic_demo/evaluation.json -k 1

Open synthetic_demo/evaluation.json. The software-check result should contain two test cells: query_T maps to the T-cell reference and query_B to the B-cell reference. Accuracy and macro-F1 are both 1.0 for these deliberately easy toy points only. inference_performed remains false.

Trigger a meaningful failure: copy the metadata file and change a query cell's donor to D_reference. Rerun using that copy and a new output filename. The evaluator must exit with a donor-leakage error and create no evaluation JSON. Reordering rows without changing IDs should not change predictions.

B. Evaluate actual model-exported embeddings

After the software check passes, follow the model-specific handoff above and export your actual vectors. Use the same checkpoint, embedding layer/pooling, dimension ordering, and preprocessing for reference and test cells. Save your real exports as real_embeddings.csv and real_metadata.csv; these are files you must supply, not generated model results included with this lesson.

python3 foundation_embedding_workflow.py \
  --embeddings real_embeddings.csv \
  --metadata real_metadata.csv \
  --output real_evaluation.json -k 3
Before the real-data run: k must be no larger than the number of reference cells (the example uses k=3). Choose k and preprocessing using reference-only validation before examining test labels. Holding donors out in this evaluation does not establish that a pretrained checkpoint never saw those donors or their study during pretraining; check checkpoint training provenance separately.

The tool checks unique headers, rectangular rows, cell-ID agreement, finite coordinates, exact metadata fields, donor separation, valid k, and a fresh output filename. It refuses inputs above 10 MiB per CSV or a comparison budget above 10 million reference-cell × test-cell × embedding-dimension terms. It does not silently subsample. Use an appropriately validated vectorized or nearest-neighbor implementation for larger cohorts, and document any resulting approximation.

Distance overflow produces a scale-review error, not a JSON containing infinity. Output is serialized as strict JSON before exclusive file creation; an existing result is never overwritten. Review the failure message rather than replacing invalid coordinates or leaking held-out labels into a repair.

Read outputs and failure cases

The JSON reports the configuration, split sizes and donors, cell predictions and nearest neighbors, squared Euclidean distances, tie labels, top-vote fraction, confusion matrix, accuracy, macro-F1, per-class precision/recall/F1, and per-test-donor accuracy. Distances depend on the supplied coordinate scale, embedding layer, and preprocessing; compare them only for consistently generated vectors. A tied vote resolves alphabetically and lists all tied labels. The top-vote fraction describes neighbor agreement, not a calibrated probability.

  • Cell-ID mismatch/duplicate: repair upstream barcode/sample prefixes and confirm one-to-one export alignment. Do not “fix” by relying on row order.
  • NaN/infinity or nonnumeric value: trace embedding extraction and CSV serialization; do not silently impute or replace values.
  • Donor leakage: reassign whole donors before exporting metadata. If the scientific target is within-donor generalization, design that validation separately and label it as such.
  • Poor class or donor performance: inspect support and confusion matrix; potential causes include representation failure, shifts in tissue/site/batch, label inconsistency, unrepresented cell state, and class imbalance. Do not tune against held-out test labels.
  • High score: not evidence of biological truth or zero-shot universal transfer. Check marker coherence, independent cohorts, baseline models, batch/site confounding, and annotation quality using a preregistered plan.

Limitations and official sources

This is supervised nearest-neighbor label transfer using labeled reference cells, not zero-shot prediction. Donor exclusion limits a common leakage route but cannot remove confounding when labels align with site, protocol, or disease cohort. A single donor-level split is not a population-level uncertainty estimate. Report cohort composition, per-class support, donor/site performance, baselines, preprocessing, chosen k, and independent replication. No test accuracy is asserted by this tutorial.

Embedding similarity is not a gene-regulatory network, causal edge, differential expression result, or mechanistic claim. Network inference requires separate methods and evidence; no GRN is produced here.
