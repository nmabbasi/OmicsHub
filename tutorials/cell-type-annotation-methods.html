Complete Cell Type Annotation: 6 Methods + CyteTypeR

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Example environment: R 4.3.2 (SingleR v2.4.0, scCATCH v3.2), Python 3.11

Learning objectives and prerequisites

After completing this lesson you will be able to:

  • Run six common automated cell-type annotation workflows on a clustered single-cell RNA-seq dataset and inspect their outputs.
  • Compare and interpret annotation agreement and disagreement between methods using confusion matrices and marker checks.
  • Use CyteTypeR, a modern multi-agent large language model (LLM) framework, as an additional evidence source and integrate its outputs with algorithmic predictions.
  • Understand common failure modes, diagnostic checks, and responsible-use caveats for automated annotation.

Prerequisites

  • A clustered single-cell object (Seurat v4 or SingleCellExperiment) produced from quality-controlled scRNA-seq data. Example filename used in commands below: data/pbmc_seurat.rds.
  • Normalized expression matrix available inside the object (log-normalized counts or SCTransform). Commands below assume standard Seurat assays are present.
  • R (>= 4.2) with the listed packages installed; Python only required for scmap (optional) if you prefer its Python port, but the R ecosystem has equivalents. Exact package install instructions are provided inline where needed.

Why automated cell-type annotation matters

After dimensionality reduction and clustering of single-cell RNA-seq (scRNA-seq) data, researchers need to assign biological cell-type labels to clusters or individual cells. The gold standard is manual annotation using canonical marker genes, but this process is time-consuming and subjective. Automated annotation tools speed up this step by applying algorithmic rules or by using reference atlases and marker databases. Different tools rely on different assumptions—reference mapping, marker enrichment, supervised classifiers, or generative models—so combining several orthogonal methods gives stronger evidence and highlights ambiguous clusters for manual review. This tutorial demonstrates six widely used algorithmic approaches and compares them to CyteTypeR, an LLM multi-agent system that synthesizes marker patterns and contextual knowledge to suggest annotations.

Files you should have before starting

  • data/pbmc_seurat.rds — clustered Seurat object (cells × genes) with Idents set to clusters.
  • results/ — an output directory you will write method outputs into (create if missing).
  • Optional reference files if you run methods that accept custom references (paths are shown in each section).

Reproducible workflow: six methods + CyteTypeR

Below are sequential, reproducible R commands. Each block states inputs and outputs explicitly. Install packages only if not already available; package installation can be slow — do this in a separate step and avoid re-installing on every run.

Preparatory R setup (load data and common utilities)

## Input:
##   data/pbmc_seurat.rds  (Seurat object with clusters in Idents)
## Output:
##   loaded object in variable 'pbmc'
library(Seurat)
library(dplyr)
library(Matrix)
# adjust the path to your file
pbmc <- readRDS("data/pbmc_seurat.rds")
# ensure a named output folder
dir.create("results", showWarnings = FALSE)

Method 1 — SingleR (reference-based, per-cell mapping)

SingleR maps each cell (or cluster centroid) to a reference transcriptome using correlation-based scoring. It is sensitive to the choice of reference.

## Inputs:
##  - pbmc (Seurat object)
##  - celldex references will be downloaded if not present
## Output:
##  - results/singleR_predictions.csv  (cell-level labels)
if (!requireNamespace("SingleR", quietly = TRUE)) {
  install.packages("BiocManager")
  BiocManager::install(c("SingleR","celldex"))
}
library(SingleR)
library(celldex)

# download a common reference (Human Primary Cell Atlas)
hpca <- HumanPrimaryCellAtlasData()

# run SingleR on normalized data (use pbmc@assays$RNA@data for lognormalized counts)
singleR_res <- SingleR(test = pbmc@assays$RNA@data,
                       ref = hpca,
                       labels = hpca$label.main)

# attach and save
pbmc$SingleR_label <- singleR_res$labels
write.csv(singleR_res$labels, "results/singleR_predictions.csv", row.names = TRUE)

Method 2 — scCATCH (marker-based cluster scoring)

scCATCH finds marker genes per cluster and matches them to a curated tissue-specific marker database. It reports cluster-level annotations and can abstain when evidence is weak.

## Inputs:
##  - pbmc (Seurat object)
## Output:
##  - results/scCATCH_celltype.csv  (cluster -> assigned celltype)
if (!requireNamespace("scCATCH", quietly = TRUE)) {
  # scCATCH is on CRAN/Bioconductor depending on version - adjust as needed
  install.packages("scCATCH")
}
library(scCATCH)

# find positive marker genes per cluster
# Note: FindAllMarkers requires Seurat v3/v4
pbmc_markers <- FindAllMarkers(pbmc, only.pos = TRUE, min.pct = 0.25, logfc.threshold = 0.25)

# build scCATCH object and run
obj <- createscCATCH(data = pbmc@assays$RNA@data, cluster = as.character(Idents(pbmc)))
obj <- findmarkergene(obj, species = "Human", marker = pbmc_markers, tissue = "Blood")
obj <- findcelltype(obj)

# results are in obj@celltype (cluster-level)
scCATCH_df <- obj@celltype
write.csv(scCATCH_df, "results/scCATCH_celltype.csv", row.names = FALSE)

Method 3 — Seurat label transfer (reference-based, anchors)

Seurat’s label transfer uses mutual nearest neighbors (anchors) to transfer labels from a labeled reference Seurat object to your query. Useful when you have a high-quality single-cell reference atlas.

## Inputs:
##  - pbmc (Seurat query object)
##  - reference Seurat object (if you have one) at path: data/ref_seurat.rds
## Output:
##  - results/seurat_transfer_predictions.csv (cell-level labels and scores)
if (!file.exists("data/ref_seurat.rds")) {
  message("Create or download a reference Seurat object at data/ref_seurat.rds to run label transfer.")
} else {
  ref <- readRDS("data/ref_seurat.rds")
  # standard workflow: find anchors and transfer
  anchors <- FindTransferAnchors(reference = ref, query = pbmc, dims = 1:30)
  transfer <- TransferData(anchorset = anchors, refdata = ref$celltype_label, dims = 1:30)
  pbmc$SeuratTransfer_label <- transfer$predicted.id
  write.csv(transfer, "results/seurat_transfer_predictions.csv", row.names = TRUE)
}

Method 4 — scmap (kNN mapping using indexed references)

scmap builds an index from a reference and predicts labels for query cells. It has both cluster- and cell-level modes. Below uses the R scmap package.

## Inputs:
##  - pbmc (query)
##  - reference SingleCellExperiment saved at data/ref_sce.rds (optional)
## Output:
##  - results/scmap_cell_predictions.csv
if (!requireNamespace("scmap", quietly = TRUE)) {
  BiocManager::install("scmap")
}
library(scmap)
library(SingleCellExperiment)

# convert Seurat to SingleCellExperiment if needed
sce_query <- as.SingleCellExperiment(pbmc)

# if you have a reference SingleCellExperiment file, load and index it:
if (file.exists("data/ref_sce.rds")) {
  ref_sce <- readRDS("data/ref_sce.rds")
  ref_sce <- selectFeatures(ref_sce)       # scmap feature selection
  ref_sce <- indexCluster(ref_sce, cluster_col = "celltype_label")
  scmap_res <- scmapCluster(projection = sce_query, index_list = list(ref = metadata(ref_sce)$scmap_cluster_index))
  write.csv(scmap_res$combined_labs, "results/scmap_cluster_predictions.csv", row.names = TRUE)
} else {
  message("No reference SingleCellExperiment found; scmap requires a labeled reference.")
}

Combine predictions and compute an agreement matrix

## Inputs:
##  - per-cell or per-cluster label files produced above (modify if you used different paths)
## Output:
##  - results/agreement_matrix.csv
# Example: compare SingleR (cell-level) and scCATCH (cluster-level)
singleR_labels <- read.csv("results/singleR_predictions.csv", row.names = 1, stringsAsFactors = FALSE)
scCATCH_labels <- read.csv("results/scCATCH_celltype.csv", stringsAsFactors = FALSE)

# map scCATCH cluster labels to cells (depends on cluster naming)
cluster_to_type <- setNames(scCATCH_labels$cell_type, scCATCH_labels$cluster)
cell_clusters <- as.character(Idents(pbmc))
scCATCH_cell_labels <- cluster_to_type[cell_clusters]

compare_df <- data.frame(cell = colnames(pbmc),
                         SingleR = singleR_labels$labels,
                         scCATCH = scCATCH_cell_labels,
                         stringsAsFactors = FALSE)

# confusion matrix (table)
agreement <- table(compare_df$SingleR, compare_df$scCATCH)
write.csv(as.matrix(agreement), "results/agreement_matrix.csv")

Output inspection and interpretation

For each method inspect both the assigned label and any confidence metric the method provides (e.g., SingleR's delta score, scCATCH's support, CellAssign posterior probabilities, CyteTypeR textual explanation and confidence). Key checks:

  • Per-cluster majority label: for cluster-level tools, check whether the majority of cells in a cluster share the same assigned label. Mixed labels inside a cluster indicate either heterogeneous clusters or poor clustering resolution.
  • Marker expression sanity check: for each assigned cell type, plot canonical markers (FeaturePlot / violin plots) to confirm expected expression patterns (e.g., CD3D for T cells, CD19/CD79A for B cells). Lack of marker expression weakens confidence.
  • Agreement matrix: high diagonal values indicate consensus between methods; off-diagonals point to disagreements that require manual review.
  • CyteTypeR outputs: treat LLM-suggested labels as hypotheses. Use the provided supporting markers and explanations to cross-check expression patterns and biological plausibility.

What agreement does and does not prove:

  • Agreement across orthogonal methods increases confidence but is not definitive proof — common biases (shared reference artifacts, shared marker databases) can produce consistent but incorrect labels.
  • Disagreement highlights clusters that need targeted manual inspection (marker plots, subclustering, pseudotime, or protein-level validation if available).
  • Absence of a predicted rare or novel cell type in all methods does not prove absence; many tools cannot detect states not represented in references or marker sets.

Troubleshooting: symptoms, likely causes, and fixes

  • Symptom: SingleR assigns many cells to "unknown" or an unexpected broad label.
    Likely cause: Reference mismatch (species, platform differences, missing cell types) or low-quality input normalization.
    Fix: Try a different reference (e.g., a single-cell reference like MonacoImmune or BlueprintEncode), run SingleR on cluster centroids (aggregate counts) rather than individual cells to reduce noise, or re-normalize using the same method as the reference.
  • Symptom: scCATCH returns many "Unknown" clusters.
    Likely cause: Marker list does not contain strongly distinguishing genes for those clusters or tissue argument mismatched.
    Fix: Provide improved marker discovery parameters (lower min.pct, different logFC threshold), double-check tissue argument, or supplement with custom marker files.
  • Symptom: Seurat transfer labels seem inconsistent for activated cells.
    Likely cause: Reference does not include activated states or technology/platform differences create systematic shifts.
    Fix: Use integration pipelines (SCTransform and reciprocal PCA), choose a more closely matched reference, or filter for highly conserved genes before anchoring.
  • Symptom: CyteTypeR returns plausible-sounding labels but supporting markers are weak or missing.
    Likely cause: LLM agent relied on noisy marker lists or used general textual knowledge not specific to the dataset.
    Fix: Provide the agent with higher-quality inputs (cluster-level DEG lists, per-cluster mean expression), or request the agent to prioritize markers present in your dataset and to report which markers were actually detected above background.

Limitations, version and reference-data caveats, and responsible use

  • Tool performance depends strongly on the reference atlas, marker database quality, and normalization. For example, SingleR results differ if you use microarray-based HPCA versus single-cell atlases.
  • Some tools force a label for every cell (no abstention) while others can refuse to assign a label; interpretation differs accordingly. Always check confidence metrics.
  • LLM tools like CyteTypeR synthesize evidence but can hallucinate if inputs are incomplete. Treat LLM outputs as evidence to be validated, not final truth.
  • Versioning matters. Package APIs and default behaviors change between releases. Re-run analyses with consistent package versions (record sessionInfo() or use containers) for reproducibility.
  • Automated annotation is not a clinical diagnostic. Do not make clinical claims from automated labels without orthogonal validation (protein markers, flow cytometry, or pathology).
