Advanced Visualization Packages (SCpubr, SCP, dittoSeq)

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04

Learning objectives & prerequisites

By the end of this lesson you will be able to:

  • Transform Seurat exploratory plots (DimPlot, FeaturePlot, DotPlot, violin) into publication-ready figures using SCpubr, scCustomize, dittoSeq, SCP and related helper packages.
  • Select colorblind-friendly palettes, tune legends/labels, and export high-resolution figures with reproducible code.
  • Produce composite visual panels (UMAP + violin + heatmap) while preserving consistent color scales across panels.

Prerequisites (assumed completed):

  • Completed a basic single-cell RNA-seq (scRNA-seq) workflow: alignment, count matrix, cell/gene QC, normalization, dimensional reduction and clustering (e.g., using Seurat).
  • A QC-reviewed Seurat object saved as an RDS file: data/seurat_obj.rds containing metadata columns cell_type, condition and assay data (normalized counts or SCT slots depending on pipeline).
  • R >= 4.2 (examples tested on R 4.3.x), and the packages used below installed. Installation instructions for each package are referenced in the References section.

Why advanced visualization matters (biological & computational context)

Exploratory plots in Seurat (DimPlot, FeaturePlot, DotPlot) are excellent for iterative analysis, but default styling is designed for quick inspection rather than publication. Well-crafted figures must communicate a specific biological message: which cell types change with condition, which genes mark a cluster, or how pathway activities distribute across cell states. Poor color choices, inconsistent legends, and cluttered axis labels can obscure biological signals or, worse, mislead the reader.

Wrapper packages (SCpubr, scCustomize, dittoSeq, SCP, scplotter, SeuratExtend, etc.) standardize aesthetic best practices and provide high-level convenience functions that keep code succinct while producing consistent, high-contrast, colorblind-friendly figures. They do not change the underlying data — they simply help you display it in ways that are easier to interpret and reproduce.

Reproducible, sequential workflow

The following workflow assumes a Seurat object located at data/seurat_obj.rds. Each code block describes inputs and expected outputs. Replace file paths and column names to match your dataset.

1) Setup: load libraries and the Seurat object

# Input files:
# - data/seurat_obj.rds  (Seurat object with metadata: 'cell_type', 'condition')
# Outputs:
# - An R session with the object loaded as 'seurat_obj'

library(Seurat)          # core single-cell object
library(SCpubr)         # publication-ready wrappers
library(scCustomize)     # extended aesthetics
library(dittoSeq)       # composition & heatmaps
library(scplotter)      # specialized plots (if installed)
library(SCP)            # SingleCellPlot-like wrappers
library(ggplot2)        # underlying plotting system

seurat_obj <- readRDS("data/seurat_obj.rds")
stopifnot(inherits(seurat_obj, "Seurat"))

Notes: If a package is not installed, install from CRAN or Bioconductor per package instructions. Some packages are on GitHub; prefer the release versions unless you need a development feature.

2) Standardized UMAP with SCpubr

# Purpose: create a publication-ready dimensional reduction plot grouped by cell type.
# Input: seurat_obj
# Output: PNG and PDF files saved to results/umap_celltype.png and results/umap_celltype.pdf

dir.create("results", showWarnings = FALSE)

p_umap <- SCpubr::do_DimPlot(
  sample = seurat_obj,
  reduction = "umap",         # verify that UMAP is present; change to 'tsne' if needed
  group.by = "cell_type",
  label = TRUE,               # add cluster labels
  repel = TRUE,               # avoid label overlap
  font.size = 12,
  legend.position = "right"   # or "bottom"
)

ggsave("results/umap_celltype.png", p_umap, width = 8, height = 6, dpi = 300)
ggsave("results/umap_celltype.pdf", p_umap, width = 8, height = 6)

What to check: ensure reduction = "umap" matches an existing reduction in seurat_obj@reductions. If labels overlap heavily in dense datasets, consider increasing repel or label font size.

3) Feature expression map with scCustomize / SCpubr

# Purpose: plot expression of a marker gene with a colorblind-friendly gradient.
# Input: seurat_obj; feature: "GeneA" must be present (check FeaturePlot support).
# Output: results/feature_GeneA.png

feature <- "GeneA"  # replace with a real gene symbol from your dataset

p_feat <- SCpubr::do_FeaturePlot(
  sample = seurat_obj,
  features = feature,
  reduction = "umap",
  colors.use = c("#ECECEC", "#D55E00"),   # light -> dark (colorblind-aware pair)
  pt.size = 0.5
)

ggsave(sprintf("results/feature_%s.png", feature), p_feat, width = 6, height = 5, dpi = 300)

Tip: When comparing multiple genes across panels, fix the color scale limits (e.g., min.cutoff, max.cutoff or scale your expression values) to ensure comparability.

4) Dot plot of top markers with scCustomize

# Purpose: summarize marker expression across annotated cell types.
# Input: a vector of gene names; seurat_obj metadata column 'cell_type'
# Output: results/dotplot_top_markers.pdf

top_markers <- c("GeneA", "GeneB", "GeneC", "GeneD", "GeneE")  # replace with validated markers

p_dot <- scCustomize::Clustered_DotPlot(
  object = seurat_obj,
  features = top_markers,
  group.by = "cell_type",
  scale = TRUE,
  dot.scale = 6
)

ggsave("results/dotplot_top_markers.pdf", p_dot, width = 9, height = 4)

Note: If genes in top_markers are missing, the function will typically error or drop them; confirm gene names using rownames(seurat_obj) or rownames(GetAssayData(seurat_obj, slot="data")).

5) Composition barplot with dittoSeq

# Purpose: show relative cell type composition across samples or patients.
# Input: seurat_obj with 'cell_type' and 'patient_id' metadata columns
# Output: results/composition_by_patient.png

p_comp <- dittoSeq::dittoBarPlot(
  seurat_obj,
  var = "cell_type",
  group.by = "patient_id",
  plot.theme = theme_bw(),
  legend.title = "Cell type"
)

ggsave("results/composition_by_patient.png", p_comp, width = 9, height = 4, dpi = 300)

When preparing figure panels, ensure sample ordering is intentional (ascending/descending or experimental order) — modify factor levels of patient_id in metadata if needed.

6) Heatmap of marker genes with dittoSeq

# Purpose: multi-annotation heatmap with consistent scaling across genes.
# Input: seurat_obj and vector top_markers
# Output: results/heatmap_top_markers.pdf

p_heat <- dittoSeq::dittoHeatmap(
  seurat_obj,
  genes = top_markers,
  annot.by = c("cell_type", "condition"),
  scale = "row"
)

ggsave("results/heatmap_top_markers.pdf", p_heat, width = 8, height = 6)

Row-scaling (z-score per gene) highlights relative expression patterns but removes absolute expression differences. State this explicitly in figure captions.

7) Composite figure assembly

# Purpose: assemble UMAP + violin + heatmap into a single multi-panel figure
# Input: p_umap, p_dot, p_heat (from prior steps)
# Output: results/panel_figure.pdf

library(patchwork)  # for combining ggplots

combined <- (p_umap + p_feat) / (p_dot + p_heat) + plot_layout(guides = "collect")
ggsave("results/panel_figure.pdf", combined, width = 12, height = 10)

Patchwork collects shared legends by default when guides = "collect". Confirm legend titles and sizes to avoid overlaps.

Output inspection and interpretation

When you open the generated images, inspect the following:

  • UMAP: Are clusters coherent and consistent with annotated cell_type? Look for outlier cells, doublet-like intermediate states, or batch effects (clusters dominated by one patient).
  • Feature plots: Does the expression pattern match expectation (e.g., marker expression enriched in specific clusters)? High expression in many clusters may indicate a housekeeping or ambient RNA gene.
  • Dot plots: Dot size indicates percent of cells expressing the gene; color indicates average expression. Distinguish between broad low-level expression (large dots, pale color) and restricted high-level expression (small cluster, intense color).
  • Heatmap: Confirm whether row-scaling was applied; heatmaps can emphasize relative differences but hide absolute expression scale.

What a plausible result may indicate:

  • Concordant marker expression in a cluster supports the assigned cell identity, but does not prove function or lineage — follow up with independent validation (e.g., protein-level assay).
  • Consistent shifts in composition across conditions suggest biological effect, but require statistical testing and consideration of sampling or cell capture biases.

What the figures do NOT prove:

  • They do not establish causality or mechanism. Visualization is descriptive and hypothesis-generating unless paired with proper downstream statistical and experimental validation.
  • Plots do not correct for upstream biases (batch effects, doublets, ambient RNA) — these must be addressed in preprocessing.

Troubleshooting

Here are common symptoms, likely causes, and suggested fixes.

Symptom: Plot fails with “reduction not found” or UMAP missing

  • Cause: The Seurat object lacks the requested reduction name (e.g., "umap").
  • Fix: Check available reductions with names(seurat_obj@reductions). If missing, compute UMAP:
# Compute UMAP if necessary (warn: non-destructive but can change object)
seurat_obj <- RunUMAP(seurat_obj, dims = 1:30)
saveRDS(seurat_obj, file = "data/seurat_obj_with_umap.rds")

Symptom: FeaturePlot colors inconsistent across genes

  • Cause: Per-plot autoscaling of expression ranges.
  • Fix: Set common cutoffs using min.cutoff / max.cutoff or normalize expression to a shared scale before plotting.

Symptom: Overlapping labels in DimPlot

  • Cause: Dense embedding or many small clusters.
  • Fix: Increase repel = TRUE, reduce font.size, or disable labels and annotate manually using cluster centroids or inset tables.

Symptom: Missing genes in DotPlot or Heatmap

  • Cause: Gene naming inconsistencies (e.g., case differences, gene symbols vs Ensembl IDs).
  • Fix: Map gene identifiers to the same ID space used in your Seurat object. Use row.names(GetAssayData(seurat_obj)) to inspect and then translate using org-specific biomaRt or annotation packages.

Limitations, version & reference-data caveats, and responsible use

  • Package versions matter: plotting functions and defaults can change between versions. Save the package versions used with sessionInfo() inside a results/session_info.txt file to aid reproducibility.
  • Visualization does not substitute for statistical testing. For differential abundance or expression claims, use appropriate models (e.g., MAST, edgeR, DESeq2 adapted to single-cell, or compositional methods) and report statistical parameters.
  • Color choices: Even colorblind-friendly palettes can fail for readers with other visual impairments. Provide clear legends, shape encodings, and high contrast. Include figure captions that explicitly describe color meaning and scaling (e.g., "row-scaled z-scores").
  • Data provenance: For multi-sample comparisons, ensure the object accounts for batch correction where needed. Visual patterns dominated by a single batch may reflect technical artifact rather than biology.
  • Spatial/multi-omic visualizations: SCP and other spatial wrappers assume appropriate coordinate metadata. Verify coordinate systems and resolution before plotting spatial overlays.

Responsible-use notes:

  • Do not over-interpret low-expressed genes or small clusters (n < 10 cells) — report cell counts alongside any claim about rare populations.
  • When publishing, provide the exact code and data (or a minimal reproducible example) so peers can reproduce the figure-generation steps.

Next-step checklist

  • Confirm Seurat object has required metadata and reductions; save a snapshot: saveRDS(seurat_obj, "data/seurat_obj_for_figures.rds").
  • Run the provided scripts and save high-resolution outputs in results/.
  • Record sessionInfo() to document package versions.
  • Create figure captions that state: data source, normalization/scale (e.g., log-normalized, row-scaled), color scales used, and any filtering applied.
  • Perform the appropriate statistical tests for claims suggested by the visuals (differential expression, composition tests, etc.).

References

  • dittoSeq (Bioconductor) — composition plots and heatmaps tuned for single-cell data.
  • scCustomize (CRAN) — extended ggplot2-based customizations for Seurat plots.
  • SCP (SingleCellPlot) on Bioconductor — multi-omic and spatial visualization helpers.
