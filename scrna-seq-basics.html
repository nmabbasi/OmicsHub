scRNA-seq Basics

NM

Nasir Mahmood Abbasi, PhD

Bioinformatics Educator

Tested on: Python 3.11, R 4.3.2, Ubuntu 24.04
Last Review: 2026-08-15

Learning Objectives & Prerequisites

  • Prerequisites: Complete Linux, biological data formats, and basic statistics; install current Scanpy or Seurat in an isolated environment.
  • Objective: Load a 10x count matrix, inspect QC distributions, normalize, identify variable features, run PCA/UMAP, and cluster cells without treating fixed thresholds as universal.
  • Expected Output: A reproducible AnnData or Seurat object with documented per-sample QC decisions, neighborhood graph, UMAP, and cluster labels.

Suggested route: use the Bioinformatics Learning Path to review any prerequisite stage before continuing.

From Raw Counts to Biological Insights

Once the sequencing facility provides raw FASTQ files, the initial preprocessing step (using alignment tools like Cell Ranger, STARsolo, or pseudo-aligners like Alevin) maps the reads to a reference genome. This computationally intensive step generates a sparse count matrix, which serves as the foundational data structure for all downstream single-cell analysis. In this matrix, rows typically represent individual genes (features) and columns represent individual droplets (cells). Understanding how to manipulate this matrix is the core skill of any computational biologist working with single-cell transcriptomics.

In this comprehensive tutorial, we will walk through a standard end-to-end analysis on a 10x Genomics dataset. Because the bioinformatics community is split between two incredibly powerful ecosystems, we provide parallel, step-by-step workflows in both Python (using the Scanpy framework) and R (using the Seurat package). By seeing both side-by-side, you can choose the language that best fits your laboratory's needs while understanding the conceptual similarities between them.

1. Loading the Data

We begin by loading the sparse matrix into our core data structures: AnnData in Python, or a Seurat object in R.

import scanpy as sc
import pandas as pd
import numpy as np

sc.settings.verbosity = 3
sc.logging.print_header()

# Load 10x data
adata = sc.read_10x_mtx(
    'data/filtered_feature_bc_matrix/',
    var_names='gene_symbols',
    cache=True
)

adata.var_names_make_unique()

library(Seurat)
library(dplyr)
library(patchwork)

# Load 10x data
data_dir <- "data/filtered_feature_bc_matrix/"
pbmc.data <- Read10X(data.dir = data_dir)

# Initialize the Seurat object
pbmc <- CreateSeuratObject(counts = pbmc.data, project = "pbmc3k", min.cells = 3, min.features = 200)

2. Quality Control (QC)

Before any meaningful biological interpretation can occur, we must rigorously clean our dataset. Empty droplets (droplets containing ambient RNA but no actual cell) or dying, ruptured cells can severely confound downstream clustering and differential expression analysis. When a cell ruptures during the isolation process, its cytoplasmic RNA leaks out, leaving behind a disproportionate amount of mitochondrial RNA. Therefore, high mitochondrial expression, combined with unusually low total gene counts, is a classic hallmark of low-quality or dead cells.

However, it is critical to understand that Quality Control is not a one-size-fits-all process. The distribution of gene counts and mitochondrial percentages must be visualized and inspected for each individual dataset, tissue type, and sequencing batch. For instance, heart muscle cells naturally have higher mitochondrial content than blood cells. The thresholds provided in the code below are training starting points, not universal biological laws. You should always document and justify your filtering decisions in your research methodology.

# Identify mitochondrial genes
adata.var['mt'] = adata.var_names.str.startswith('MT-')

# Calculate QC metrics
sc.pp.calculate_qc_metrics(adata, qc_vars=['mt'], percent_top=None, log1p=False, inplace=True)

# Filter cells
adata = adata[adata.obs.n_genes_by_counts < 2500, :]
adata = adata[adata.obs.pct_counts_mt < 5, :]

print(f"Cells remaining after QC: {adata.n_obs}")

# Calculate mitochondrial percentage
pbmc[["percent.mt"]] <- PercentageFeatureSet(pbmc, pattern = "^MT-")

# Filter cells
pbmc <- subset(pbmc, subset = nFeature_RNA > 200 & nFeature_RNA < 2500 & percent.mt < 5)

print(paste("Cells remaining after QC:", ncol(pbmc)))

3. Normalization, Scaling, and PCA

Due to technical variations in the droplet microfluidics process, different droplets capture vastly different total amounts of RNA, even if the cells are identical in size and type. To ensure that our downstream clustering groups cells by true biological differences rather than mere sequencing depth artifacts, we must normalize the data. A standard approach is global-scaling normalization, where we scale the feature expression measurements for each cell by the total expression, multiply this by a scale factor (usually 10,000 counts per cell), and log-transform the result.

Following normalization, we identify features (genes) that exhibit high cell-to-cell variation in the dataset. Focusing on these highly variable genes (HVGs) highlights the biological signal and significantly reduces the computational burden. We then scale these genes so that highly expressed genes do not dominate the analysis, and apply Principal Component Analysis (PCA) to reduce the dimensionality of the dataset from thousands of genes down to a few dozen principal components.

# Normalize and log transform
sc.pp.normalize_total(adata, target_sum=1e4)
sc.pp.log1p(adata)

# Find highly variable genes
sc.pp.highly_variable_genes(adata, min_mean=0.0125, max_mean=3, min_disp=0.5)

# Save the raw data before scaling
adata.raw = adata

# Scale data and run PCA
sc.pp.scale(adata, max_value=10)
sc.tl.pca(adata, svd_solver='arpack')
sc.pl.pca_variance_ratio(adata, log=True)

# Normalize
pbmc <- NormalizeData(pbmc, normalization.method = "LogNormalize", scale.factor = 10000)

# Find highly variable genes
pbmc <- FindVariableFeatures(pbmc, selection.method = "vst", nfeatures = 2000)

# Scale data
all.genes <- rownames(pbmc)
pbmc <- ScaleData(pbmc, features = all.genes)

# Run PCA
pbmc <- RunPCA(pbmc, features = VariableFeatures(object = pbmc))
ElbowPlot(pbmc)

4. Neighborhood Graph and Clustering

With our data now compressed into principal components, the next step is to group similar cells together. We first construct a K-nearest neighbors (KNN) graph based on the Euclidean distance in PCA space. This graph maps out the local neighborhood of every single cell, connecting it to the cells with the most similar transcriptional profiles. To visualize this complex multi-dimensional network on a flat screen, we embed the graph into 2D space using non-linear dimensionality reduction techniques like UMAP (Uniform Manifold Approximation and Projection) or t-SNE.

Finally, to formally define our cell populations, we apply a graph-based clustering algorithm (such as Louvain or Leiden) to the KNN graph. These algorithms iteratively group cells together based on their interconnectivity, resulting in transcriptionally distinct subpopulations that often correspond to true biological cell types or states.

# Compute neighbors and UMAP
sc.pp.neighbors(adata, n_neighbors=10, n_pcs=40)
sc.tl.umap(adata)

# Cluster using the Leiden algorithm
sc.tl.leiden(adata, resolution=0.5)

# Visualize
sc.pl.umap(adata, color=['leiden'])

# Compute neighbors
pbmc <- FindNeighbors(pbmc, dims = 1:10)

# Cluster using Louvain/Leiden
pbmc <- FindClusters(pbmc, resolution = 0.5)

# Run UMAP
pbmc <- RunUMAP(pbmc, dims = 1:10)

# Visualize
DimPlot(pbmc, reduction = "umap", label = TRUE)

Conclusion and Next Steps

Both the Python (Scanpy) and R (Seurat) ecosystems support incredibly robust, production-ready scRNA-seq workflows. While they achieve similar end goals, they differ significantly in their underlying data structures, default algorithmic parameters, and community plugin ecosystems. Your choice between them should be deliberate, often dictated by your lab's existing codebase or specific downstream tools you wish to use. Regardless of the language you choose, the most important aspect of computational biology is reproducibility: always document your software versions, random seeds, and exact parameter choices.

With our cells now cleaned, normalized, reduced, and clustered into distinct subpopulations, our foundational processing is complete. We are now perfectly positioned to tackle advanced downstream analyses, such as assigning biological identities to these clusters via marker genes, inferring developmental trajectories, or mapping cell-cell communication networks.

Methodology and Reproducibility Considerations

In computational biology and bioinformatics, executing the code is only one part of the scientific process. Ensuring that your analysis is statistically sound, biologically meaningful, and strictly reproducible is paramount. When adapting this workflow for your own datasets, it is crucial to carefully evaluate the underlying assumptions of each algorithmic step. For instance, default parameters in tools like Seurat, Scanpy, or standard aligners are often optimized for specific tissue types (e.g., PBMCs) or sequencing technologies. Applying these defaults blindly to different biological contexts—such as highly heterogeneous solid tumors or non-model organisms—can lead to severe artifacts, false-positive discoveries, or the loss of rare cell populations.

Furthermore, we strongly recommend implementing strict environment management. The rapid evolution of bioinformatics software means that updating a single dependency (like NumPy, Pandas, or a Bioconductor package) can subtly alter downstream results. Always utilize package managers such as Conda or Mamba to isolate your project environments, and explicitly export your environment configurations (e.g., using conda env export > environment.yml). This practice not only safeguards your own longitudinal research but also ensures that peer reviewers and collaborative scientists can exactly replicate your computational findings years after publication.

Finally, always maintain a rigorous quality control (QC) mindset. Computational pipelines will almost always run to completion and produce a result, even if the input data is heavily contaminated or mathematically flawed. It is the responsibility of the bioinformatician to integrate negative controls, perform batch-effect evaluations, and visually inspect intermediate data distributions before proceeding to downstream biological interpretation.
